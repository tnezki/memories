# Multi-Step / Dependent-Chain Patterns

Multi-step requires dependency: an intermediate result is needed to answer the final task.

## Common chain patterns
- `solve_intermediate_then_transfer`
- `infer_rate_then_predict`
- `derive_relationship_then_apply`
- `representation_read_then_calculate`
- `calculate_then_interpret`
- `compare_then_select_model_then_apply`
- `find_component_then_resultant`
- `find_force_then_motion_prediction`

## One-final-answer preference
If the intermediate result exists only to reach one final requested quantity, normally write one natural problem rather than artificial `(a)` and `(b)` labels.

## Variation rules
For parallels, vary some combination of:
- direction of the relationship / unknown quantity
- dependency path
- order of givens
- values
- names/context
- compatible units

Do not vary only names/nouns and call it a new family.
