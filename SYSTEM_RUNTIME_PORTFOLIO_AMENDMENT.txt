ROSTER / SUPPORT
----------------
The stored student_registry.csv is reused on ordinary runs. A new roster is required only for first run/reset or explicit roster_update_requested=true. Durable Student Num reconnects history. Departed students become inactive rather than deleted.




Student-support documents are private setup/support sources, never evidence. Preserve raw sources under Student Support/Source Files. Normalize accommodations/modifications into student_support_current.csv. Keep actionable accommodations/modifications in the Unit Student Support files. Keep student-to-support-staff routing in the separate global `00 Contact Directory/student_support_contacts_current.csv`. That routing table may include case managers, special education teachers, study-skills teachers, academic support teachers, resource-room teachers, or future support roles/classes. Do not infer an email address from a name.




Support-only runs do not change evidence or grades. Report refresh after support maintenance is allowed only when explicitly requested.




REPORT / GRADE OUTPUT
---------------------
Official grading export is one current CSV per Mastery Goal per period; no overall Unit-grade CSV. Not assessed means the Mastery Goal has not been checked yet and therefore has blank PowerSchool Score. Needs first check means the individual I Can has not been checked yet.




The locked teacher report uses exactly:
- Whole Class
- Priority Day Groups
- Pull In Students




Priority Day has at most 2 groups and at most 15 students per group. Rank eligible students by current I-grade count, then Practice + check soon gap count, then evidence severity. Summarize the best common 20-minute Crewtime intervention for each selected group. Pull In is one landscape page of students with 1-2 Practice + check soon gaps.

Recurring Portfolio HTML must be instantiated from the exact registered `student_packet_template.html`, `teacher_summary_template.html`, and `portfolio.css` at the pinned SYSTEM commit. Run `Tools/templates/portfolio/verify_portfolio_output.py` before PASS. Any mismatch is `PORTFOLIO_TEMPLATE_DRIFT` and blocks PASS.

RESULTS ZIP / CROSS-DEVICE ARCHIVE - HARD
------------------------------------------
A report-producing run builds one results ZIP with:
  results_manifest.json
  student_reports/class_student_packet.html
  student_reports/individual/<stable-student-key>.html
  teacher_report/teacher_summary.html
  powerschool/<period>_MGxx.csv




Do not generate PDFs during the normal Portfolio run. Individual student HTML must be self-contained enough for reliable offline printing and email-prep PDF conversion.




After QA, persist the exact ZIP bytes twice under 02 Portfolio Data / Results Archives:
1. an immutable dated filename;
2. Latest Portfolio Results.zip, replacing the prior current copy.


Verify readback/hash. If either archive copy or required 01/02 state write cannot be persisted and verified, final status is `INCOMPLETE` / `PORTFOLIO_DRIVE_PERSISTENCE_FAILED`; do not claim Completed/PASS. A local ZIP may be returned only as an explicitly unpersisted recovery artifact. When PASS is allowed, return the exact same persisted ZIP to the teacher in chat. This private archive solves cross-device availability without placing student data in GitHub.




EMAIL BOUNDARY
--------------
Normal Portfolio runs do not generate Email Delivery PDFs and do not refresh email_delivery_manifest.csv. Email preparation is a separate explicit action in the email tool. That tool may read Latest Portfolio Results.zip, create verified email-ready PDFs in 03 Student Packets/Email Delivery, and refresh email_delivery_manifest.csv.




The email tool may also send the student's report to active support staff linked by student_id in `00 Contact Directory/student_support_contacts_current.csv`. Do not share an entire report folder as a substitute for student-specific delivery.

Before any email attachment is prepared, verify student_key + student_name + visible report identity agree. Legacy delivery manifests without explicit identity verification must fail closed. The email preflight may mark a student inactive only by explicit teacher action; this preserves historical evidence and send history.
