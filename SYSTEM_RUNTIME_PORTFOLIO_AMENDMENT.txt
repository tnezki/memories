SYSTEM RUNTIME AMENDMENT - PORTFOLIO DELIVERY / DRIVE ROUTING
============================================================
STATUS: CURRENT
SCOPE: Portfolio workflow only.
REVISION: 2026-09-22 - ROSTER + STUDENT SUPPORT STATE / MG GRADE EXPORTS

Portfolio is a private state-and-report workflow, not a repository artifact build. Student evidence, rosters, IEP/504/support files, Portfolio state, PDFs, CSVs, contacts, and names must never be written to GitHub.

CANONICAL PORTFOLIO DRIVE ROOT - HARD
-------------------------------------
Use exactly:
  title: ____Portfolio_Data
  folder_id: 1xFGmkwiHXxJIwsJEx36nSy4C6OLr3Y3o

Resolve the exact <Course>/unit N below that root. Preserve/create exactly these Portfolio-owned Unit folders:
  01 Evidence Inbox/
  02 Portfolio Data/
  03 Student Packets/
  04 Class & Intervention Summaries/
  05 PowerSchool Exports/

Preserve course-authorized siblings such as 06 Checkpoints.

02 Portfolio Data may contain the private nested support area:
  Student Support/Source Files/
  Student Support/student_support_current.csv
  Student Support/student_support_review.csv
  Student Support/student_support_import_history.csv

Roster and support state are private. Never expose them in public repository files or URLs.

ROSTER PERSISTENCE
------------------
The stored student_registry.csv is reused on ordinary Portfolio runs. A new roster CSV is required only on first run/reset or when the request explicitly sets roster_update_requested=true.

When roster update is requested, compare old/new by durable Student Num when present. Add new active students; mark departed students inactive; preserve all historical evidence. Do not infer deletions from missing submissions.

STUDENT SUPPORT PERSISTENCE
---------------------------
Explicit student-support documents are setup/support sources, not evidence. Preserve raw source bytes only under 02 Portfolio Data/Student Support/Source Files and normalize only actionable classroom/assessment supports. Do not normalize unrelated diagnosis, medical, family, or narrative details.

Support-only operations are permitted without new evidence and must not change evidence status or grades.

DRIVE PERSISTENCE IS A COMPLETION GATE
-------------------------------------
A normal evidence run is not complete until the canonical Drive state has been written and verified.

Required normal evidence-run persistence:
1. raw student evidence -> 01 Evidence Inbox;
2. longitudinal/current data -> 02 Portfolio Data;
3. current class Student Packet PDFs -> 03 Student Packets;
4. one current exact two-page individual report per active student -> 03 Student Packets/Email Delivery;
5. current teacher intervention summary -> 04 Class & Intervention Summaries;
6. current PowerSchool MG CSVs -> 05 PowerSchool Exports.

POWERSCHOOL OUTPUT
------------------
The official grading export is now one CSV per Mastery Goal per period. No overall Unit-grade CSV is produced. A completely unassessed Mastery Goal has blank Score cells, not an invented I.

CURRENT REPORTING
-----------------
The student report has no large Unit-grade box. It may state the number of Unit Mastery Goals demonstrated and shows each MG's current grade or Not assessed.

The teacher report is intervention-first and uses exactly these main lanes:
- Whole Class
- Priority Day Group
- Pull In Students

Priority Day Groups are exact shared 2-4-I-Can substantial-gap bundles. Pull In Students is student-centered for 1-2 small gaps.

DELIVERY
--------
Normal returned artifacts remain individual class Student Packet PDFs, one Teacher Summary PDF, and current MG PowerSchool CSVs. Do not wrap student Portfolio outputs in a github_transfer package.

A github_transfer ZIP is appropriate only for a separate repository-code/template/policy change such as this runtime amendment itself, and such a transfer must contain no student-specific Portfolio data.

All other SYSTEM_RUNTIME_CONTRACT rules remain in force.
