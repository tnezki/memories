CURRICULUM CONTROL PANEL ARCHITECTURE CONTRACT
==============================================
STATUS: CURRENT
REVISION: 2026-09-26 v1.2

PURPOSE
Keep the canonical Curriculum Control Panel small and stable while separating shared curriculum/resources from owner-only operational tools.

CORE MODEL - HARD
The canonical Curriculum Control Panel is the BUILD FACTORY.
The course Teacher Dashboard is the SHARED TEACHER RESOURCE SURFACE.
The local owner-tools root is the OWNER OPERATING SURFACE.

For Algebra 1 the owner-tools root is:
  _algebra_teacher_tools/
It is a sibling of algebra/, memories/, _portfolio_data/, and _github_transfers/ under the local GitHub root. It is intentionally NOT a Git repository.

The canonical control panel exposes two top-level modes:
1. Build
2. General
Do not expose a generic Maintenance tab.

BUILD MODE
Initial course/unit establishment is owned by pms_build/MANIFEST.json. Current shared Build menu:
1. Build Assessment Plan
2. Build Framework
3. Build Bank
4. Build Notes
5. Build Practice
6. Build Activities
7. Build Quick Checks
8. Build Warm-Ups
9. Build Review
10. Build Summative
11. Build Unit Plan

Do not reintroduce retired/operational jobs such as First 4 Days, Progress Tracker, Practice to Summative, Discourse, Portfolio evidence processing, or generic combined special-resource jobs merely because old PM files exist.

GENERAL MODE
Purpose-specific general PMs are owned by pms_general/MANIFEST.json.

SHARED TEACHER DASHBOARD - HARD
The shared Algebra Teacher Dashboard may expose finished curriculum/resources that another Algebra teacher can use: Notes, Practice, Activities, Investigations, Warm-Ups, Reviews, approved Quick Check HTML/PDF, assessment plans, Banks/teacher views, Summatives, and approved shared teacher resources.

It MUST NOT expose owner-only operational controls for:
- Portfolio evidence processing;
- Portfolio email/report delivery;
- personalized Checkpoint Builder;
- Quick Check Builder/selector.

Hiding a public link is not the long-term security boundary. Owner-only builder/control pages belong under _algebra_teacher_tools and should not remain as active public repository control pages after migration. Finished artifacts created by those tools may remain shared/public when their artifact policy permits it.

ALGEBRA OWNER TOOLS - HARD
Current owner-only entry points:
- _algebra_teacher_tools/index.html
- _algebra_teacher_tools/tools/checkpoint/checkpoint_builder.html
- _algebra_teacher_tools/tools/quick_check/quick_N.html
- Portfolio/email links surfaced only from the local owner index.

The local index should also link back to the shared Algebra Teacher Dashboard. The owner-tools folder stores controls/software only, not student evidence state. Student/private state remains in its authorized private location.

The owner-tools folder may be copied between school/home Macs alongside _portfolio_data. Relative links should assume the stable sibling layout under /Users/troynezki/Documents/GitHub rather than hard-coding one machine-specific absolute path.

DASHBOARD MAINTENANCE MODEL
Shared artifact outputs remain course/unit/section organized. Owner-only creation/management controls live locally. A shared teacher should be able to open a produced Quick Check without receiving access to the Quick Check selector that creates/replaces it.

ALGEBRA RECURRENCE / SET BUILDER REQUIREMENT - FUTURE DASHBOARD REORG
When the Algebra Teacher Dashboard is further reorganized, it MUST surface the current mastery recurrence map:
  frameworks/2_Framework_Algebra_1/Algebra1_Spiral_Framework/curriculum/mastery_recurrence_map.html
and provide a clear route to the section Set Builder/control surface from the local owner tools, while shared finished Sets remain available from the shared dashboard.

The Set Builder should open with recommended Target Plan A and Target Plan B from the recurrence map/current course profile. The teacher edits the recommendation rather than building the I Can mix from scratch. Editable controls should include selected I Cans, question counts, optional family preference, and a small fine-tuning note.

QUICK CHECK OWNER-TOOL RULE
Algebra Build Quick Checks remains in initial Build because it creates/repairs the owner-local Unit selector. Routine section Quick Checks are built from that local selector. Approved HTML/PDF/source-map output stays in the Algebra repository under the approved Quick Check folder and may be linked from the shared Teacher Dashboard.

PORTFOLIO / PRIVATE EVIDENCE
Portfolio/evidence processing is an owner-only private-data workflow, not an initial curriculum build job and not a shared-dashboard control.

TRANSFER / REVIEW
Repository-targeting jobs return through the current local GitHub Transfer contract. Declared owner-local tool files under _algebra_teacher_tools may use the same transfer helper because destinations remain inside /Users/troynezki/Documents/GitHub; they are installed locally without Git operations and are never committed merely because they live beside repositories.

END - CURRICULUM CONTROL PANEL ARCHITECTURE CONTRACT
