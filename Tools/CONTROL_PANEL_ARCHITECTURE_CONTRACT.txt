CURRICULUM CONTROL PANEL ARCHITECTURE CONTRACT
==============================================
STATUS: CURRENT
REVISION: 2026-09-26 v1.3

PURPOSE
Keep the canonical Curriculum Control Panel small and stable while separating shared curriculum/resources from owner-only operational tools.

CORE MODEL - HARD
The canonical Curriculum Control Panel is the BUILD FACTORY.
The course Teacher Dashboard is the SHARED TEACHER RESOURCE SURFACE.
The local owner-tools root is the OWNER OPERATING SURFACE.

For Algebra 1 the owner-tools root is:
  _algebra_teacher_tools/
It is a sibling of algebra/, memories/, _portfolio_data/, and _github_transfers/ under the local GitHub root. It is intentionally NOT a Git repository.

The normal Algebra owner entry point is:
  _algebra_teacher_tools/index.html
It is the one-page launcher for shared curriculum, private evidence, builders, first-build workflows, repair tools, and current course/system control panels.

PORTABLE TEACHER WORKSPACE - HARD DIRECTION
After another teacher is trained, the supported portable workspace may be copied to that teacher's machine/thumb drive as sibling folders:
  _algebra_teacher_tools/
  _portfolio_data/
  _github_transfers/
  algebra/
  memories/
The receiving teacher operates their own copies/state/repositories. Never use this portability model to expose one teacher's live private student evidence to another teacher.

CANONICAL CONTROL PANEL
The canonical Curriculum Control Panel exposes two top-level modes:
1. Build
2. General
Do not expose a generic Maintenance tab.

BUILD MODE
Initial course/unit establishment is owned by pms_build/MANIFEST.json. Current shared Build menu:
1. Build Assessment Plan
2. Build Framework
3. Build Bank
4. Build Notes
5. Build Practice
6. Build Activities
7. Build Quick Checks
8. Build Warm-Ups
9. Build Review
10. Build Summative
11. Build Unit Plan

Do not reintroduce retired/operational jobs such as First 4 Days, Progress Tracker, Practice to Summative, Discourse, Portfolio evidence processing, or generic combined special-resource jobs merely because old PM files exist.

GENERAL MODE
Purpose-specific general PMs are owned by pms_general/MANIFEST.json.

SHARED TEACHER DASHBOARD - HARD
The shared Algebra Teacher Dashboard may expose finished curriculum/resources that another Algebra teacher can use: Notes, Practice, Activities, Investigations, Warm-Ups, Reviews, approved Quick Check products, intentionally shared Checkpoint products, assessment plans, Banks/teacher views, Summatives, and approved shared teacher resources.

It MUST NOT expose owner-only operational controls for:
- Portfolio evidence processing;
- Portfolio email/report delivery;
- personalized Checkpoint Builder;
- Quick Check Builder/selector.

The dashboard distinguishes PRODUCTS from CONTROLS:
- green Quick Checks / Checkpoints Unit buttons open finished-product libraries;
- the corresponding builders stay in _algebra_teacher_tools.

Hiding a public link is not the long-term security boundary. Owner-only builder/control pages belong under _algebra_teacher_tools and should not remain as active public repository control pages after migration.

STUDENT PRACTICE BUILDER
The Student Practice Builder is a student/course resource, not a repeated Unit owner-control button. Shared/public dashboards should link the hosted course route:
  https://tnezki.github.io/algebra/practice_builder___p7r4x/student_practice_builder.html
so a teacher opening a local dashboard does not trigger file:// fetch failures.

ALGEBRA OWNER TOOLS - HARD
Current owner-local entry points include:
- _algebra_teacher_tools/index.html
- _algebra_teacher_tools/tools/checkpoint/checkpoint_builder.html
- _algebra_teacher_tools/tools/quick_check/quick_N.html
- Portfolio/email launch links surfaced only from the local owner index.

The owner index should group tools by job rather than give every control its own large card. At minimum it provides:
- Shared Curriculum links;
- Private Evidence links;
- Builders (Quick Check, Checkpoint, Practice/Set, Summative, Investigation, Performance Task, etc.);
- First Build buttons for the current Build factory sequence;
- Repair/Maintenance links;
- current Control Panels;
- finished evidence-library links.

The owner-tools folder stores controls/software only, not student evidence state. Student/private state remains in its authorized private location. Relative links should assume the stable sibling layout rather than hard-coding one machine-specific absolute path.

FINISHED PRODUCT LIBRARIES - HARD
Shared finished assessment products use library/index surfaces so a teacher can find every intentionally retained version without receiving the builder.

Quick Checks:
  algebra/quick_check____htq5855/library.html
  algebra/quick_check____htq5855/library.json
The registry is append-only. A makeup, alternate, or later approved run must not overwrite an earlier approved Quick Check.

Checkpoints:
  algebra/checkpoints___trmn78/library.html
  algebra/checkpoints___trmn78/shared_library.json
Only intentionally shared, non-student-specific Checkpoint products may appear there. Personalized Checkpoint runs remain private.

DASHBOARD MAINTENANCE MODEL
Shared artifact outputs remain course/unit/section organized. Owner-only creation/management controls live locally. A shared teacher should be able to open a produced Quick Check without receiving access to the selector that creates it.

ALGEBRA RECURRENCE / SET BUILDER REQUIREMENT
The Algebra Teacher Dashboard/owner hub must preserve access to the current mastery recurrence map:
  frameworks/2_Framework_Algebra_1/Algebra1_Spiral_Framework/curriculum/mastery_recurrence_map.html
and provide a clear route to the section Set Builder/control surface from local owner tools, while shared finished Sets remain available from the shared dashboard.

The Set Builder should open with recommended Target Plan A and Target Plan B from the recurrence map/current course profile. The teacher edits the recommendation rather than building the I Can mix from scratch.

QUICK CHECK OWNER-TOOL RULE
Algebra Build Quick Checks remains in initial Build because it creates/repairs the owner-local Unit selector. Routine section Quick Checks are built from that local selector. Approved products deploy to append-only run folders in the Algebra repository and are registered in the shared Quick Check library.

PORTFOLIO / PRIVATE EVIDENCE
Portfolio/evidence processing is an owner-only private-data workflow, not an initial curriculum build job and not a shared-dashboard control.

TRANSFER / REVIEW
Repository-targeting jobs return through the current local GitHub Transfer contract. Declared owner-local tool files under _algebra_teacher_tools may use the same transfer helper because destinations remain inside /Users/troynezki/Documents/GitHub; they are installed locally without Git operations and are never committed merely because they live beside repositories.

END - CURRICULUM CONTROL PANEL ARCHITECTURE CONTRACT
