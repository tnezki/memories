CURRICULUM CONTROL PANEL ARCHITECTURE CONTRACT
==============================================
STATUS: CURRENT
REVISION: 2026-09-26 v1.1

PURPOSE
Keep the canonical Curriculum Control Panel small and stable while moving day-to-day artifact operation to the teacher's actual course dashboards.

CORE MODEL - HARD
The canonical Curriculum Control Panel is the BUILD FACTORY.
The course Teacher Dashboard is the OPERATING SURFACE.

The canonical control panel exposes two top-level modes:
1. Build
2. General
Do not expose a generic Maintenance tab.

BUILD MODE
Initial course/unit establishment is owned by pms_build/MANIFEST.json. Current shared Build menu:
1. Build Assessment Plan
2. Build Framework
3. Build Bank
4. Build Notes
5. Build Practice
6. Build Activities
7. Build Quick Checks
8. Build Warm-Ups
9. Build Review
10. Build Summative
11. Build Unit Plan

Do not reintroduce retired/operational jobs such as First 4 Days, Progress Tracker, Practice to Summative, Discourse, Portfolio evidence processing, or generic combined special-resource jobs merely because old PM files exist.

GENERAL MODE
Purpose-specific general PMs are owned by pms_general/MANIFEST.json.

TEACHER DASHBOARD OPERATING MODEL - HARD
Once an artifact/tool exists, routine use/improve/rebuild should launch from a course/unit/section-specific control page linked from the Teacher Dashboard. The control page should already know the course/unit/section/artifact context that the teacher clicked from.

Expected patterns include:
- course-level: personalized Checkpoint, Student/Teacher Practice Builder, Portfolio/email tools;
- unit-level: Quick Check selector, future Summative controls, recurrence-map views;
- section-level: Notes, Practice/Set Builder, Activities, Investigations, and similar artifacts.

ALGEBRA RECURRENCE / SET BUILDER REQUIREMENT - FUTURE DASHBOARD REORG
When the Algebra Teacher Dashboard is reorganized, it MUST surface the current mastery recurrence map:
  frameworks/2_Framework_Algebra_1/Algebra1_Spiral_Framework/curriculum/mastery_recurrence_map.html
and provide a clear route to the section Set Builder/control surface.

The Set Builder should open with recommended Target Plan A and Target Plan B from the recurrence map/current course profile. The teacher edits the recommendation rather than building the I Can mix from scratch. Editable controls should include selected I Cans, question counts, optional family preference, and a small fine-tuning note.

Do not implement this future dashboard redesign opportunistically during unrelated curriculum builds; preserve this contract so it is not forgotten when the dashboard work is explicitly opened.

QUICK CHECK EXCEPTION
Algebra Build Quick Checks remains in initial Build because it creates/repairs the Unit selector. Routine section Quick Checks are built from the selector itself.

PORTFOLIO / PRIVATE EVIDENCE
Portfolio/evidence processing is an operational private-data workflow, not an initial curriculum build job. Do not reintroduce it to the generic Build menu.

TRANSFER / REVIEW
Repository-targeting Control Panel BUILD/MAINTENANCE jobs return through the current local GitHub Transfer contract. The transfer helper installs files locally without Git operations; teacher review/sync remains the promotion step.

END - CURRICULUM CONTROL PANEL ARCHITECTURE CONTRACT
