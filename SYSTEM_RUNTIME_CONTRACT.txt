CURRICULUM SYSTEM RUNTIME CONTRACT
=================================
STATUS: CURRENT
REVISION: 2026-09-26 - OFFLINE-FIRST + CURRENT TRANSFER ROUTING

1. CANONICAL GITHUB / STORAGE - HARD
Canonical GitHub stores readable authorities and long-lived readable artifacts expanded. ZIP is a handoff/transport format only unless a current artifact contract explicitly declares another archive boundary.

Resolve and pin the memories commit and selected course commit once at job start. Never mix later commits into one run. Resolve authorities through SYSTEM_MANIFEST.json and the relevant current registry/manifest; do not guess versioned filenames.

2. DECLARED AUTHORITY DIRECT-FETCH RULE - HARD
When a required authority/resource is declared by a manifest, Framework, artifact manifest, Bank index, or request snapshot, fetch that exact declared repo/path at the pinned commit. Do not use generic public-web search, repository archaeology, similarly named files, stale uploads, prior chats, or alternate copies to discover/verify/substitute it.

3. CONTROL PANEL REQUEST SOURCE POLICY - HARD
Curriculum Control Panel BUILD and MAINTENANCE jobs are closed-project-source jobs by default. Use only:
- current request/current explicit teacher instruction;
- request-provided files;
- exact pinned project GitHub repositories and declared paths;
- current manifests/Frameworks/PMs/tools resolved from those pinned repositories;
- current canonical course artifacts;
- explicitly authorized private state when a current operational workflow (for example Portfolio/Checkpoint) declares it.

Prior chats, project conversation history, saved/personal memory, assistant/model memory, prior assistant outputs, and stale uploaded copies are not curriculum authority or ambiguity resolvers for Control Panel execution.

File Library recovery is OFF by default. It may be used only when the CURRENT request explicitly authorizes project-artifact recovery, and never as a substitute for a missing declared canonical GitHub source.

Public-web research/fetch is OFF by default for Curriculum Control Panel BUILD and MAINTENANCE jobs unless current teacher instruction explicitly authorizes outside research.

4. TOOL ROUTING GATE - HARD
Tool-policy fields declared by a request/PM/profile are executable constraints, not commentary. When web/external research is disabled, do not perform public search/fetch detours for discovery, validation, examples, supplementation, question writing, source comparison, layout ideas, or convenience.

Direct reads from the exact pinned project GitHub repositories are allowed when current project policy permits them. A direct pinned project read is not permission for open public-web research.

5. FAIL-CLOSED RULE - HARD
If a required declared project source cannot be read directly at the pinned commit:
- fail closed;
- name the exact missing repository + commit + path/resource;
- do not search around the failure for similarly named files;
- do not substitute old uploads/chat copies/alternate representations.
Use the selected PM's declared missing-source failure code when one exists.

6. READ BUDGET / AUTHORITY OWNERSHIP
Read only files the selected PM requires. When a manifest declares a purpose-specific canonical file, use that file rather than opening broad trees.

Ownership:
- Philosophy -> universal learning/system principles;
- Question Structure -> shared task-design vocabulary;
- Framework/course profiles/maps -> course behavior and exact recurring architecture;
- PM -> procedure;
- registered tools/templates -> deterministic mechanics/rendering;
- Git history -> version history.

7. OFFLINE-FIRST DETERMINISTIC ASSEMBLY - HARD DIRECTION
When approved maps, Bank families, templates, parameters, and validators define a classroom artifact sufficiently, prefer local/offline deterministic assembly over repeatedly asking AI to reinvent routine content.

Safe deterministic work includes, when explicitly authorized by the owning family/contract:
- number/value/data substitution;
- table generation from a rule;
- graph/diagram generation through registered tools;
- computed answers/solutions;
- controlled misconception distractors;
- seeded parallel instances;
- question/answer-choice scrambling;
- count/path/syntax/hash validation;
- repeatable packaging and mechanical QA.

Every deterministic instance must preserve the exact learning target/I Can, evidence job, representation demand, response mode, usable difficulty, and family invariants. Store seed/parameters/provenance when the current schema supports them so an output can be reproduced.

Offline-first does NOT mean AI-free. Semantic curriculum authoring, new family design, rich-context writing, pedagogical repair, and teacher-facing judgment remain appropriate AI/teacher work. Never force deterministic generation when it reduces quality or changes the student thinking job.

8. LOCAL REPOSITORY TRANSFER - HARD
For Curriculum Control Panel BUILD/MAINTENANCE jobs whose canonical repository destination is known, return ONE local repository transfer ZIP using the contract declared by `local_transfer_contract` in SYSTEM_MANIFEST.json.

The transfer ZIP is an OUTER transport wrapper only. Canonical files live under:
  payload/<repo-folder>/<canonical-relative-path>
with TRANSFER_MANIFEST.json declaring create/replace/delete actions.

For one-file or multi-file repository changes, use the transfer wrapper rather than naked repository files. Do not require the teacher to unzip and manually place curriculum files.

If authorities do not declare enough information to resolve a safe repository destination, fail as:
  TRANSFER_DESTINATION_UNDECLARED
rather than guessing.

The local transfer helper performs no Git operations. After installation, changes remain uncommitted for teacher review in GitHub Desktop. Do not commit, push, pull, merge, branch, or create a PR unless a current explicit teacher request separately authorizes such Git work.

9. PRIVATE-STATE WORKFLOW EXCEPTIONS
Current operational workflows may declare a delivery exception in SYSTEM_MANIFEST/runtime amendments. In particular, Portfolio and personalized Checkpoint runs may read/write authorized private state and return their declared runtime artifacts rather than a GitHub Transfer ZIP. Those exceptions do not broaden ordinary curriculum build source policy or authorize student data in GitHub.

10. AUTOMATIC OUTPUT FINALIZATION - HARD
Every Curriculum Control Panel BUILD or MAINTENANCE job that produces/replaces files must run the current finalization contract declared by SYSTEM_MANIFEST.json before packaging/return.

Required order:
1. complete normal build/repair and artifact-specific QA;
2. run artifact-specific registered validators/normalizers;
3. run registered universal `finalize_output` against the complete final staging tree;
4. if finalization changes bytes covered by another validator, rerun that affected validator;
5. package/return only after required checks pass.

Universal finalization may repair only deterministic/mechanical output defects. It may not change curriculum meaning, question content, evidence mappings, difficulty, security, Learning Targets/I Cans, or other upstream instructional decisions.

Required successful terminal signal:
  FINALIZATION_QA: PASS

11. HUMAN REVIEW / AUTHORITY PROMOTION
Generated curriculum is a candidate until teacher review/testing and intentional sync to canonical GitHub. Runtime automation may install files locally through the transfer helper, but installation itself does not promote a curriculum decision beyond the teacher's review/sync step.

END - CURRICULUM SYSTEM RUNTIME CONTRACT
