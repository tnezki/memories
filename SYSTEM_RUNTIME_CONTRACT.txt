CURRICULUM SYSTEM RUNTIME CONTRACT
=================================

1. Canonical GitHub stores readable authorities and long-lived readable artifacts expanded. ZIP is a handoff/transport format only unless the resource is intrinsically an archive/binary bundle. A staged build checkpoint may remain a ZIP only when the PM explicitly treats the archive boundary/integrity as part of that temporary checkpoint contract.

2. Resolve and pin the memories commit and selected course commit once at job start. Never mix later commits into the run.

3. Resolve authorities through SYSTEM_MANIFEST.json and the relevant registry/manifest. Do not guess versioned filenames.

4. DECLARED AUTHORITY DIRECT-FETCH RULE - HARD
When a required curriculum authority or resource is declared by the system manifest, Framework manifest, course manifest, artifact manifest, Bank manifest/index, or request snapshot, fetch that exact declared resource at the pinned commit.
Do not use generic public-web search, repository-wide search, similarly named files, lightweight/alternate views, archived copies, prior uploads, or chat copies to discover, verify, supplement, or substitute a canonical curriculum source.
If an exact repo/path is declared, direct-fetch that repo/path. Do not search for it.

5. CONTROL PANEL REQUEST SOURCE POLICY - HARD
Curriculum Control Panel requests are CLOSED-PROJECT-SOURCE jobs by default.
Use only:
- the CURRENT request and current explicit teacher instruction for that job;
- request-provided files;
- exact pinned project GitHub repositories and declared paths;
- current manifests/Frameworks/PMs/tools resolved from those pinned repositories;
- current canonical course artifacts.

CONVERSATION ISOLATION - HARD
Prior chats, project conversation history, saved/personal memory, assistant/model memory, prior assistant outputs, and stale chat/upload copies are NOT permitted curriculum sources or ambiguity resolvers for a Control Panel job. Ignore them for job execution even if they are visible to the model. They may not be used to discover files, select between competing sources, supplement missing content, or justify curriculum decisions. A current explicit teacher correction in the active request/turn remains allowed.

File Library recovery is OFF by default. It may be used only when the CURRENT request explicitly sets `file_library_project_artifact_recovery_allowed = true`.

Public web is NOT an allowed default curriculum source.

6. TOOL ROUTING GATE - HARD
A request/PM/profile may declare tool-policy fields such as:
- `web_search_allowed = false`
- `web_fetch_allowed = false`
- `public_web_fetch_allowed = false`
- `external_research_allowed = false`
- `project_github_direct_fetch_allowed = true`
- `prior_chat_context_allowed = false`
- `project_conversation_history_allowed = false`
- `assistant_saved_memory_allowed = false`
- `file_library_project_artifact_recovery_allowed = false`

These declarations are EXECUTABLE CONSTRAINTS, not commentary.

When `web_search_allowed = false`:
- do not perform any action that would appear as `Searching the web` in the ChatGPT activity for the job;
- do not invoke public web/search-engine/browser-search tools for discovery, validation, freshness checking, examples, supplementation, question writing, source comparison, CSS/layout ideas, or convenience;
- do not use public-web search as a fallback after a failed project-source read;
- do not narrate or attempt a web-search detour before using a permitted exact project source.

When `public_web_fetch_allowed = false`:
- do not open/fetch public websites as substitute curriculum sources;
- do not use a public URL to bypass a declared project GitHub path.

Direct reads from the exact pinned project GitHub repositories are ALLOWED when `project_github_direct_fetch_allowed = true`. Use GitHub/project-repository tools for those reads. A direct pinned project-repository read is not permission for public-web research.

7. FILE LIBRARY RECOVERY - HARD
File Library is not curriculum authority and is disabled by default for Control Panel jobs.
Only when the CURRENT request explicitly sets `file_library_project_artifact_recovery_allowed = true` may it be used to recover a previously generated matching project artifact needed to resume/repair the current job. A PM/profile alone does not silently enable recovery when the request says false.
- Prefer the exact expected artifact name/course/unit/job identity.
- Verify fingerprint/record identity before use.
- Do not browse File Library for alternate curriculum authorities or outside replacements.
- Do not use File Library to substitute for a missing declared canonical GitHub source.

8. FAIL-CLOSED RULE - HARD
If a required declared project source cannot be fetched directly at the pinned commit:
- FAIL CLOSED;
- name the exact missing repository + commit + path/resource;
- do not search the public web;
- do not search around the failure for similarly named files;
- do not substitute old uploads/chat copies/alternate representations.

Failure code for a required project dependency:
`BANK_REQUIRED_PROJECT_SOURCE_MISSING` for Bank jobs, or the selected PM's equivalent missing-source code.

If public web research is used despite a no-web request, the affected curriculum build cannot PASS. Record `UNAUTHORIZED_PUBLIC_WEB_SOURCE`.

9. DEFAULT NO-WEB SCOPE - HARD
All Curriculum Control Panel BUILD and MAINTENANCE requests are NO-PUBLIC-WEB by default.
GENERAL requests created by the Control Panel are also no-public-web unless a future explicit request-level opt-in says otherwise.
This includes Bank Map, Bank Complete, Notes, Practice, Activities, Exit, Warm-Up, Progress, Review, Summative, Practice-to-Summative, Demos/Investigations, Performance/Quick Checks, Discourse, First 4 Days, Unit Plan, Portfolio, and maintenance jobs.
A Framework/profile hint, source note, model judgment, or convenience does not override the request-level no-web policy.
Only explicit current teacher authorization for outside research may change it.

10. READ BUDGET
Read only the files the selected PM requires. Heavy source/resource trees are on-demand resources, not default authority payloads. When a manifest declares a purpose-specific canonical file, use that file directly instead of opening a broader aggregate and searching inside it.

11. OUTPUT / HANDOFF
One output file is returned directly. Multi-file folders may be zipped for handoff, but the ZIP is extracted before canonical GitHub sync.

12. AUTHORITY OWNERSHIP
PMs own procedure; manifests own stable discovery; Framework/course profiles own course-specific behavior; Git history owns version history.

13. AUTOMATIC OUTPUT FINALIZATION - HARD
Every Curriculum Control Panel BUILD or MAINTENANCE job that produces or replaces files must run the current system finalization contract declared by SYSTEM_MANIFEST.json before returning the artifact.

Resolve:
- `finalization_contract` from SYSTEM_MANIFEST.json;
- all finalizer/validator tools only through Tools/MANIFEST.json.

Required order:
1. complete the selected PM's normal build/repair and artifact-specific QA;
2. run every artifact-specific registered validator/normalizer that the selected PM requires;
3. run the registered universal `finalize_output` tool against the COMPLETE final staging tree;
4. if finalization changes bytes that an artifact-specific validator covers, rerun that affected validator;
5. package/return only after the required checks PASS.

The universal finalization layer may repair only deterministic/mechanical output defects. It may not change curriculum meaning, question content, evidence mappings, difficulty, security, Learning Targets/I Cans, or other upstream-owned instructional decisions.

MathJax/TeX repair is part of universal finalization through the registered `fix_mathjax_output` tool. The fixer must preserve the artifact's existing delimiter family. Current Algebra Notes use `\\(...\\)` and `\\[...\\]`; the finalizer must not convert them to dollar delimiters merely because a legacy script did so.

A Control Panel artifact cannot report final PASS when required universal finalization returns nonzero. Repair allowed local/mechanical defects and rerun; otherwise report/fail according to the selected PM.

The required successful terminal signal is:
`FINALIZATION_QA: PASS`
