STATUS: CURRENT
STEP: 12
JOB: practice_to_summative
ROLE: Run the current registered build PMs from Practice through Summative in one controlled request.

THIS IS AN ORCHESTRATOR ONLY.

It does NOT own question authoring, Bank selection, shell DOM, CSS, security rules,
artifact-specific QA, or child packaging mechanics.

It owns only:
- child-PM resolution;
- execution order;
- one shared pinned system/course snapshot;
- staged handoff from an upstream child to a downstream child when required;
- stop-on-failure behavior;
- final all-in-one course-root packaging.

CORE RULE — HARD
----------------
DO NOT embed, restate, summarize, reconstruct, or reinterpret child PM logic here.

The CURRENT registered child PM is the sole procedural authority for its artifact.
If this orchestrator and a child PM appear to disagree about that child's content,
rendering, shell, security, QA, path, or source rules:

  THE CHILD PM WINS.

This PM exists so the teacher can run the existing PM stack with one Control Panel request
without maintaining a second duplicate implementation.

============================================================================

Every child must behave exactly as though its current PM were run independently against
the same pinned inputs.

- CSS selectors;
- workspace rules;
- figure sizing decisions;
- question-selection rules;

  THE CHILD PM WINS.
