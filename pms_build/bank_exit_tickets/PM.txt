STAGE 3C AUTHORING SCOPE - EXIT TICKETS ONLY
--------------------------------------------
Author every audited-map slot belonging to Exit Tickets and NOTHING ELSE.

For the current five-section Physics architecture this is normally:
- Exit Ticket A: 4 questions x 5 sections = 20
- Exit Ticket B: 4 questions x 5 sections = 20
- Exit Ticket C: 4 questions x 5 sections = 20
= 60 new Stage 3C items

Together with the normal 615 Stage 3B items, the Stage 3C checkpoint normally contains 675 authored canonical items and exactly 120 pending Summative slots. The AUDITED MAP owns actual counts.

Do NOT author any Summative item in Stage 3C.

WHY THIS STAGE EXISTS
---------------------
Exit Tickets are formative evidence, not extra Practice. They are authored only after the entire exposed instructional layer exists, so the builder can avoid simply recycling Example/YTI, Practice, CYU, or Warm-Up tasks while still collecting the mapped evidence efficiently.

Stage 3D will later see BOTH the complete exposed instructional layer and the complete Exit inventory before authoring secure Summative questions.

SECURITY / FRESHNESS PRINCIPLE
------------------------------
Inspect all Stage 3A/3B instructional questions before authoring Exit Tickets.

A secure Exit question MAY target the same I-can, question structure, formula, representation type, or kind of reasoning students practiced. It must NOT simply reproduce an exposed instructional question or distinctive stimulus/data set.

Security does not require forced novelty. Comparable parallel Exit forms are desirable.

GLOBAL WRITING RULES
--------------------
SHORT BY DEFAULT.
Four Exit questions should feel like an Exit Ticket, not a mini-test. Extra context is allowed only when it improves the Physics or carries evidence.

VISUALS ARE CHEAP, NOT A QUOTA.
If a graph, FBD, vector diagram, motion diagram, table, or model materially improves or carries the evidence, make a purpose-built one. B/C parallel forms normally receive their own corresponding values/data/visual instance when the evidence depends on it. Do not ration visuals merely to save work.

Exact visual uniqueness is NOT itself a requirement. Judge correctness, usefulness, and security.

PHYSICS BEFORE ALGEBRA SHELLS.
Quantitative Exit questions use concise physical situations. The situation supplies the measurements and students use, choose, rearrange, interpret, or combine the relationship. Do not write naked variable-assignment prompts.

NO UPSTREAM REPAIRS IN THIS STAGE.
Preserve every Stage 3A/3B canonical question object and figure unchanged. If an upstream defect is noticed, record it in STAGE_3C_REPORT.txt under UPSTREAM PATCH NOTES. Do not repair instructional content here.

EXIT EVIDENCE MAP FIRST
-----------------------
The audited Bank Map must already define the four Exit evidence jobs for each section before prose.

For each section, reconcile BEFORE authoring:
- exact I-can for A1-A4;
- exact evidence job;
- response demand;
- planned structure;
- representation requirement;
- security/freshness expectation;
- B/C parallel relationship.

If the map is materially incomplete or contradictory, FAIL CLOSED rather than inventing a replacement assessment plan.

FORM A CONTRACT - FOUR UNIQUE SECURE SEEDS
------------------------------------------
For each section:
- A1, A2, A3, and A4 are FOUR separate secure seed questions.
- Each one must do its own mapped evidence job.
- They may share an I-can when the map calls for it, but they are not four phrasings of one prompt.
- Each must be independently solved/verified.

A useful default evidence shape may include core understanding, conceptual reasoning, quantitative/application, and stronger transfer/representation evidence, but the audited map owns the actual four jobs. Do not force a generic quota over the map.

FORMS B/C CONTRACT - DELIBERATE PARALLELS
------------------------------------------
For each corresponding slot:
- B1 parallels A1; C1 parallels A1;
- B2 parallels A2; C2 parallels A2;
- and so on.

A legitimate parallel preserves:
- mapped I-can;
- evidence job;
- response demand;
- approximate difficulty;
- structural family.

It changes legitimate evidence details as appropriate:
- values/data;
- givens/unknown;
- physical situation;
- representation values/layout;
- misconception/evidence set;
- wording when useful.

Parallel does NOT mean changing only a noun when the map calls for a deeper variation. Parallel also does NOT mean forcing a completely different question just to look novel.

Do not force Standard / Inverted / Context-rich wording by form letter. Context-rich remains optional.

REPRESENTATIONS
---------------
When the mapped evidence requires a representation, the representation must actually exist.

Do not write prose such as "use the diagram" or "from the graph" when no actual representation is present.

For parallel forms, generate corresponding purpose-built data/graphs/diagrams when appropriate. Because graph/figure production is effectively free, do not reuse an old instructional graph merely to avoid generating a new secure one.
