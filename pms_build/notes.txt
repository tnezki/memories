BUILD NOTES — SINGLE PASS / BANK-V2.3 — ALGEBRA TEXTBOOK-STYLE PILOT
=========================================================================

STATUS: PILOT
ROLE: Build complete student + teacher Notes for one Unit from the current Framework,
the completed Bank, the accepted source_map that travels with the Bank, and any
Framework-declared instructional source/spine.

This remains ONE Notes build. There is no separate Notes Map stage.

JOB
---
SOURCE -> PLAN -> GENERATE -> PLACE -> ASSEMBLE -> RENDER -> CHECK

This job is NOT:
- a Bank rebuild;
- a Bank Map redesign;
- permission to alter Exit Tickets;
- permission to expose secure Summative items;
- a requirement that every possible Notes routine appear in every section;
- a requirement that the teacher complete every included Notes component in class.

CORE PRINCIPLE — NOTES ARE A MODULAR TOOLBOX
--------------------------------------------
Notes must teach the exact section Learning Target / I-can jobs, but the routine
mix is flexible.

The teacher is NOT expected to do Vocabulary Preview, WTC, preview/skim,
Talk to the Text / Close Reading, Stop & Discuss, and every EX/YTI pair every time.

Build each section so that:
- the core reading stands on its own;
- each included routine can be skipped without making later reading nonsensical;
- optional routines earn their place;
- the page does not feel like a checklist of every strategy the system knows.

TEACHER INPUT OVERRIDES
-----------------------
If the request explicitly asks to include/omit a routine, follow it unless doing so
would violate curriculum authority or make the artifact unusable.

When no teacher routine preference is supplied:
- use the SMALLEST useful routine set;
- do not stack all opening routines;
- normally use at most ONE opening routine before the main reading;
- use Stop & Discuss only where discussion materially helps;
- do not add a routine merely for visual variety.

-------------------
Read current Philosophy + SYSTEM_RUNTIME_CONTRACT first.

BANK ROLES
----------
WTC:
- canonical Bank item;
- use exact Bank WTC only when the section routine plan includes WTC;
- never rewrite it silently.

Exit:
- protected evidence;
- read only to enforce the Notes-vs-Exit firewall below;
- NEVER use an Exit item as the source template for a Notes EX/YTI pair.

Practice1:
- instructional calibration source;
- may inform typical values, representations, misconceptions, and difficulty;
- do not copy a Practice item verbatim when a fresh instructional instance is better.

Seeds:
- inspiration only;
- not required quota;
- use only when genuinely useful.

Secure Summative:
- not a Notes authoring source;
- do not expose secure prompt/stimulus/key content in Notes.

Use it to understand:

- question-structure intent;

Do NOT duplicate the entire map record inside every Notes task.

SOURCE / READING RULE
---------------------
Use the Framework-declared source/spine when one exists.

For Physics:
- preserve the declared textbook's major conceptual order, terminology, physics meaning,
  and usable instructional figure order;
- preserve the current Physics all-usable-instructional-image rule unless the Framework changes it.

For Algebra:
- do NOT force a textbook source when the Framework does not declare one;
- Framework synthesis is allowed;
- use concise explanation, examples, tables, graphs, and representations that directly teach
  the current I-can jobs;
- preserve durable mathematical language and avoid decorative prose.

Target a section that is reasonably usable in roughly 30–40 minutes IF the teacher
chooses to use most of it, but do not design the artifact as a mandatory 30–40 minute script.

SECTION CORE — REQUIRED
-----------------------
Every section requires:
1. section/title shell;
2. exact Learning Target;
3. exact I-can statements;
4. core instructional reading organized around exact I-can jobs;
5. generated EX/YTI inventory using the rule below;
6. concise close/summary.

OPTIONAL ROUTINE MENU
---------------------
The following are OPTIONAL by section unless teacher input/Framework explicitly requires them:
- Vocabulary / Key Notation Preview;
- canonical WTC;
- Let's Get Started / skim preview;
- Talk to the Text / Close Reading directions;
- Stop & Discuss;
- Formula / Relationship reference box;
- Common Mistakes;
- What I Figured Out / reflection;
- miscellaneous final workspace.

Omission of an optional routine is NOT a QA failure.

OPENING DENSITY — HARD
----------------------
Do not automatically render:
Vocabulary Preview + WTC + Let's Get Started + Close Reading directions
before the first real mathematics.

Default:
- choose zero or one substantial opening routine;
- a tiny target/objective box does not count as the opening routine;
- add a second opening routine only when there is a clear instructional reason.

EXAMPLE / YOU TRY IT — NEW GENERATION CONTRACT
-----------------------------------------------
Canonical Bank EX/YTI pairs are retired.

Generate Notes EX/YTI pairs DURING the Notes build.

DEFAULT:
- ONE complete Example/YTI pair per exact I-can.

SECOND PAIR:
A second pair for the same I-can is allowed ONLY when that I-can has a materially
different second learning job that cannot be represented well by the first pair.

Examples of earned second-pair reasons:
- two genuinely different required representations;
- two different procedures/decision paths;
- conceptual interpretation plus a distinct application/modeling job;
- a high-value misconception that needs a separate corrective instance.

Do NOT create a second pair merely for more practice.

PAIR FUNCTION
-------------
Example:
- models the mathematical thinking clearly;
- may be slightly more scaffolded;
- shows a complete teacher solution in teacher copy.

You Try It:
- fresh parallel instance of the SAME I-can/evidence job;
- less scaffolded;
- requires students to do the thinking;
- must not be the same values/context/stimulus as the Example.

The teacher is not required to complete every generated pair in class.
Pairs are a ready-to-use instructional inventory inside the Notes.

PAIR AUTHORING SOURCE
---------------------
Generate each pair from:
  exact I-can
  -> accepted map evidence job / representation route
  -> Question Structure
  -> Practice1 calibration when useful
  -> fresh Notes-specific authored instance

Do NOT generate from the Exit prompt.

QUESTION STRUCTURE
------------------
When EX/YTI is a question/task, follow the current Question Structure authority:
target/evidence -> natural structure -> response mode -> representation -> executable route
-> author -> solve/check -> render-level QA.

Direct reads stay direct.
Construction tasks need real answer-neutral response surfaces.
Mixed representations must visibly include every named representation.

EXIT TICKET FIREWALL — HARD
----------------------------
Before finalizing ANY generated Notes Example or YTI, compare it against ALL Unit Exit records.

Same I-can/evidence job is allowed.

PROHIBITED overlap:
- same prompt;
- same or trivially changed wording that preserves the Exit's distinctive task sequence;
- same values/data set;
- same context;
- same graph/table/equation stimulus;
- same distinctive representation with only cosmetic changes;
- a near-parallel item that effectively lets students rehearse the Exit answer.

If a conflict is found:
- regenerate the Notes item;
- do NOT alter the Exit;
- re-run the firewall check.

Record for every generated Notes task:
  exit_firewall_checked = true

QA must report:
  notes_exit_duplicate_count = 0

Fail code:
  NOTES_EXIT_NEAR_DUPLICATE

WTC — OPTIONAL BUT CANONICAL
----------------------------
When WTC is included:
- use the exact canonical Bank WTC once;
- preserve item ID, prompt, representation, I-can identity, answer/solution lineage;
- teacher copy may add instructional/discourse support;
- student copy must not leak the answer.

When WTC is omitted:
- do not create a replacement WTC;
- omission is not a defect.

READING / EXACT I-CAN COMPARTMENTS
----------------------------------
For each exact I-can:
- create at least one major reading block;
- use `<section class="notes-ican-start">`;
- use `<h2 class="h-intro notes-ican-heading">EXACT I-can text</h2>`;
- place the concise explanation/representation that teaches that I-can beneath it;
- place the generated EX/YTI pair at the most natural point in that I-can's reading.

Do not create filler text just to separate routines.

STOP & DISCUSS — OPTIONAL
-------------------------
Use only when student talk would materially improve interpretation, comparison,
reasoning, critique, or misconception repair.

Do not insert one after every substantial paragraph.

When included:
- 2–4 short prompts;
- grounded in immediately preceding content;
- at least one prompt must require actual mathematical/conceptual reasoning;
- vocabulary prompt is useful when vocabulary is central, but is NOT mandatory in every discussion.

Shell:
  <section class="notes-discuss-task">
    <div class="stop-discuss">
      <strong>Stop and Discuss</strong>
      <ol>...</ol>
    </div>
    <div class="notes-ws"></div>
  </section>

REPRESENTATIONS
---------------
Preference:
1. current source figure when source-owned and instructionally appropriate;
2. canonical Bank representation when reuse is appropriate and does not violate Exit firewall;
3. registered project tool;
4. semantic HTML/CSS for simple tables/response surfaces.

Graphs:
- use registered graph tool when a new graph is required;
- no hand-built coordinate SVG fallback;
- answer-neutral student surfaces.

Tables:
- real semantic HTML;
- use `.values` / `.compact-table` as appropriate.

For Algebra Notes:
