C. STANDARD GENERATED CONTENT CHECKLIST
=====================================================

These parts are purpose-authored directly from the exact section Learning Target / I Cans.
Do not conduct a separate research pass.

[ ] C1. Section Introduction
    - short meaningful opening
    - no fake career relevance
    - not a restatement of the Learning Target

[ ] C2. Vocabulary Preview
    - only useful section vocabulary/notation
    - Know for sure | Recognize | Don't know yet

[ ] C3. Section Preview
    - exactly two rows:
      What I noticed
      What I wonder

[ ] C4. Close Reading Directions
    - one global directions box
    - no repeated Talk to the Text boxes

[ ] C5. For each exact I Can, generate:
    1. robust reading
    2. substantive Math Notes
    3. Example
    4. You Try It
    5. Stop and Discuss

[ ] C6. Robust reading
    - normally 2–4 concise paragraphs
    - teaches the idea
    - connects words to representations
    - contains substance worth annotating

[ ] C7. Math Notes
    - actual mathematics must be visible
    - use real equations/rules, tables, graphs, contexts, mappings, diagrams, or processes
    - styled labels alone do not count

[ ] C8. Representation diversity — FOLLOW FRAMEWORK EXACTLY
    - Algebra Framework §8 owns the representation system.
    - If Math Notes intentionally show FOUR views of one relationship, use exactly:
      Equation/Rule | Table | Graph | Context/Situation.
    - Ordered Pairs may appear only as correspondence notation inside the table/graph connection.
    - A standalone Ordered Pairs card does NOT count as a fourth view and may not replace Graph.
    - do not count a restatement as a new representation.

[ ] C9. Representation fidelity — HARD
    If the prompt names a representation, render that representation literally.

    TABLE:
      Use a real semantic HTML table with labeled rows/columns/cells.
      A sentence or list of ordered pairs is NOT a table.

    GRAPH:
      Use an actual graph stimulus, or an actual blank coordinate plane when students
      are constructing the graph.

    MAPPING:
      Use an actual mapping diagram.

    ORDERED PAIRS:
      Use ordered-pair notation only when ordered pairs themselves are the intended job.
      Do not substitute ordered-pair prose for a table.

    CONTEXT:
      Use an actual situation/context.

    Missing named representation -> NOTES_REQUIRED_REPRESENTATION_MISSING.

[ ] C10. Graphs
    - when the Framework/learning job requires Graph, generate an ACTUAL graph with the current registered Algebra graph tool
    - call the registered Algebra graph tool directly
    - do not replace a required graph with Ordered Pairs, prose, or a duplicate table
    - do not inspect old graph scripts for examples/patterns
    - do not build a new graph tool during Notes
    - if the registered graph tool cannot produce the required graph, REPORT NOTES_REQUIRED_GRAPH_MISSING with owner GRAPH_TOOL_REPAIR; do not pretend the representation set is complete
