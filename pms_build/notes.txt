BUILD NOTES — STEP 4B / BANK-V2
=================================

STATUS: CURRENT
ROLE: Build the complete student + teacher Notes package for one Unit from the accepted current 4A Notes map and the finalized Bank-v2 Notes records.

4B is ADAPT / ASSEMBLE / RENDER.
It is NOT a second mapping stage.
It is NOT a Bank audit.
It is NOT permission to redesign the established Notes HTML/CSS format.

The current Course Framework/profile owns course-specific Notes behavior.
The established course Notes shell/CSS owns presentation.
This PM owns procedure.

======================================================================
STARTUP — HARD
======================================================================

Read the current Curriculum Philosophy and Runtime Contract first.
Resolve and pin the required repositories once at job start.
Resolve declared authorities directly through manifests.

Canonical PM:
  pms_build/notes.txt

Canonical 4A input:
  <course>/notes/uN_notes_map/uN_notes_map.json

Required map:
  schema = physics-notes-map/2.0
  notes_flow_revision = bank-v2-textbook-chunks-v1

Do not accept/reinterpret an older Stage 3E-era Notes map.
If the current canonical map is older/incompatible, FAIL CLOSED and report that 4A must be rerun.

======================================================================
NO-WEB / DIRECT-FETCH POLICY — HARD
======================================================================

Normal 4B is a declared-source curriculum build.

Do NOT use:
- public web search;
- public-web fetch as a substitute for declared GitHub resources;
- repository-wide search for known paths;
- File Library search;
- upload search;
- prior Bank ZIP discovery;
- old generated Notes as source authority.

Fetch exact declared resources at their pinned paths/commits.

If a required declared source fails:
FAIL CLOSED with exact repository, pinned commit, path/resource, and failed requirement.
Do not search around it.

======================================================================
1. AUTHORITIES / OWNERSHIP
======================================================================

Precedence:
1. Current explicit teacher instruction.
2. Current Curriculum Philosophy.
3. Current Course Framework, including its exact embedded Unit Assessment Plan and Notes profile/contracts.
4. Accepted current 4A Notes map for the Unit's mapped instructional flow.
5. Finalized current Bank-v2 Notes records for exact WTC / Example / YTI content.
6. This PM for assembly/render/package procedure.
7. Declared tools + established course Notes HTML/CSS shell for mechanics.

The Framework owns:
- exact section title / LT / I-cans;
- course terminology/boundaries;
- Notes reading/tone/representation behavior;
- student/teacher behavior;
- visual/usage contracts;
- source roles and course-specific exceptions.

The accepted 4A map owns:
- source KEEP/CONDENSE/DROP decisions;
- reading chunk boundaries/fidelity;
- mapped source/image locations;
- WTC / EX-YTI / discussion / reference-note placement;
- post-reading EX/YTI queue;
- close targets;
- generated-representation needs.

The finalized Bank-v2 Notes files own:
- exact canonical WTC student content + solution;
- exact canonical Example/YTI student content + solutions;
- exact pair identity;
- Bank-owned representations.

4B owns:
- final source trimming/adaptation allowed by the map;
- transition headings;
- final course-appropriate reference-note wording;
- final Stop & Discuss wording;
- vocabulary definitions;
- Summary / reflection / Common Mistakes wording;
- student HTML;
- teacher HTML;
- generated local representations explicitly mapped by 4A;
- targeted QA/package.

======================================================================
2. FAST INPUT GATE — 4A MAP
======================================================================

Read:
  notes/uN_notes_map/uN_notes_map.json

Require:
- correct schema/revision;
- correct course/unit;
- qa.status = PASS;
- pinned source identities present;
- Bank manifest identity present;

`NOTES_MAP_HANDOFF.json`, readable HTML, and report are derived.
Their absence/malformation does not invalidate a correct canonical map JSON; regenerate derived provenance as needed.

Do not use a legacy map fallback path in normal Bank-v2 production.

======================================================================
3. BANK-V2 IDENTITY / CONTENT GATE
======================================================================

At the current pinned course commit read:
  banks/unitN/BANK_MANIFEST.json

Require:
- schema compatible with `canonical-bank-manifest/2.0`;
- correct course/unit;
- status = COMPLETE;
- ready_for_downstream = true;
- canonical Notes routes present.

For each map-declared Bank Notes source:
1. resolve the current canonical section route from BANK_MANIFEST;
2. fetch that exact Notes section file;
3. compare its blob SHA to the map-recorded blob SHA.

If the current course commit changed since 4A but every consumed Notes file blob SHA is unchanged, the map remains valid for Bank Notes content.

If any consumed canonical Notes file changed:
FAIL CLOSED and report the changed section/path.
Rerun 4A so instructional routing is reconciled intentionally.

Do NOT:
- read STAGE_3E_HANDOFF.json;
- compute Stage 3E fingerprints;
- run `stable_bank_fingerprint.py`;
- search for an old Bank ZIP;
- scan unrelated Bank destinations.

Load each consumed canonical Notes section file ONCE and index its records by item_id.

======================================================================
4. TARGET / SOURCE-SPINE GATE
======================================================================

Verify map title/LT/I-cans against the current pinned Course Framework.

Resolve the map-declared instructional source/spine at the exact commit recorded by 4A.
For current Physics, this is the pinned `tnezki/textbooks` Physics section source.

Read only mapped source files/spans needed by 4B.
Do not reread unrelated textbook sections or source trees.

Apply mapped source fidelity:
- CLOSE -> preserve source paragraph logic and useful wording; trim mainly by omission;
- LIGHT_CONDENSE -> preserve explanation/sequence while removing repetition/detail;
- STRONG_CONDENSE -> preserve only the essential conceptual job and only when explicitly mapped.

Do not replace retained source exposition with generic short summaries merely for compactness.

======================================================================
5. FORMAT IS LOCKED — DO NOT REDESIGN
======================================================================

Ordinary 4B production MUST use the current established course Notes HTML/CSS shell.

For current Physics, read from the SAME pinned course snapshot:
  css/base.css
  css/notes.css

Production HTML links exactly, in order:
  <link rel="stylesheet" href="../../css/base.css">
  <link rel="stylesheet" href="../../css/notes.css">

Do NOT:
- invent a new Notes stylesheet;
- copy CSS into the PM/output;
- introduce a third ordinary production stylesheet;
- redesign typography, colors, spacing, title cards, Notes boxes, task cards, tables, or page architecture;
- invent a new class vocabulary where the established shell already supports the job;
- use an old generated Notes file as a competing format authority.

Use the established classes/hooks supported by the pinned Notes CSS, including the current equivalents of:
- `.vocab-preview-section`;
- `.notes-wtc`;
- `.skim-section-task`;
- `.notes-ican-start`;

- `.notes-task-content`;
- `.notes-task-workspace`;
- established figure wrappers;
- `.notes-mistakes-block`;
- established summary/reflection/workspace classes.

A course-specific label such as `Physics Note` may use the established reference-note shell.
Do not create a new stylesheet merely to rename the label.

======================================================================
6. STUDENT NOTES — NOTABILITY-FIRST
======================================================================

Use the current Framework/profile/visual contract.

Student Notes:
- preserve exact target/section sequence;
- remain clean and answer-free;
- use generous existing writing-space contracts;
- preserve answer-neutral student representations;
- use established keep-together containers;
- allow natural page flow;
- do not clip/shrink content merely to hit a page count.

Do not add a Notes Exit Ticket / Exit Check.

Do not use forced page breaks for ordinary layout repair.
A forced break is allowed only where the current Framework/visual contract intentionally defines a separate page/workspace.

Do not place enormous multi-page reading inside one avoid-break wrapper.

======================================================================
7. SECTION ASSEMBLY — MAP-DRIVEN
======================================================================

For each section:
1. render the established section/title treatment;
2. exact Learning Target;
3. exact I-cans;
4. map/Framework-defined opening sequence;
5. canonical WTC at its mapped location;
6. mapped source reading chunks in order;
7. mapped source/toolkit/Bank representations at their mapped concept locations;
8. mapped Stop & Discuss/reference-note events;
9. mapped canonical Example/YTI pairs;
10. post-reading EX/YTI queue in order;
11. mapped close: vocabulary definitions, Summary, reflection when required, Common Mistakes, and Framework-defined final workspace;
12. finalize STUDENT HTML;
13. derive TEACHER HTML from the finalized student structure;
14. run targeted section QA.

Do not re-plan the section in 4B.
If the map itself is pedagogically wrong but structurally valid, report that as a 4A-map defect rather than silently remapping.

======================================================================
8. CANONICAL BANK CONTENT — EXACT
======================================================================

For every mapped WTC / Example / YTI:
- find the exact item_id in the mapped Bank Notes section file;
- preserve canonical student task content;
- preserve pair_id/pair_number;
- preserve canonical Bank representation content;
- preserve source ID in hidden provenance/data attributes when useful;
- use the matching canonical Bank solution in teacher support;
- do not rewrite/swap/split/improve the canonical task during ordinary production.

If a real Bank defect is discovered:
report the upstream Bank defect.
Do not create a silent corrected second canonical version inside Notes unless the teacher explicitly authorizes a local artifact exception.

======================================================================
9. STOP & DISCUSS / REFERENCE NOTES
======================================================================

Render only the processing jobs mapped by 4A and required by the current course profile.

Stop & Discuss:
- write final prompts from the mapped discussion job/source basis;
- keep prompts content-specific;
- preserve the intended vocabulary/conceptual/representation work;
- provide appropriate existing response space;
- do not paste generic discussion prompts.

Reference note:
- use the established Notes reference-note shell;
- write concise concept-specific explanation;
- may include a relationship/equation/model/representation when mapped;
- is not a second worked-example Bank.

Framework/profile behavior overrides any old PM habit.

======================================================================
11. BANK REPRESENTATIONS / GENERATED REPRESENTATIONS
======================================================================

Bank-owned representations:

- do not silently regenerate;
- resolve through the canonical Bank route/figure reference using the current course repository and established Notes shell/path behavior.

Generated Notes-specific representations:
- create ONLY when explicitly mapped by 4A;

======================================================================
12. TEACHER COPY — SAME LESSON, NATURAL FLOW
======================================================================

Derive the teacher copy from the finalized student structure.

Teacher copy:
- preserves all student content/order;
- exposes canonical Bank answers/solutions;
- adds mapped discussion reasoning/evidence support;
- adds concise facilitation/discourse support where the current course Framework/profile requires it;
- uses RED for teacher answers/support where that is the established course behavior;
- uses bullets for multi-part answers/reasoning and teacher/student moves when appropriate;
- releases fixed student workspace heights so teacher content expands naturally;
- never overlaps later content.

Teacher-only natural-flow CSS overrides may be embedded when required by the current established contract.
Do not modify student `notes.css` merely to solve teacher-only expansion.
