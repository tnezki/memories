BUILD NOTES — SINGLE PASS / ALGEBRA TEXTBOOK NOTES v1.0
=====================================================

STATUS: PILOT-APPROVED SHELL
ROLE: Build complete student + teacher Notes for the requested Unit from the current
Framework, current Unit Assessment Plan, completed Bank, accepted source_map, and current
Algebra Notes profile.

This remains ONE Notes build. There is no separate Notes Map stage.

JOB
---
SOURCE -> PLAN -> GENERATE -> PLACE -> ASSEMBLE -> RENDER -> CHECK

NOTES FAST PATH — HARD
----------------------
This build is intentionally template-driven. Do not turn Notes into a research or recovery job.

DEFAULT UNIT NOTES WORKFLOW:
1. Resolve the pinned current authorities once.
2. Read the exact Unit Assessment Plan for Learning Target / I Can text.
3. Read the current Notes profile + reusable template + Notes CSS.
4. Read BANK_MANIFEST.json only to confirm COMPLETE / ready_for_downstream.
5. Read wtc.json and exit.json.
6. Fill the approved section shell.
7. Generate reading, Math Notes, vocabulary, preview, summary, reflection, and Common Mistakes directly from the exact section Learning Target / I Cans.
8. Generate one Example/YTI pair per I Can by default.
9. Run the intensive duplicate check ONLY on generated Example/YTI tasks against current Unit Exit items.
10. Assemble the Unit, render once, fix actual render defects, and return the package.

DO NOT by default:
- search File Library;
- recover prior Notes;
- search for alternate sources;
- read secure Summative;
- read the full ITEM_INDEX;
- read the full source_map;
- read all Practice1 records;
- read Seeds;
- perform repeated fingerprint checks after the pinned Bank manifest is accepted;
- re-resolve paths already declared by the request/manifests;
- repeatedly narrate path/tool checks.

Practice1 may be read ONLY when a specific Example/YTI needs difficulty calibration.
source_map may be copied into provenance without deep-reading every record when the request already pins the accepted Bank/map identity.

The Notes build should behave like a controlled fill-in-the-template job, not a new curriculum-design pass.

HARD EXIT FIREWALL — FOCUSED
-----------------------------
The intensive Exit duplicate check is for generated Example/YTI tasks.

For each generated Example and You Try It:
- compare against current Unit Exit items;
- if prompt/stimulus is too close, regenerate the Notes task;
- try at most 3 times;
- then use the cleanest non-duplicate version and document any remaining concern.

Do NOT run the same expensive duplicate-search routine over ordinary reading prose,
Vocabulary Preview, Section Preview, Math Notes explanation, Summary, reflection, or
Common Mistakes.

Stop & Discuss should remain conceptual/discussion-oriented and must not copy an Exit prompt,
but it does not require a full duplicate-search pass unless it becomes a task-specific
assessment rehearsal.

Prohibit:
- same prompt;
- same values/data;
- same context;
- same graph/table/equation stimulus;
- cosmetic rewrites of the same distinctive task;
- near-parallel rehearsal that effectively gives away the Exit.

Same I Can/evidence job is allowed.
Same task instance is not.

If canonical WTC conflicts materially with Exit:
- NEVER alter or expose the secure Exit item;
- try up to 3 safe WTC stimulus repairs using allowed variation axes while preserving the WTC evidence job, structure, dependency chain, representation demand, and difficulty;
- if a clean repaired WTC is found, use that repaired WTC in the Notes build and record the exact proposed upstream Bank repair in the build report/handoff;
- if no clean repair is found after 3 attempts, KEEP the exact canonical WTC in the student Notes, add a clear TEACHER-COPY warning immediately above that WTC, document the conflict and proposed upstream repair, and CONTINUE the Unit Notes build;
- do NOT omit a canonical WTC solely because of an Exit conflict;
- a WTC/Exit conflict by itself is NOT a build-stopping failure after the repair attempts are exhausted;
- report status as PASS_WITH_UPSTREAM_WTC_REPAIR when the rest of Notes QA passes.

=====================================================
2. VOCABULARY / SECTION PREVIEW / CLOSE READING
=====================================================

VOCABULARY PREVIEW — STANDARD
-----------------------------
Normal Algebra section includes:
- useful vocabulary / notation list;
- prior-knowledge sort:
  Know for sure | Recognize | Don't know yet.

Keep only vocabulary that matters for this section.
Do not pad the list.

SECTION PREVIEW — STANDARD
--------------------------
Use exactly two pre-reading rows:
- What I noticed
- What I wonder

Directions should ask students to skim headings, tables, graphs, and examples before
close reading.

Do NOT add a third preview-conclusion row later.
The post-reading reflection is owned by What I Understand Now.

Section Preview visually uses the SAME cream/red family as Vocabulary Preview.
Do not use the older pale-blue preview styling.

CLOSE READING DIRECTIONS — STANDARD
-----------------------------------
Use one blue directions box before WTC.

Direction language:
READ IN SHORT CHUNKS.
Students annotate words and visuals together:
- underline evidence;
- circle/highlight bold vocabulary;
- label arrows/important features;
- connect text to tables/graphs/figures;
- jot short questions/connections in margins.

This single directions box applies through WTC and the core reading.
Do NOT insert separate TALK TO THE TEXT callout boxes inside every I Can section.

=====================================================
3. I CAN COMPARTMENTS — HARD
=====================================================

Each exact I Can gets one major section in Framework order.

Heading form:
  [maroon badge with white text: I Can N] + exact I Can text

Example:
  I Can 1 | Find matching values across different representations.

The badge is visual only.
Do not rewrite exact I Can wording.

Every I Can compartment contains, in order:
1. robust reading;
2. substantive Math Notes;
3. Example;
4. You Try It;
5. Stop and Discuss.

ROBUST READING
--------------
Reading should be more than a transition paragraph.

Default:
- 2–4 concise paragraphs;
- define/clarify the concept;
- connect words to representations;
- explain what students should notice;
- prepare students to interpret the Math Notes;
- use bold vocabulary naturally;
- give students something worth annotating under the global Close Reading directions.

Avoid:
- generic filler;
- repeating the same sentence in prose and Math Notes;
- unnecessary formalism.

=====================================================
4. MATH NOTES — SUBSTANTIVE VISUAL REFERENCE
=====================================================

Math Notes keep the approved cream surface + blue border/header language.

HARD STANDARD:
The inner white Math Notes canvas must make ACTUAL MATHEMATICS visible.

Good forms:
- same relationship shown as situation + rule + table + graph with corresponding parts
  highlighted consistently;
- rule -> table -> graph translation;
- situation key words highlighted and matched to exact equation parts;
- annotated expression/equation;
- side-by-side MATCH / MISMATCH;
- values/rate/pattern evidence examples;
- real mapping diagrams;
- graph/table/equation alignment;
- process/decision diagrams grounded in actual mathematics.

Styled text cards alone do NOT satisfy the visual requirement.

REPRESENTATION DIVERSITY — HARD
-------------------------------
Do not count two surfaces as different representations when one merely restates the other.

Examples:
- a table row and the ordered pair copied from that same row are NOT two distinct views;
- an evaluated rule and the same numeric pair written beside it are NOT two distinct views.

For multiple-representation Math Notes, prefer genuinely different forms such as:
- Rule / Equation
- Table
- Graph
- Context / Situation

An ordered pair may be highlighted as a connection INSIDE the table/graph/rule comparison,
but it should not replace a genuinely different representation when the purpose is to compare views.

MATCHING HIGHLIGHTS
-------------------
When corresponding quantities appear across representations, use consistent highlight
families to make the connection visible.

Example:
- starting amount in situation <-> intercept/constant term;
- per-unit amount <-> rate/coefficient;
- one ordered pair <-> table row <-> graph point <-> evaluated rule.

Use color sparingly and consistently.

GRAPHS
------
Production builds use the registered Algebra graph tool for coordinate/function graphs.
Do not hand-build coordinate SVG in production.
The approved pilot used self-contained SVG only for layout testing.

=====================================================
5. EXAMPLE / YOU TRY IT
=====================================================

Generate Notes EX/YTI during the Notes build.

DEFAULT:
One Example/YTI pair per exact I Can.

SECOND PAIR:
Only when the I Can contains a materially distinct second instructional job:
- different required representation;
- different decision/procedure;
- concept + application/modeling;
- major misconception requiring its own instructional instance.

STUDENT COPY
------------
Both Example and YTI show:
- full prompt;
- needed representation/stimulus;
- blank workspace.

The Example is NOT pre-solved in the student copy.

The teacher models the Example live.
The YTI is the fresh parallel student attempt.

TEACHER COPY
------------
Teacher copy adds after each Example/YTI:
- correct answer;
- worked reasoning / solution;
- useful teacher move;
- likely misconception/listen-for when useful.

Do not put worked Example answers into the student Notes.

=====================================================
6. STOP AND DISCUSS
=====================================================

Every normal I Can compartment includes Stop and Discuss after the YTI.

Use 2–3 concise prompts.

Prompts should:
- connect directly to the reading/Math Notes/Example/YTI just completed;
- ask students to explain, compare, identify evidence, critique, or connect representations;
- not become a second practice set;
- avoid cloning Exit evidence tasks.

Provide a modest response area.

=====================================================
7. END-OF-SECTION REFERENCE / REFLECTION
=====================================================

VOCABULARY REFERENCE — STANDARD
-------------------------------
Place before Section Summary.

Two columns:
  Term | Meaning in this section

Use the approved Algebra blue/navy reference styling.
Definitions should be concise and section-specific.

SECTION SUMMARY — STANDARD
--------------------------
Short bullet summary of the most durable section ideas.

WHAT I UNDERSTAND NOW — STANDARD
--------------------------------
Place immediately after Summary.

Prompt students to explain the most important idea from the section in 2–4 sentences
and connect it to one relevant value, rate, pattern, table, graph, equation, situation,
or representation.

Provide generous blank writing space.

COMMON MISTAKES — STANDARD / FINAL
----------------------------------
Final visible section.

Use 2–4 high-value mistakes:
  Mistake | What to remember

Draw from:
- section concepts;
- accepted map;
- Practice calibration;
- known mathematical misconceptions.
