CANONICAL PRACTICE FAMILY CONTRACT
----------------------------------
Each map family becomes ONE canonical family record containing:

IDENTITY / ROUTING
- family_id exactly equal to map family_id/record_id;
- record_mode = family_seed;
- destination = practice;
- section;
- family_type;
- primary_i_can_id + exact primary_i_can;
- supporting_i_can_ids when mapped;
- selection_tags and mapped deterministic-selection metadata.

EVIDENCE DESIGN
- evidence_job;
- explicit intended_reasoning;
- question_structure_id;
- response_mode;
- representation_mode;
- representation_need;
- difficulty_intent;
- security_level;
- wording_profile when mapped.

FULLY AUTHORED CANONICAL SEED
- canonical_seed.student_text;
- canonical_seed.student_html;
- canonical_seed.choices when applicable;
- canonical_seed.answer;
- canonical_seed.solution_text;
- canonical_seed.solution_html;
- canonical_seed.figure_refs;
- actual embedded table/data/model content when part of the item.

TRANSFORMATION CONTRACT
- locked_elements as explicit locks;
- allowed_variations as explicit permitted axes/rules;
- required_variations as explicit change requirements;
- forbidden_variations as explicit prohibited changes;
- representation_variation_rule when mapped;
- source_map_record_id;
- source_basis when useful.

Do NOT add audit_status / NEEDS AUDIT / KEEP / CLEAN / REBUILD fields.
Do not expose family IDs, map language, or transformation metadata in student-facing content.

SEED QUALITY — HARD
-------------------
A family seed is not a vague template and not “write another question like this.”
It is one complete, classroom-usable canonical question with correct answer and full solution.

Each seed must:
- perform the mapped evidence job;
- match the mapped response mode and question structure;
- preserve the intended approximate difficulty;
- include the actual representation when evidence depends on one;
- be independently solved/checked after final wording/data are fixed;
- be complete enough for downstream controlled sibling generation.

FAMILY VARIATION QUALITY — HARD
-------------------------------
Allowed variation is controlled, not random.

A valid sibling:
- preserves every locked property;
- satisfies every required variation;
- changes only allowed axes.

A variant is invalid when it relies only on prohibited surface changes such as names/objects, wording profile, choice order, or number changes when the family requires deeper semantic/stimulus variation.

------------------------------------
Author the complete mapped family pool, not only one selected set or feasibility witness.

For the Physics pilot: all 30 families per section.

The map owns downstream deterministic selection:
- hard coverage/composition constraints first;

- same pinned Bank identity + same declared set key -> same selected family IDs/order.
