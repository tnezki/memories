QUESTION STRUCTURE — HARD
Every mapped FINISHED QUESTION/TASK must resolve through the current universal Question Structure workflow:
  learning/evidence target -> evidence job -> student action -> structure -> response -> representation -> tool/render route.
A course may explicitly exempt a resource. If the Framework says Warm-Ups are exempt, do not force Warm-Ups through Question Structure.
Seed records are not finished questions; Question Structure applies when a seed becomes an authored question.

SEMANTIC STRUCTURE FIT — HARD
A structure ID that exists in the catalog is NOT enough to PASS. For every mapped finished task, read the CURRENT definition of the selected structure and verify all of the following agree:
- evidence job
- actual student action
- structure reasoning architecture
- structure required representation
- response mode
- mapped representation mode(s)
- executable tool / asset / response-surface route(s)

Do not use a generic fallback structure merely because it is broadly applicable.
Direct tasks may stay direct when a more elaborate architecture is not earned by the evidence job.

HARD SEMANTIC GUARDS
1. CONSTRUCT / PLOT / CREATE / DRAW / BUILD
   - If the evidence job requires the student to construct a representation, the response mode must collect that construction and the map must provide a real answer-neutral construction surface.
   - A read-only supplied-representation structure cannot stand in for construction evidence.

2. PROC-MULTISTEP-CHAIN
   - May PASS only when the map records a genuine dependency: an intermediate result/decision is required and carried into a later step to obtain the final requested result.
   - Store the dependency explicitly.
   - Multiple actions or labels alone do not make a task multi-step.

3. ERROR-DIAGNOSE-WORKED-SOLUTION
   - May PASS only when there is a specific documented misconception/error target, a supplied worked-solution stimulus containing that error, and a student action that locates/explains/repairs the error.
   - Do not map ordinary evaluation/solving to Error Diagnose merely to add variety.

4. MIXED / MULTIPLE REPRESENTATIONS
   - Every representation named by the evidence job/student action must have an executable route.
   - A graph+table task requires both a graph route AND a semantic table route, or one declared composite route that explicitly renders both.

5. STUDENT-CONSTRUCTED GRAPHS / NUMBER LINES / TABLES
   - Use an answer-neutral response surface.
   - Do not pre-render the completed mathematical answer with a graph tool.

6. STRUCTURE REASONING ARCHITECTURE
   - QA must compare the catalog's actual reasoning architecture/required representation/response type with the mapped evidence job and action.
   - Metadata presence alone cannot earn PASS.

7. DIRECT READ / IDENTIFY / EXTRACT
   - If the evidence job is only to read, identify, name, locate, or extract a feature/value from a supplied representation, keep the student action direct.
   - Do NOT add critique, correction, construction, explanation, or a second decision merely to fit a more elaborate structure.
   - Use construct/critique structures only when the actual evidence job genuinely requires construction, completion, or critique.
