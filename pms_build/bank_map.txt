BUILD BANK MAP — STEP 3A / PROFILE-DRIVEN BANK DESIGN
========================================================

STATUS: CURRENT
STEP: 3a
JOB: bank_map
ROLE: Build one complete executable Unit Bank design map before final Bank question prose is authored.

3a OWNS DESIGN, NOT FINISHED QUESTIONS.

AUTHORITY — HARD
1. current explicit teacher instruction
2. current Curriculum Philosophy
3. current universal Question Structure authority
4. current Course Framework + exact Unit Assessment Plan
5. current Framework-declared Bank course profile + canonical operational maps
6. this PM
7. registered tools/render contracts

Pin the current system/course snapshot once. Do not silently substitute stale uploads or legacy Bank inventories.

QUESTION STRUCTURE — HARD
Every mapped FINISHED QUESTION/TASK must resolve through the current universal Question Structure workflow:
  learning/evidence target -> evidence job -> student action -> structure -> response -> representation -> tool/render route.
A course may explicitly exempt a resource. If the Framework says Warm-Ups are exempt, do not force Warm-Ups through Question Structure.
Seed records are not finished questions; Question Structure applies when a seed becomes an authored question.

PROFILE-DRIVEN INVENTORY — HARD
Do not hard-code Notes pairs, CYU, Warm-Ups, Practice 2/3, Exit A/B/C, or any historical count.
Read the CURRENT Framework Bank profile and map ONLY the destinations it declares canonical Bank inventory.

For Algebra 1 v7.1, the current profile resolves to:
- official Exit evidence/questions;
- secure Summative V1-V6;
- Practice 1;
- WTC;
- useful reusable Seeds when they earn a canonical role.
Extra Practice, CYU, middle practice, Notes Examples/YTIs, and finished Warm-Up questions are downstream-generated and therefore are NOT Bank Map destinations.
Other courses may resolve differently; follow their current profile.

CANONICAL FRAMEWORK MAPS
When the Framework declares an operational evidence/progression map, CONSUME IT; do not recreate its curriculum allocation.
For Algebra:
- curriculum/exit_evidence_map.json owns which Mastery/I-Can evidence jobs appear on each Exit and the reassessment chain;
- curriculum/warmup_progression_map.json is NOT a Bank destination but is a downstream Framework authority.

OUTPUT
Return ONE ZIP: unitN_bank_map.zip
ZIP root: unitN_bank_map/

Required files:
- MAP_MANIFEST.json
- unitN_question_design_map.json
- bank_inventory_map.json
- one destination slice for every canonical destination declared by the course profile
- seed_map.json when seeds are mapped
- MAP_REPORT.txt

Recommended Algebra destination slices:
- exit_map.json
- summative_map.json
- practice1_map.json
- wtc_map.json
- seed_map.json (may contain zero records)

MAP_MANIFEST must list the exact destination slices actually required. Downstream builders consume the manifest; they must not guess fixed filenames from an older architecture.

MAP_MANIFEST ACCEPTANCE — HARD
Top-level status = PASS only when:
- question_design.status = PASS
- qa.status = PASS
- every profile-required canonical destination is mapped
- every mapped record is executable and aligned
- no retired destination has been reintroduced without explicit current authority.

QUESTION-DESIGN MAP
For every exact target/I-Can/evidence job needed by a canonical destination, map:
- design_slot_id
- exact target / goal / I-Can IDs + text
- stage when relevant (Intro / Review / Mastery or course equivalent)
- evidence_job
- student_action
- candidate/selected question_structure_id
- response_mode
- representation_mode + need
- tool/render route
- difficulty intent
- allowed/required/forbidden variation axes
- source_basis
- security role

EXIT — HARD
Follow the Framework Exit map exactly.
For Algebra normal sections:
- 2 new current-Mastery evidence jobs
- 2 fresh parallel reassessment jobs inherited from the previous section carryforward pair.
U1.1 follows its Framework opening exception.
Do not remap Intro/Review into official Exit slots unless the current Framework says to.
Map secure/exposure status and parallel-variation axes. Reassessment must preserve evidence target and usable difficulty; it is not a literal-copy requirement.

SUMMATIVE — HARD
Build the Summative evidence blueprint from current Unit Mastery Goals and the Framework Exit evidence plan.
For Algebra:
1. map V1 first as the anchor secure form;
2. map V2-V4 as parallel forms preserving blueprint/evidence/difficulty;
3. map V5-V6 after V1-V4 as additional secure forms under the same evidence blueprint and comparable rigor.
Do not reduce parallel forms to number-only clones when the structure permits meaningful fresh variation.
Exact item count is evidence/time driven and must be explicitly resolved in the map.

PRACTICE 1 — HARD
Map primary independent practice from the exact section architecture.
For Algebra, Practice 1 must have a TRUE BALANCE of:
- Intro
- Review
- Mastery
Visible stage headings are allowed/preferred by the current course profile.
Equal counts are preferred; if total count requires otherwise, stage counts differ by at most one and no strand is token coverage.
Mastery practice is informed by the Exit evidence map but Practice 1 must not become an Exit clone set.
Exact Practice 1 count is resolved by the map from usable length + coverage needs, not inherited from legacy 24-question forms.

WTC
When canonical, map one coherent section-level multipart routine using the current course profile. Normally 3-5 connected labeled parts, shared stimulus/representation, and at least one real carry-forward/dependency. Keep the role preview/decomposition; do not inflate difficulty to look rigorous.

SEEDS
Map a seed only when it has durable reuse value. A seed may preserve:
- context/situation
- dataset
- graph/diagram idea
- representation pairing
- misconception/error pattern
- source problem idea
- useful mathematical setup
Record what is locked, what may vary, why it is useful, and which later artifacts may use it.
Do not force every seed into a finished question now.

REPRESENTATIONS / TOOLS
Map only representations that serve evidence. Routes must be executable: registered graph tool, canonical asset, semantic HTML table, registered deterministic tool, or explicit student response surface. No decorative visual quota.

GOOD-ENOUGH MAP AUDIT — HARD
Verify at minimum:
[ ] exact Unit Assessment Plan / Mastery Goal identities correct
[ ] current course profile read and canonical Bank inventory resolved
[ ] retired legacy destinations absent unless explicitly current
[ ] every finished-question destination uses current Question Structure unless explicitly exempt
[ ] Framework operational maps consumed exactly where declared
[ ] Exit chain feasible
[ ] Summative V1-V6 blueprint feasible
[ ] Practice 1 Intro/Review/Mastery balance feasible
[ ] WTC/Seed roles correct
[ ] every required representation has an executable route
[ ] security/variation rules explicit
[ ] IDs unique and destination slices reconcile
[ ] question_design.status = PASS
[ ] qa.status = PASS
[ ] MAP_MANIFEST.status = PASS

BUILD ORDER
1. Pin authorities.
2. Resolve current Bank profile + Framework operational maps.
3. Resolve canonical Bank inventory.
4. Build question-design slots.
5. Map Exit evidence from Framework map.
6. Map Summative V1 -> V2-V4 -> V5-V6.
7. Map balanced Practice 1.
8. Map WTC.
9. Map useful Seeds.
10. Reconcile representation/tool/security routes.
11. Audit, report, package, STOP.
