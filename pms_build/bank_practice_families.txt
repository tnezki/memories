DETERMINISTIC CONTRACT PASSES — HARD
------------------------------------

  python3 <system_repo_root>/Tools/qa_bank_3a_contract.py <course_repo_root> --unit N --json-report <course_repo_root>/banks/unitN/provenance/3a_contract_qa.json

A nonzero 3A result blocks entry into 3B. Do not bypass or reinterpret a mechanical failure.

After all 3B files are written, run:

  python3 <system_repo_root>/Tools/qa_bank_3b_contract.py <course_repo_root> --unit N --json-report <course_repo_root>/banks/unitN/provenance/3b_contract_qa.json

A nonzero 3B result blocks 3B PASS. Repair only the reported mechanical contract failures and rerun the SAME validator. Do not change or expand validator criteria during the run.

THE 3B DETERMINISTIC PASS HAS A FROZEN SCOPE:
- every mapped Practice family exists exactly once;
- section counts and family-type mix match the accepted Practice map;
- exact mapped family identity/contract fields are preserved;
- each family has one complete canonical_seed;
- selected-response choices are stored, visible, unique, and keyed;
- required semantic tables use real `<table class="values">` markup;
- canonical asset paths exist and are actually referenced/rendered;
- student-constructed representations contain an explicit response surface;
- equation_relationship seeds contain an actual MathJax render marker;
- registered-tool routes retain a tool key and output reference;
- ITEM_INDEX paths/indexes/modes reconcile with Practice files;
- BANK_MANIFEST stage state and accepted-map fingerprint reconcile.

THE 3B DETERMINISTIC PASS DOES NOT JUDGE:
- Physics correctness;
- whether a prompt semantically fulfills its evidence job;
- whether a distractor is pedagogically strong beyond mechanical completeness/uniqueness;
- whether family variation is interesting enough;
- whether difficulty is ideal;
- instructional quality, novelty, wording preference, or aesthetics.

Those are separate review passes. A deterministic PASS must never be described as semantic/content certification.

If a profile revision changes any contract or slice consumed by the stage being entered, or if explicit compatibility is absent, FAIL CLOSED rather than assuming compatibility.

FAMILY CONTRACT
---------------
Each family contains:
- family_id exactly equal mapped ID
- record_mode = family_seed
- destination = practice
- section
- family_type
- exact primary/supporting I-cans
- evidence_job
- intended_reasoning
- question_structure_id
- response_mode
- representation_mode / representation_need
- question_design object with design_slot_id + tool/render route
- difficulty_intent
- security_level
- selection_tags
- fully authored canonical_seed:
  - student_text / student_html
  - choices when applicable
  - answer
  - solution_text / solution_html
  - figure_refs
- explicit locked/allowed/required/forbidden variation rules
- representation variation rule
- source_map_record_id / source_basis

A seed is a complete classroom-usable question, not a template.

QUESTION STRUCTURE / RENDER EXECUTION — HARD
--------------------------------------------
Every canonical seed must execute its mapped structure, response mode, representation, and tool route.

Selected response:
- complete visible choices;
- keyed correct answer;
- plausible task-specific distractors.

Small data table:
- semantic HTML table;
- `<table class="values">`;
- no pipe-delimited pseudo-table.

Graph:
- resolve/use `graph_tool` when supported;
- inspect actual render.

Diagram/FBD/vector:
- approved source/deterministic route only;
- no crude or physically wrong improvised visual;
- missing approved route -> fail that item.

Representation-required seeds must visibly contain the representation in student_html.

PHYSICS QUALITY
---------------
- concrete physical situations for quantitative work;
- relevant data only;
- physically plausible states/units;
- equations as relationships;
- real representation use, not decorative metadata;
- meaningful semantic variation where required;
- no noun-swap pseudo-variety.

FAMILY FIDELITY
---------------
A downstream sibling preserves:
- exact I-can/evidence job;
- question structure;
- intended reasoning;
- comparable difficulty;
- required representation behavior;
- locked elements.

It satisfies required variation using only allowed axes.
Surface-only name/object changes do not count when deeper variation is required.
