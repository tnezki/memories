================================================================================
PURPOSE
================================================================================

Practice creates learning. Practice Sets turn the rich canonical Bank into clean student-facing work pages.
They should be easy to assign, print, annotate, or skip from without exposing internal Bank metadata.

The Practice builder MUST NOT:
- rewrite canonical Bank questions
- replace values or contexts
- "improve" repeated questions merely because they repeat
- diversify repeated procedural families
- add generic justify/check/reasonableness suffixes
- add new hidden questions to reach a count
- convert open response to selected response unless the current Framework explicitly owns that destination
- leak Bank IDs, DOK, Bloom, I-can routing, source_basis, question_family_id, or internal authoring labels into
  ordinary student Practice pages

Purposeful repetition and useful abundance are allowed. The teacher can skip.

================================================================================
BASE STUDENT HTML CONTRACT
================================================================================

Production pages use external shared CSS only. The universal Practice stylesheet is practice_set.css, bundled
with this Starter and mirrored byte-for-byte in each current course Framework. Resolve the deployed relative path
from the CURRENT Framework path contract. Use the universal Practice classes described here and any course-specific
usage decisions in the Framework; do not invent a second course-specific Practice stylesheet.

Universal page requirements:
- valid HTML5 shell
- MathJax config before the approved CDN when math rendering is needed
- shared base stylesheet first, then the Framework-approved Practice stylesheet
- one clear course/unit/section/resource title
- one visible local question number per canonical item
- one Framework-approved problem wrapper per canonical item
- hidden `data-bank-id` traceability is allowed
- no visible Bank metadata, DOK/Bloom labels, answer panels, evidence panels, or teacher annotations unless the
  current Framework explicitly defines a different student-facing Practice design
- the visible `<h1>` uses the current Framework's short Practice resource name and renders as navy text with
  a THICK 4px horizontal navy rule underneath; do not use a filled title box
- every ordinary Practice problem is enclosed by a 2px navy rounded rectangle (`border-radius: 10px`) around the complete prompt + representation + workspace; do not add a second standalone divider beneath the card
- for any graph, table, diagram, or other representation, render the visible local question number + canonical
  student prompt FIRST, then render the representation beneath the prompt, then the workspace. Do not place an
  unexplained graph/table above the question prompt. This is a rendering-order rule only; canonical Bank content
  remains unchanged.
- follow the Philosophy no-descriptive-caption rule for every student-facing representation; preserve only mathematically necessary labels inside the visual
- REQUIRED DOM ORDER for representation questions: the first visible paragraph inside `.problem-body` MUST contain both the local `.qnum` span and the canonical prompt text. Only after that paragraph may table/figure/diagram nodes appear. A number-only paragraph followed by a representation and then a prompt paragraph is INVALID.
- ordinary two-column data tables use `values compact-table` plus a two-column `colgroup` with `half-col` classes
  so they render compact, centered, and 50/50 rather than full-page width

Generic logical skeleton; replace bracketed wrappers/classes with the CURRENT Framework contract:

<div class="[FRAMEWORK PROBLEM CLASS]" data-bank-id="[BANK_ID]">
  <div class="[FRAMEWORK PROBLEM-BODY CLASS]">
    [VISIBLE LOCAL NUMBER] [CANONICAL STUDENT QUESTION / TASK PROMPT]
    [CANONICAL TABLE / FIGURE / DIAGRAM USING FRAMEWORK CLASSES]
    [FRAMEWORK WORKSPACE ELEMENT + DEFAULT WORKSPACE CLASS]
  </div>
</div>

Visible question numbers are ordinary student numbering, not metadata.

Do not add metadata ribbons, Answer dropdowns, evidence panels, or teacher annotations to student
Practice pages unless the current Framework explicitly changes the design.

================================================================================
FIGURES / TABLES / REPRESENTATIONS
================================================================================

Representations are canonical content, not decoration.

If a Bank question uses a graph, table, diagram, or other representation, the Practice page must include it.
Do not replace a real representation with prose saying what it would show.

STUDENT-FACING RENDER ORDER IS LOCKED:
1. visible local question number + canonical task/prompt
2. canonical graph/table/diagram/figure
3. any remaining coherent multipart task text only when its mathematical meaning requires that location
4. workspace

The Bank remains canonical for content, but Bank storage/DOM order does NOT force student-facing Practice layout.
If the Bank stores a representation before its prompt, the Practice renderer must safely reorder the rendered nodes
so the student sees the task before the representation. Do not alter values, labels, wording, or mathematical meaning.

Priority:
1. Copy the finalized Bank figure bytes exactly.
2. Preserve the canonical Bank table in HTML.
3. If a required canonical Bank figure is missing, report the upstream Bank problem; do NOT regenerate, redesign,
   or substitute the visual inside the Practice renderer.

Use the universal Practice classes and the current Framework usage contract for figures/tables.

Do not emit visible descriptive `<figcaption>` text, figure names, graph titles, source labels, or representation labels beneath a student-facing visual. Mathematical labels that are actual student data
(axes, units, ticks, legends, point labels when required) remain part of the canonical visual.

For ordinary two-column data tables, attach `values compact-table` and a two-column `colgroup` using `half-col`
classes so the universal CSS produces the approved Notes-style compact centered table. Preserve all canonical
cell values and headings exactly.
