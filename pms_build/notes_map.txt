BUILD NOTES MAP — STEP 4A / BANK-V2
====================================

STATUS: CURRENT
ROLE: Build one complete Unit Notes map from the current Course Framework, finalized Bank-v2 Notes anchors, and the Framework-declared instructional source/spine.

4A is MAP / CUT / ROUTE.
It does NOT author final Notes HTML.
It does NOT rewrite the textbook into a new mini-textbook.
It does NOT audit/rebuild the Bank.
It does NOT redesign the established Notes format.

STARTUP — HARD
--------------
Read current Philosophy + Runtime first.
Resolve/pin required repositories once.
Resolve Framework/Notes runtime through manifests.
Fetch exact declared paths directly.
No web/File-Library/prior-ZIP/repository hunting for declared sources.

BANK-V2 INPUT
-------------
Read:
  banks/unitN/BANK_MANIFEST.json
  banks/unitN/ITEM_INDEX.json

Require COMPLETE + ready_for_downstream.


SYSTEM / CONTRACT IDENTITY — HARD
---------------------------------
At the top of NOTES_MAP_REPORT.txt record:
- loaded PM path: `pms_build/notes_map.txt`
- pinned memories commit
- supported Notes-route contract schemas

Supported route contracts:
- `bank-notes-route/1.0` — current producer handshake
- `legacy-paths-notes/1.0` — compatibility bridge for already-finalized Banks that have `paths.notes` but predate the explicit handshake

If `BANK_MANIFEST.downstream_contracts.notes_route` exists:
- require schema = `bank-notes-route/1.0`;
- require route_field = `paths.notes`;
- require route_template = exact `BANK_MANIFEST.paths.notes`;
- record `bank_notes_route_contract_schema = "bank-notes-route/1.0"`.

If the handshake is absent but valid `BANK_MANIFEST.paths.notes` exists:
- do NOT reject an already-finalized legacy Bank;
- record `bank_notes_route_contract_schema = "legacy-paths-notes/1.0"`;
- state in the report that the producer is legacy-compatible.

FAILURE CLASSIFICATION — HARD
-----------------------------
When failing before mapping, classify the failure:

SYSTEM_CONTRACT_MISMATCH
- Bank declares a Notes-route schema this PM does not support, or producer/consumer contract versions conflict.
- Report the loaded PM path, pinned memories commit, Bank-declared schema, and supported schema(s).
- Tell the teacher to sync/update the system repo and rerun.
- Do NOT describe the Bank itself as defective unless its own declared contract is internally inconsistent.

BANK_INPUT_DEFECT
- Bank claims a supported contract but required route/path/files are missing or internally inconsistent.

SOURCE_INPUT_DEFECT
- Declared Framework/textbook/source input is missing or non-resolving.

Never collapse these into a generic "missing field" message.


Resolve the canonical Notes section route ONLY from:
  BANK_MANIFEST.paths.notes

Current Bank-v2 route shape:
  notes/section_<section-id>.json

HARD ROUTING RULES:
- `paths.notes` is the final Bank -> Notes handoff contract.
- Do NOT require or infer `canonical_artifacts.notes`; the finalized Bank-v2 manifest does not use that field as the Notes routing authority.
- Expand the declared `paths.notes` pattern only with the exact current Framework section IDs for the Unit.
- Every resolved Notes section file must exist.
- Use ITEM_INDEX only to confirm that the WTC / EXAMPLE / YTI Bank anchors routed through those files resolve to the same concrete Notes section paths.
- Read ONLY those resolved Notes section files for Bank-owned Notes anchors.
- Missing, ambiguous, or non-resolving `paths.notes` -> FAIL CLOSED. Do not search the repository for substitutes.

Record:
- Bank manifest path/blob identity;
- Bank `paths.notes` route template exactly as declared;
- exact resolved Notes section paths/blob identities;
- accepted Notes-map slice hash when present.

No Stage-3E fingerprinting.
No prior Bank ZIPs.

SOURCE-SPINE RULE — HARD
------------------------
For current Physics, the Framework-declared Physics textbook is the instructional spine.

The close-reading content is SELECTED FROM THAT SOURCE.
Do not invent a replacement close-reading passage when usable source text exists.

For each target section:
1. resolve exact title/LT/I-cans;
2. read the matching textbook section;
3. preserve useful conceptual order;
4. map source blocks KEEP / CONDENSE / DROP;
5. cut by omission first;
6. allow light paraphrase/condensation where needed;
7. retain useful source figures at their natural concept locations;
8. route Bank anchors and instructional processing around the retained source;
9. map the close.

SOURCE FIDELITY
---------------
KEEP:
- preserve the source idea/order and recognizable explanation;
- 4B trims mainly by omission/light editing.

CONDENSE:
- preserve the conceptual sequence;
- remove repeated examples/details/tangents;
- light paraphrase allowed for clarity/length.

DROP:
- outside current target;
- redundant;
- navigation/media/answer clutter;
- tangent that damages lesson flow.

For each retained chunk record:
- flow_id
- source_file
- source heading/span
- action = KEEP|CONDENSE
- text_fidelity = CLOSE|LIGHT_CONDENSE|STRONG_CONDENSE
- transition heading target
- purpose
- i_can_ids
- retained_images
- estimated pacing

Do not write final reading prose in 4A.

OPENING — CURRENT PHYSICS CONTRACT
----------------------------------
Map exactly:
1. section title / LT / I-cans;
2. Vocabulary Preview;
3. canonical WTC;
4. Let's Get Started skim;
5. ONE Close Reading directions block;
6. retained close-reading flow.

Physics skim prompt:
  "Skim before close reading. Look at the headings and figures. Find 1–2 things you notice and 1–2 things you wonder about."

Do not add a prediction row unless current Framework explicitly requires it.
Do not map repeated Close Reading direction boxes.

READING BOUNDARY RHYTHM — HARD
-------------------------------
Each reading boundary may have at most ONE PRIMARY STUDENT-PROCESSING EVENT:
- stop_discuss
- ex_yti
- none

Do NOT map Stop & Discuss and Example/YTI after the same reading chunk.

Instructional insertions may coexist with reading:
- Physics Note
- diagram
- graph
- model
- other explanatory/reference representation

Those are instructional supports, not a second mandatory student-processing event.

EXAMPLE / YTI ROUTING
---------------------
Use every complete canonical pair exactly once.
Preserve hidden Bank IDs/pair IDs.

Assign `display_pair_number` from final Notes display order:
1, 2, 3...

Visible numbering is NOT the Bank pair_number.

Place a pair after a reading chunk only when it naturally processes that concept.
If natural insertion points run out:
  place remaining intact pairs in `post_reading_ex_yti_queue`
after the final reading chunk, continuing the visible numbering.

WTC
---
Route exact canonical Bank WTC.
Do not rewrite it in 4A.
Preserve its representation and coverage_role.

STOP & DISCUSS
--------------
Map only when a reading/representation genuinely benefits from verbal conceptual processing and that boundary is not occupied by EX/YTI.

Record:
- after_flow_id
- i_can_ids
- discussion_job
- concise prompt skeletons
- source representation IDs when relevant
- evidence/listen-for

No stock comprehension prompts.

PHYSICS NOTES / REPRESENTATIONS
-------------------------------
Map a Physics Note or explanatory diagram/model only when it improves the retained source explanation.

Prefer:
1. retained textbook/source figure;
2. canonical Bank representation;
3. mapped Physics Notes Image Toolkit asset;
4. generated Notes-specific representation only when none of the above satisfies the need.

Toolkit assets are reference-in-place.
Do not copy them into Notes section folders.

CLOSE — HARD
------------
Map:
1. Vocabulary with concise definitions;
2. bulleted Summary;
3. What I Figured Out;
4. Common Mistakes;
5. Framework-defined final miscellaneous workspace when required.

Do not omit What I Figured Out.
Do not add a Notes Exit Check.
