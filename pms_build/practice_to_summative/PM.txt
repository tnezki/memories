SELECTED-RESPONSE CHOICE SCRAMBLE — FINAL CONTENT MUTATION / HARD
------------------------------------------------------------------
For any active Summative profile that contains selected-response items, run the bundled deterministic tool on a TEMPORARY staging copy of the finalized Bank data after all question/distractor content is final and immediately before Summative rendering/final-byte QA/ZIP:

  python3 Tools/scramble_selected_response.py <STAGED_UNIT_BANK_DATA.json> --in-place --seed "<course>|unit<U>|practice-to-summative-v1" --report <STAGING>/summative_choice_scramble_report.json [--strict-16x4]

Rules:
- NEVER run the tool against the deployed/canonical Bank. Use a staging copy only.
- The tool may reorder choices and update the displayed correct letter; it may not rewrite choice content, prompt content, evidence, figures, or I-can metadata.
- For current Physics 16-selected-response / 4-choice forms, use `--strict-16x4`; every form must finish exactly 4 A / 4 B / 4 C / 4 D.

- The renderer must consume the scrambled staging data, never the unsorted source data.
- No later build step may reorder selected-response choices. MathJax/final-byte repair, shell QA, rendering, and packaging may follow, but choice order is locked after this tool runs.
- `summative_choice_scramble_report.json` is build-time QA evidence; it is not a required student-facing deployed file.
- If the tool reports malformed/ambiguous correct-answer metadata, mixed choice counts in a form, or distribution failure, FAIL CLOSED.
- Current canonical detection does NOT require `item_type`: a Summative item with non-empty `choices` and `question_design.response_mode = selected_response` is selected response. Legacy `item_type` remains accepted.
- Under `--strict-16x4`, if Summative records with choices exist but none (or only some) are recognized as selected response, FAIL CLOSED. `PASS_NOOP` is forbidden for that mismatch condition.
- If a course Summative truly has no selected-response items, the tool may return PASS_NOOP.

SUMMATIVE LAYOUT - WORKSPACE-FIRST, NOT DEFAULT-FIRST
------------------------------------------------------
The secure Bank owns the questions. The renderer owns usable printed workspace.

For math-style Summatives using `summative_math.css`:
- every question gets exactly one of:
    q-compact / q-standard / q-large / q-xlarge
- NEVER assign `q-standard` merely because no decision was made;
- size is a WORKSPACE decision, not a DOK/difficulty label.

Use this decision process for EACH instantiated question:

Q-COMPACT
- short direct calculation / identification / brief response;
- no substantial graph/table construction;
- expected student work fits comfortably in a small card.

Q-STANDARD
- moderate computation or short explanation;
- a few written steps;
- small representation/table that still leaves reasonable work space.

Q-LARGE
- multi-step solution, modeling, interpretation, critique, justification;
- student-generated graph/table work;
- content-bearing figure plus meaningful written reasoning;
- response clearly needs more room than standard.

Q-XLARGE
- genuinely extended response or unusually large representation/work area;
- use only when page composition can support it and the response really needs it.

FORM-LEVEL LAYOUT PASS - REQUIRED:
1. Classify each question by expected response footprint.
2. Lay out the form using the current Framework's exact item count.
3. Give each page enough writing space without shrinking text/figures.
4. Rebalance page breaks and size classes when necessary.
5. Do not change question content merely to make the page fit.
6. Render/open enough pages to verify actual print usability.

DETERMINISTIC FIRST-PASS SIZING — REQUIRED:
- Start from the expected student response, not from `q-standard`.
- Short direct algebra/evaluation items remain `q-compact` even when they ask for one
  brief check, property, or sentence of support. Examples: evaluate a rule and say why
  it is a function; solve one short equation and give one check; rewrite an expression
  and name the property; decide equivalence with one substitution/structure check.
- Moderate contextual equations, multi-step computation, or short analytical responses
  normally start `q-standard`.
- Use `q-large` when the RESPONSE FOOTPRINT is clearly larger: a content-bearing graph/table
  that must be analyzed and explained; writing an equation from a representation with
  evidence; creating a representation plus context/explanation; evaluating a claim with
  evidence; or a contextual solution that also requires substantial verification.
- `q-xlarge` is reserved for genuinely extended multi-part reasoning or unusually large
  student-generated representation + written justification. It should be rare.
- Reasoning verbs by themselves do NOT automatically force `q-large`; estimate the actual
  amount of handwriting the student needs.
- After the first pass, page composition may increase a class when needed. If an obvious
  compact item is intentionally enlarged, add a hidden `data-workspace-override` reason so
  the choice is auditable rather than accidental.

For an 8-item math form, a tested 3 + 3 + 2 page sequence is acceptable when it
fits the current Framework/profile. Do not force an obsolete 10-question template.
The exact form item count always comes from the current secure Bank + Framework.

SUMMATIVE DOM GATES:
- image figures: `<figure class="figure-block">` + `<img class="question-graph">`
- ordinary data tables: `data-table` or the Framework-approved styled equivalent
- prompt precedes representation
- no descriptive student-facing figcaption
- no visible DOK / Bank ID / Mastery Goal labels
- active forms only; no stale version selectors
- preserve exact secure Bank membership and figures.
