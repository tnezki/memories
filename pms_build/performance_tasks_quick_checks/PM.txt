MAP-FIRST REPETITION DISCIPLINE — UNIVERSAL
------------------------------------------
The complete evidence map is also the first defense against BAD repetition. Before authoring final student materials, read the full requested-scope map and ask whether repeated question shells, experience sequences, representation choices, reasoning suffixes, or student actions are repeated for a real learning/evidence reason or merely because the renderer/template made them convenient.

Purposeful repetition is allowed and often desirable: fluency, retrieval, repeated independent evidence, consistent comparison, repeated use of a high-value representation, or deliberate return to an important structure. Do not use anti-repetition quotas. If a repeated structure has a real mapped purpose, keep it. If it is only a template byproduct, revise the PLAN before authoring.

This is a PRE-AUTHORING design gate, not permission for a late anti-clone/diversification pass. The goal is intentionality, not maximum variety.

RESOURCE PURPOSE
----------------
QUICK CHECK
- A compact, independent evidence resource that gives a deeper/bigger picture than an Exit Ticket.
- Quiz-like in evidence purpose, not extra Practice.
- Exact I-can alignment comes first.
- The course Framework owns timing, page, response-mode, representation, and portfolio/collection conventions.
- It should contain enough connected evidence to judge what a student currently understands without becoming a full Summative.

PERFORMANCE TASK
- A richer coherent evidence route in which students use knowledge across connected steps/actions to model, create, analyze, test, critique, revise, decide, design, or defend something meaningful.
- Exact I-can/evidence alignment comes first.
- The course Framework may assign Performance Tasks a special role for deeper DOK 3/4 evidence, laboratory/modeling evidence, extended justification, design, or other discipline-specific performance.
- DOK is descriptive after task design; it is not a proficiency tier and should not be faked with generic justification language.
- One coherent performance is preferable to a bundle of unrelated quiz questions.

EVIDENCE-MAP-FIRST GATE — REQUIRED BEFORE HTML
----------------------------------------------
For every multi-section or all-course build, map BOTH resource families for the complete requested scope before writing any student or teacher HTML. This is a hard gate. Do not render early sections while later sections are still unmapped.

PHASE 1A — EXACT I-CAN MAP
For every section, extract the exact current Assessment Plan I-can statements and relevant evidence intent. Do not paraphrase them into generic chapter objectives when exact wording exists.

PHASE 1B — QUICK CHECK EVIDENCE MAP
For every section, record at minimum:
- section ID/title
- exact I-can statements
- which I-cans the Quick Check will actually evidence
- evidence opportunity/question -> I-can mapping
- what independent student evidence should make the I-can judgeable
- expected time/page scope from the Framework
- representations/figures/data used or constructed
- graph/figure/tool decision when relevant
- why THIS SECTION'S planned check provides a deeper/bigger evidence picture than an Exit Ticket
- when the Framework requires multiple parallel versions: one canonical evidence blueprint plus a version-by-version variation/permutation plan showing how every form preserves the same mapped evidence while changing permitted values/context/representation details and question order

The last rationale must be section-specific enough to reveal actual thinking. Repeating one stock sentence across most or all sections is a PLAN FAILURE even though the map is not student-facing.

PHASE 1C — PERFORMANCE TASK EVIDENCE + ACTION MAP
For every section, record at minimum:
- section ID/title
- exact I-can statements
- which I-cans the Performance Task will actually evidence
- evidence claim(s) the teacher should be able to make from the student work
- intended DOK after the task concept is designed
- coherent situation/problem/design/model
- PERFORMANCE ACTION: what students actually DO
- student action sequence
- individual vs shared/group/setup components
- student artifact/output
- representations students read/build/use/compare/translate
- graph/figure/data/tool decision
- materials/technology needs
- evidence to look/listen for
- why this action fits the mapped I-cans

The Framework supplies course-specific action libraries/examples. Use them as a thinking menu, not a rotation quota. Stable CSS is NOT a reason to repeat the same student action across the course.

PHASE 1D — WHOLE-SCOPE QA BEFORE RENDERING
Read the maps as a course/body of evidence. Repair the MAP before HTML when you find:
- an exact I-can accidentally receiving little/no planned evidence;
- the same easy I-can receiving nearly all opportunities while another is ignored;
- a supposed Performance Task that is really unrelated questions;
- claimed DOK 4 that does not actually require extended analysis/synthesis/modeling/decision/revision/defense;
- representation-heavy evidence planned as text-only without a reason;
- one performance action repeated everywhere because it is easy to render;
- an action label whose required verbs are absent from the actual student sequence (for example CREATE/TRADE with no exchange/reconstruction, MOVE with no movement, COLLECT with no data collection, or BUILD with nothing constructed);
- stock map rationales repeated across most/all sections instead of section-specific evidence reasoning;
- a Quick Check that has become either an Exit Ticket pulse or a mini-Summative.

The goal is intentional coverage, not equal quotas. Teacher professional judgment remains final.

AUTHORING FROM THE MAP
----------------------
After both maps pass QA, author resources from the mapped evidence/action design. Do not let the visual shell rewrite the plan.

For Quick Checks:
- preserve independent evidence;
- keep prompts specific to the I-can;
- use real representations when representation reasoning is claimed;
- do not add generic “explain your reasoning” suffixes to every question;
- provide enough workspace for the actual response mode and honor the Framework's exact approved workspace geometry;
- when multiple parallel versions are required, author ALL versions from the same mapped evidence blueprint; keep I-can coverage, time, response mode, and approximate difficulty parallel while changing permitted values/context/representation details and applying the planned question-order permutation;
- when the Framework requires multiple forms inside ONE HTML file, render every complete form inside that single section HTML rather than creating separate version files. Each form remains a complete printable Quick Check, with its own header/evidence block/questions/footer and a clear version identifier. Put a hard print page break BETWEEN forms so Version 2 never begins on the last page of Version 1;
- renumber questions after scrambling; do not let the same I-can silently disappear from one version;
- never display internal generator labels, answer keys, DOK badges, or proficiency labels on the student resource unless the Framework explicitly requires them.

For Performance Tasks:
- make the planned action real. COLLECT means students collect/record; BUILD means they make/construct; MOVE means the physical action/setup is present; AUDIT/REPAIR means there is a real inconsistency to locate and repair; CREATE/TRADE means the exchange/reconstruction mechanism is present; MODEL means students build/use/evaluate a model rather than merely answer context questions.
- preserve one coherent through-line across the task.
- allow shared setup/data collection/partner exchange when the Framework permits it, but preserve interpretable individual evidence when independence matters.
- render FROM the mapped action sequence. Stable CSS does not authorize a fixed page/card choreography.
- do not force a universal page count, a universal number of task cards, a universal “Situation / Starting Evidence” heading, or a universal “Part 1/Part 2/Part 3” intellectual sequence.
- in a large build, an output where every/near-every Performance Task has the same page count and same card count is a RENDER-FIDELITY WARNING and normally a failure unless the map truly calls for that structure.

REPRESENTATIONS / FIGURES / DATA
--------------------------------
Representations are evidence content, not decoration. Students must actually read, build, use, compare, translate, annotate, interpret, or evaluate them.

Use the Framework's authoritative graph/figure/data tool whenever a supported representation cleanly serves the intended evidence. Performance Tasks and Quick Checks are authoring resources, so they MAY generate new supported visuals unless the Framework says otherwise. When student construction of the graph/model is itself the evidence, provide the appropriate blank scaffold instead of pre-solving it.

Representation promises must be literal. If the prompt says a grid/table/diagram/data display is provided, that object must exist in the HTML/assets. If a planned representation is central to the evidence but students must construct it themselves, provide enough scaffold/workspace to make that construction practical rather than merely naming the representation in prose.

MATHJAX / MATHEMATICAL TYPESETTING — HARD REQUIREMENT
------------------------------------------------------
Loading a MathJax script is not sufficient. Every visible mathematical expression that relies on TeX syntax must be INSIDE MathJax delimiters so the browser actually renders it. Do not emit raw student-facing text such as `x^2+7x+12`, `A(w)=200+20w^2`, `b^2-4ac`, `x_1`, `\frac{...}{...}`, or `\sqrt{...}` outside math delimiters.

Use this EXACT proven MathJax boilerplate in Performance Task and Quick Check HTML that contains mathematics. Do not invent or simplify a different configuration:

<script>
window.MathJax = {
  tex: {
    inlineMath: [['$','$']],
    displayMath: [['$$','$$']],
    processEscapes: true
  }
};
</script>
<script async src="https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js"></script>

IMPORTANT: PT/QC uses the established course-wide dollar-delimiter contract: `$...$` for inline math and `$$...$$` for display math. `inlineMath` must enable only `$`/`$`; `displayMath` must enable only `$$`/`$$`; `processEscapes: true`. This matches the Framework finalizer and MathJax repair tool. Do not invent a second PT/QC-only delimiter system.

Author ordinary inline mathematics with `$...$` and display mathematics with `$$...$$` so authored content matches the established MathJax configuration, Framework finalizer, and `~fix_mathjax` repair workflow. Escape literal currency dollar signs as `\$` in HTML source (for example `\$24`) so currency cannot open an accidental math span. Teacher-guide inserted answers must follow the same rule.

Before delivery, inspect visible HTML text for raw caret/subscript/TeX commands outside delimiters AND inspect the `<head>` to confirm the exact MathJax boilerplate above. A page that includes MathJax but visibly shows `x^2` instead of a superscript has FAILED final-byte QA.

UNIVERSAL STUDENT-FACING CAPTION RULE
-------------------------------------
No descriptive captions/titles/source labels beneath student-facing graphs, tables, diagrams, images, or other figures. The prompt introduces the representation; the visual stands alone. Preserve only mathematically/scientifically necessary labels inside the representation.


PERFORMANCE-TASK DISCOURSE LAYER
--------------------------------
Performance Tasks may include purposeful teacher-facilitated discussion during learning or
sense-making phases. Quick Checks remain independent evidence and do NOT receive discourse
coaching.

For each MAJOR discussion-worthy Performance Task phase in the TEACHER guide, include:

  Discourse Moves
  Teacher Moves — 2–4 short bullets
  Student Moves — 2–4 short bullets

Tailor the bullets to the phase's exact evidence, representation, model, or misconception.
Use teacher moves such as wait, invite multiple strategies, revoice, ask students to restate,
probe evidence, compare approaches, and connect representations. Use student moves such as
explain, clarify, restate, compare, support, build on, and challenge.

Do NOT force discourse into every independent-response workspace. If teacher discussion would
contaminate the intended evidence, omit the block.

Do NOT add discourse support to Quick Checks or student Performance Task files.
