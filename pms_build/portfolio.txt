===========================================================
2. RUN MODES
===========================================================
A request may contain one or more operations in the same run.


A. EVIDENCE UPDATE
- One or more student evidence files are supplied.
- Preserve raw evidence, judge/update evidence state and grades, and refresh reports/PowerSchool exports.


B. ROSTER UPDATE
- Runs only when roster_update_requested=true.
- A current PowerSchool roster/template CSV is explicitly supplied.
- Compare supplied roster to stored registry before applying changes.
- Student Num is the durable identity key when present.
- Added students become active. Students absent from the new roster become inactive; never delete historical evidence.
- Exact existing student numbers reconnect to prior history, including returning students.
- Name changes on the same student number update current display name without creating a new student.
- Ambiguous/duplicate/malformed identity rows go to review_queue.csv; do not guess.
- A normal evidence run with roster_update_requested=false reuses the stored roster and requires NO roster upload.


C. STUDENT SUPPORT UPDATE
- Runs when one or more files are explicitly classified as student_support_files.
- Accepted examples include IEP, 504, accommodation plan, case-manager accommodation summary, or another teacher-authorized support document.
- These are private support/setup sources, never student evidence.
- Preserve each source unchanged under 02 Portfolio Data/Student Support/Source Files with SHA-256/import timestamp.
- Match to current registry using exact Student Num when available, otherwise unique exact normalized student name; unresolved identity goes to student_support_review.csv. Never fuzzy-guess.
- Extract only classroom/assessment information needed to apply the student's documented support accurately. Do NOT normalize diagnoses, medical history, family details, disability narrative, or unrelated sensitive content.
- student_support_current.csv contains only actionable accommodation/modification fields such as student_key, source hash/date, accommodation/modification label, concise operational description, applies_to, and review/expiration metadata when explicitly present.
- Support-recipient routing is maintained separately in the global `00 Contact Directory/student_support_contacts_current.csv` file, not inside a Unit Student Support folder. If a supplied IEP/504/support source explicitly identifies a staff relationship and the teacher requests routing maintenance, it may be proposed for that file, but the seven-column course-agnostic schema remains authoritative.
- Never invent or infer a staff email from a name. Rows with missing/invalid staff email or inactive routing are not eligible email recipients.
- Approved accommodations do not lower the learning standard or evidence status of a valid demonstration.
- A support-only run may occur with no new student evidence and must not alter evidence_ledger.csv, I Can status, Mastery Goal grades, or PowerSchool grades.


D. REPORT REFRESH
- Evidence updates refresh reports automatically.
- Roster/support-only runs refresh reports only when refresh_reports_requested=true.
- Report refresh reads the updated current Portfolio state but does not manufacture new evidence or alter grades solely because reports were requested.
- A report refresh returns HTML/CSV results in one downloadable ZIP; it does not write generated artifacts to Drive folders 03-05.

===========================================================
8. INTERVENTION ROUTING - LOCKED THREE-LANE MODEL
===========================================================
The teacher report is an intervention-planning tool. Translate longitudinal evidence into exactly three teacher lanes.


WHOLE CLASS
- Use only when current evidence supports a genuinely broad shared instructional need suitable for normal class time.
- Select at most ONE highest-leverage whole-class target for the normal report.
- Do not recommend whole-class reteach from No Evidence or raw frequency alone. The evidence notes/pattern must support a coherent shared instructional response.
- Persist/report exact target, affected PRACTICE_AND_CHECK count, recurring evidence pattern/misconception, and concise teacher move.
- If evidence does not support classwide intervention, state no whole-class intervention is recommended and omit the separate Whole Class page.


PRIORITY DAY GROUPS
Priority Day represents one limited weekly Crewtime intervention opportunity.


ELIGIBILITY
A student is eligible when ALL are true:
- active=true;
- at least one current assessed Mastery Goal has grade_code=I;
- at least one current I Can is PRACTICE_AND_CHECK.


Do NOT consume a Priority Day seat for a student whose only current next steps are NEEDS_FIRST_CHECK and/or NEEDS_ANOTHER_DEMONSTRATION.


RANKING - HARD
For eligible students calculate:
1. i_grade_count = number of current assessed Mastery Goals with grade_code=I.
2. practice_gap_count = number of current PRACTICE_AND_CHECK I Cans.
3. practice evidence severity using current/latest evidence on those targets: UNUSABLE before LIMITED before PARTIAL before stronger evidence.


Sort by:
- i_grade_count descending;
- practice_gap_count descending;
- evidence severity descending by need;
- stable student_key only as final deterministic tie-break.


If only one MG has been assessed, many students may tie on i_grade_count. In that case practice_gap_count and evidence severity determine the order.


CAPACITY - HARD
- Group 1 = ranks 1-15.
- Group 2 = ranks 16-30.
- Maximum 2 groups.
- Maximum 15 students per group.
- Never create Group 3.
- If more than 30 eligible students exist, show only a compact remaining-count note after Group 2; do not add another page of names.


GROUP PLAN
Exact shared I Can bundles are NOT required. For each selected group:
- show each student's current PRACTICE_AND_CHECK I Can codes;
- count how many selected students need each target;
- identify dominant overlapping target(s) and recurring evidence patterns;
- synthesize the best common 20-minute Crewtime intervention, not separate mini-lessons for every I Can;
- use a short alternate practice strip only when a few students have a different small target;
- include an independent check at the end so repaired gaps can move out of PRACTICE_AND_CHECK on the next run.


PULL IN STUDENTS
- Eligible when active and current PRACTICE_AND_CHECK count is exactly 1 or 2.
- Student-centered, not I-Can-centered.
- Show exact 1-2 I Can targets per student.
- Everyone on this page has the same action: Practice + check soon. State that once in the page banner; do not repeat PLAN on every student card.
- Keep ALL current Pull In students on ONE landscape page using a compact 3-column grid, or 4 columns when needed.
- Students who only need another independent demonstration are intentionally excluded.
- Priority Day and Pull In are scheduling views, not mutually exclusive. A student may appear in both.


Never use `Brief guided practice` as a current teacher-report lane or heading.
