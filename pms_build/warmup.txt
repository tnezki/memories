========================================================
3. DAILY ALGEBRA ARCHITECTURE — EXACTLY FOUR STABLE JOBS
========================================================

Every daily Algebra Warm-Up contains:

Q1 · SOLVE / EQUATION FLUENCY
Q2 · DIAMOND / FACTORING PATTERN
Q3 · SKILL REVIEW
Q4 · CHALLENGE

These identities remain stable for the entire course.

Do NOT label Warm-Up questions:
- Intro
- Review
- Mastery

Warm-Ups are not official evidence events.

========================================================
4. Q1 — SOLVE / EQUATION FLUENCY
========================================================

Follow the exact current section row and Unit solve ceiling from the progression map.

DEFAULT:
- 2 equations

ALLOW:
- 3 equations only when all are very short one-step retrieval
- 1 equation when the current method is substantially longer

Across a normal three-day section:
- introduce newly permitted work gradually;
- keep earlier equation types alive;
- do not make all three days the newest solve type;
- do not inflate coefficients as fake difficulty;
- prefer clean values that keep attention on algebraic structure.

FRACTION / INTEGER CALCULATOR LANGUAGE
--------------------------------------
When fraction/integer fluency is present, include brief language that encourages:
  "Try without a calculator first. Use a calculator if you need one."

Equivalent concise wording is allowed.

The tone must:
- encourage mental/manual fluency;
- clearly allow calculator use when needed;
- never make calculator use sound prohibited or shameful.

========================================================
5. Q2 — DIAMOND / FACTORING PATTERN
========================================================

Normally one job per day.

Follow the exact progression map timing:
- numeric product/sum
- signed factor pairs
- missing-cell variations
- symbolic factoring patterns
- factoring maintenance

Do not jump to symbolic factoring before the map permits it.

Vary which values/cells are known when useful.
Use natural, readable values.

If the established diamond graphic is needed, use the current project figure/render route.
Do not invent a new visual language during the Unit build.

========================================================
6. Q3 — SKILL REVIEW
========================================================

Follow the exact section prerequisite/review purpose from the progression map.

Normally:
- one short job

Allow:
- a 2–3 item mini-set only when all items serve one coherent narrow fluency purpose.

Q3 is:
- intentional prerequisite runway;
- retrieval of useful prior mathematics;
- sometimes a small prerequisite preview.

Q3 is NOT:
- random spiral review;
- a second lesson on unreached content;
- copied current Practice/Activity work.

========================================================
7. Q4 — CHALLENGE
========================================================

One short reasoning/nonroutine job per day.

Challenge should be:
- accessible enough that every student can begin;
- worth discussing;
- concise enough for a Warm-Up;
- reasoning-focused rather than arithmetic-heavy.

Useful forms include:
- pattern
- explain
- compare
- error analysis
- representation
- generalize
- model
- critique
- "always / sometimes / never"
- find an example / counterexample

Across the three days, vary the type of thinking when useful.

Do not turn Q4 into:
- a long project;
- a mini performance task;
- merely harder arithmetic;
- a hidden current-section test.

========================================================
8. THREE-DAY SECTION RHYTHM
========================================================

Default = 3 days per section unless current teacher/calendar instruction says otherwise.

Planning tendency:

DAY 1
- clean entry / retrieval
- establish current row fluency

DAY 2
- emphasize the new or expanding fluency permitted by the row

DAY 3
- mix and strengthen the row
- keep earlier fluency alive

This is NOT three separate stages.
Do not visibly label Day 1 / Day 2 / Day 3 as Intro/Review/Mastery.

If a section row contains no newly introduced solve/factoring type, all three days may be cumulative
maintenance with useful variation.

========================================================

Follow:
  Tools/QUESTION_FRESHNESS_CONTRACT.txt

WARM-UP-SPECIFIC INTERPRETATION
-------------------------------
EXPECTED / ALLOWED:
- same four daily jobs
- same equation type
- same diamond structure
- same prerequisite skill
- same challenge family
- deliberate short fluency runs
- fresh values/instances of familiar routines

FAIL / REPAIR:
- exact repeated finished question inside the new Unit build
- same distinctive values/data + same prompt
- same exact table/graph/context used as the same task
- exact student-facing prompt copied from Notes/Practice/CYU/Activities/Exit

For Warm-Ups, a fresh value-set parallel may be pedagogically appropriate.
Do not over-repair useful routine repetition.

Compare newly authored Warm-Ups against:
1. other Warm-Ups in the same new Unit build
2. current Notes student prompts for the same Unit
3. current Practice / Extra Practice / CYU
4. current Activities question sets
5. current public Exit questions when present

Comparison artifacts are freshness-only.
They are not curriculum authorities or question sources.

11. FOUR-UP SCREEN VIEWER — REQUIRED
========================================================

Also create:

  warmups/unit_{U}_warmups/unit_{U}_warmups_view.html

PURPOSE
-------
A fast screen-only way to inspect the entire Unit's Warm-Ups without scrolling through
large handwriting workspaces.

The viewer REUSES the exact same authored Warm-Up questions.
It creates ZERO new question instances.

LAYOUT — HARD
-------------
Model the compact structure after the Bank viewer's four-column idea.

For EACH section/day:
- one day header;
- directly below it, ONE ROW of FOUR question cards:
  Q1 | Q2 | Q3 | Q4

Desktop:
  grid-template-columns: repeat(4, minmax(0, 1fr))

Responsive:
- 2 columns on medium screens
- 1 column on narrow screens

Each card shows:
- job label
- exact question content
- actual table/graph/diamond/representation when used

Viewer does NOT show:
- student workspace
- blank writing lines
- answers
- solutions
- internal IDs
- provenance metadata

VIEWER NAVIGATION
-----------------
Main Notability file must include a visible link:
  "4-Up Viewer"

The 4-Up Viewer must include a visible return link:
  "Notability View"

Use relative local links only.

The link should be easy to find but visually small enough that it does not disrupt the tested
Notability layout.

VIEWER STYLE
------------
Use base.css plus compact viewer-specific CSS.
Do NOT stretch warmup.css's handwriting card heights into the viewer.
The viewer is screen-first and compact.
