========================================================
3. DAILY ALGEBRA ARCHITECTURE — EXACTLY FOUR JOBS
========================================================

Every daily Warm-Up contains:

Q1 · SOLVE / EQUATION FLUENCY
Q2 · DIAMOND / FACTORING PATTERN
Q3 · SKILL REVIEW
Q4 · CHALLENGE

Do NOT label Warm-Ups Intro / Review / Mastery.
Warm-Ups are not official evidence events.

========================================================
4. Q1 — SOLVE / EQUATION FLUENCY
========================================================

Follow the exact current section row and Unit solve ceiling.

Default:
- 2 equations

Allow:
- 3 only when all are very short one-step retrieval;
- 1 when the current method is substantially longer.

Across three days:
- introduce newly permitted work gradually;
- keep earlier equation types alive;
- do not make all work the newest type;
- do not inflate coefficients as fake difficulty.

FRACTION / INTEGER CALCULATOR LANGUAGE
--------------------------------------
When fraction/integer fluency is present, include concise language such as:

  Try without a calculator first. Use a calculator if you need one.

The tone encourages mental/manual fluency while explicitly allowing calculator use.

========================================================
5. Q2 — DIAMOND / FACTORING PATTERN — GRAPH TOOL REQUIRED
========================================================

Normally one job per day.

Follow exact mapped progression:
- numeric product/sum
- signed factor pairs
- missing-cell variations
- symbolic factoring patterns
- factoring maintenance

HARD VISUAL RULE
----------------
Every visual diamond problem MUST be generated by the CURRENT REGISTERED GRAPH TOOL.

Current registered entrypoint is resolved from:
  Tools/MANIFEST.json

The currently registered v13 entrypoint re-exports the v12 public surface.
The diamond helper is:
  make_diamond(top, left, right, bottom, filename=...)

When using v13, stage its required v12 behavior base beside it or otherwise resolve it exactly
as the registered tool requires.

DO NOT:
- hand-draw diamonds in SVG;
- build diamonds with CSS borders/transforms;
- use ad hoc HTML shapes;
- create a replacement diamond renderer;
- paste an old diamond image when fresh values are required.

For each diamond:
- pass the intended visible top/left/right/bottom values to make_diamond;
- use '' for intentionally blank cells;
- save to the current Warm-Up figures folder;
- reuse the SAME generated figure in Notability view and 4-Up Viewer.

If the graph tool cannot be resolved or make_diamond is unavailable:
STOP with:
  GRAPH_TOOL_DIAMOND_UNAVAILABLE

========================================================
6. Q3 — SKILL REVIEW
========================================================

Follow the exact section prerequisite/review purpose from the progression map.

Normally one short job.
A 2–3 item mini-set is allowed only when all items serve one coherent narrow fluency purpose.

Q3 is intentional prerequisite runway, not random review and not a second lesson on unreached content.

========================================================
7. Q4 — CHALLENGE
========================================================

One short reasoning/nonroutine job per day.

Useful forms:
- pattern
- explain
- compare
- error analysis
- representation
- generalize
- model
- critique
- always/sometimes/never
- example/counterexample

Challenge means thinking, not uglier arithmetic.

========================================================
8. THREE-DAY SECTION RHYTHM
========================================================

Default = 3 days per section unless current teacher/calendar instruction says otherwise.

Day 1: clean entry/retrieval
Day 2: emphasize new or expanding mapped fluency
Day 3: mix/strengthen and keep earlier fluency alive

This is a planning tendency, not three visible stages.

========================================================
9. FRESHNESS
========================================================

Follow:
  Tools/QUESTION_FRESHNESS_CONTRACT.txt

Allowed:
- same four jobs;
- same equation/factoring type;

- same distinctive values/data + same prompt;
- same exact table/graph/context as the same task;
- exact student-facing prompt copied from another artifact.

Warm-Ups may use clean fresh value-set parallels when routine fluency is the instructional purpose.

Required terminal:
  QUESTION_FRESHNESS: PASS

13. BANK-STYLE 4-UP VIEWER — REQUIRED
========================================================

Create:

  warmups/unit_{U}_warmups/unit_{U}_warmups_view.html

PURPOSE
-------
A fast screen-first inspection page modeled after the Bank viewer.

VISUAL MODEL
------------
Use the Bank viewer as the visual idea:
  algebra/banks/unit1/unit1.html

Do NOT copy Bank content architecture.
Copy the useful viewing behavior:
- wide screen container;
- clean section/day banners;
- compact bordered cards;
- four equal cards across on desktop;
- easy vertical scanning through the Unit.

LAYOUT — HARD
-------------
Group by SECTION.

For each section:
- section banner with section number + title

For each day:
- small Day header
- directly underneath, ONE FOUR-CARD ROW:

  Q1 | Q2 | Q3 | Q4

Desktop:
  grid-template-columns: repeat(4, minmax(0, 1fr))

Medium:
  repeat(2, minmax(0, 1fr))

Narrow:
  1fr

Each card shows:
- question number/job name;
- EXACT SAME student question content as main Warm-Up;
- actual table/graph/diamond/representation.

NO:
- workspace;
- answer;
- solution;
- internal IDs;
- provenance;
- giant page-height cards.

The viewer creates ZERO new question instances.

Viewer cards should be compact enough that a teacher can quickly scan the whole Unit.
