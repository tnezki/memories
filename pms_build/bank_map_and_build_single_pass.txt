5. EXIT — AUTHOR FIRST
=================================================

Follow:
  .../curriculum/exit_evidence_map.json

Normal section:
- Q1-Q2 = two NEW current-section Mastery evidence questions
- Q3-Q4 = fresh parallel reassessments of the previous section carry-forward pair

Unit 1 Section 1 exception:
- four opening readiness/mastery questions
- Q1-Q2 become the carry-forward pair for U1.2

HARD AUTHORING RULE:
A reassessment must be a NEW INSTANCE.

Preserve the evidence target, but change enough of the instance to make it fresh:
- values and/or
- graph/table data and/or
- context and/or
- representation details and/or
- scale / signs / placement when useful

Do NOT reuse the exact same:
- prompt
- values
- graph
- table
- stimulus
- generated graph file

U1.1's four opening questions should be four meaningfully different evidence tasks,
not four cosmetic versions of the same question.

10. LIGHTWEIGHT QA ONLY — DO NOT EXPAND
=================================================

This job intentionally uses a SHORT sanity check.
Do not run a giant audit framework.
Do not create dozens of QA categories.
Do not reopen the map after it is complete unless one of these checks finds a real defect.

PASS only these checks:

1. INVENTORY / COUNT
   - all expected IDs exist once
   - no missing or extra finished-task records
   - Practice = exactly 8 Intro + 8 Review + 8 Mastery per section
   - WTC = one shared stimulus + Parts A-D per section
   - Summative V1-V6 all exist

2. EXIT FRESHNESS
   - NEW questions are not duplicates of each other
   - reassessments are not exact/cosmetic copies of their source question
   - no reassessment reuses the same graph/table/stimulus file from its source

3. PROMPT COMPLETENESS
   - every value/data item named by the directions is actually present
   - if the prompt says "plot these points," the points are actually shown in the prompt
   - if the prompt says "use the graph/table/equation," that representation is actually visible
   - no TODO/TBD/placeholders

4. REPRESENTATION CHECK
   - required graph/table/equation/context is actually rendered
   - student construction surfaces are blank / answer-neutral
   - graph contents agree with the prompt
   - required graph evidence is inside the visible bounds

5. MATH / KEY CHECK
   - answer and solution match the authored prompt
   - arithmetic/algebra is correct
   - no answer leakage in student-facing content

6. SECURITY
   - secure Summative prompts/keys/solutions are not exposed in the public viewer
   - Practice does not copy secure Summative/Exit task instances

7. FINALIZATION
   - run Tools/finalize_output.py on the finished Bank tree
   - require FINALIZATION_QA: PASS

THAT IS THE QA.
Do not add separate MAP_FIDELITY_REPORT or giant RENDER_QA schemas unless
the current teacher explicitly asks for them.

If one of the checks fails:
fix the concrete defect and rerun only the affected check plus finalization.
