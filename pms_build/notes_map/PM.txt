ROLE
----
You are sequencing the instructional pathway for Physics Notes. You are NOT writing final Notes and you are NOT re-auditing the Unit Bank.

4A is a LIGHTWEIGHT SEQUENCING STAGE.
The canonical EX/YTI pairs already exist. The canonical WTC already exists. Physics Notes images are already cataloged and normally sorted by Unit/section. 4A decides how those existing parts fit together into a coherent conceptual story.

- inspect unrelated Bank items;

- research or plan final instructional prose;
- re-read full textbook/source libraries when the current Framework/map inputs already provide the needed concept sequence;

- fail because an optional polish check, broad architecture scan, or unrelated Bank finding is imperfect.

A finding blocks 4A ONLY when it prevents a trustworthy 4B handoff under the DIRECT BLOCKERS section below.

======================================================================
3. MAP THE STORY — DO NOT PLAN FINAL PROSE
======================================================================

Build each section as a short sequence of conceptual story beats.

For each beat record only what 4B needs:
- beat_id;
- concept_title;
- i_can_ids;
- reading_goal;
- essential_ideas;
- misconceptions/contrasts when useful;
- vocabulary introduced/developed;
- reading_depth = brief | developed | substantial;
- selected images;
- processing_anchor.

PROCESSING ANCHOR RULE
- Prefer the existing canonical EX/YTI pair when it naturally processes the beat.
- Otherwise map one content-specific Stop & Discuss.
- Do not invent extra EX/YTI.
- Do not automatically place Stop & Discuss before/after every pair.
- Several related ideas/images may share one processing destination when instructionally coherent.

MAP, DO NOT WRITE:
- reading_goal and essential_ideas are planning notes, not final paragraphs;
- Stop & Discuss uses a concise prompt skeleton/job, not polished teacher script;
- vocabulary definitions are targets, not final glossary prose;
- Summary is bullet targets only;
- Common Mistakes are misconception targets only.

======================================================================
4. EXAMPLE / YTI + WTC PLACEMENT
======================================================================

Resolve every canonical Notes EX/YTI pair actually present in the Unit Bank and each section WTC.

For each EX/YTI pair record:
- example_bank_id;
- yti_bank_id;
- i_can_id;
- story beat it follows;
- why that placement is natural;
- concept consolidated/applied.

HARD
- every canonical Notes EX/YTI pair exactly once;
- Example immediately paired with its YTI;
- no split pair;
- no rewritten pair;
- no substitute pair.

For each WTC record:
- exact bank_id;
- placement;
- purpose in flow.

Do not rewrite WTC content.

======================================================================
5. IMAGE SEQUENCING
======================================================================

Use the section-sorted toolkit catalog first. Select images that materially advance the mapped concept story.

For every selected image record:
- image_id;
- toolkit_path relative to toolkit root;
- source/provenance when available;
- story_role;
- exact concept/I-can connection;
- what_students_should_notice;
- why_here;
- processing destination.

Do not impose a fixed image count. Do not perform a full toolkit audit. Verify selected image IDs/paths only.

======================================================================
6. STOP & DISCUSS
======================================================================

Use Stop & Discuss only where the preceding reading/image beat needs processing and no canonical EX/YTI naturally fills that role.

For each Stop & Discuss record:
- after_story_beat_id;
- i_can_ids;
- discussion_job;
- prompt_skeleton;
- source_image_ids;
- expected_reasoning_evidence_to_listen_for.

FIELD OWNERSHIP — HARD
source_image_ids:
- array of image IDs only;
- each non-empty value matches ^PHYS-[A-F0-9]{12}$;
- each ID exists in the selected/current toolkit catalog.

expected_reasoning_evidence_to_listen_for:
- teacher-facing reasoning/evidence text only;
- no image IDs.

======================================================================
7. VOCABULARY / SUMMARY / COMMON MISTAKES
======================================================================

For each section map:

VOCABULARY PREVIEW
- exact required terms only.

VOCABULARY DEVELOPMENT
- first meaningful story beat for each term;
- image/phenomenon connection when useful.

VOCABULARY WITH DEFINITIONS
- definition targets immediately before Summary.

SUMMARY
- bullet-level concepts to synthesize.

COMMON MISTAKES
- section-specific misconceptions/errors Notes should address.

======================================================================
8. GENERATED REPRESENTATIONS

Record:
- representation_type;
- purpose;

- what must be shown;
- answer-neutrality constraints;

Do NOT generate the final asset in 4A.

======================================================================
9. CONTENT-STABLE BANK FINGERPRINT — HARD
======================================================================

4A identifies the source Bank by curriculum/content identity, never raw ZIP bytes.

PRIMARY METHOD — stage3e-canonical-v1
1. Read banks/unitN/STAGE_3E_HANDOFF.json from the pinned course commit.
2. Read canonical_authored_content_sha256.
3. Validate 64 hexadecimal characters.
4. Record exactly:
   source_bank_fingerprint_method = "stage3e-canonical-v1"
   source_bank_fingerprint = "stage3e-canonical:<lowercase-64-hex>"

Do NOT recompute or re-audit the entire Bank when this canonical Stage 3E identity is present.

FALLBACK METHOD — content-manifest-v1
Use only when Stage 3E canonical identity is unavailable and the current authority permits proceeding.

FORBIDDEN
- sha256:<raw-zip-hash>;
- omitting either fingerprint field;
- different fingerprints in map vs handoff.

12. DIRECT BLOCKERS — THE ONLY REASONS TO FAIL CLOSED
======================================================================

FAIL CLOSED only when one of these is true:

A. REQUIRED AUTHORITY MISSING
- current Assessment Plan/Framework/PM cannot be retrieved from the pinned snapshot.

B. EXACT TARGET MISMATCH
- section title, Learning Target, or I-can cannot be reconciled to the current Assessment Plan.

C. MAPPED BANK DEPENDENCY MISSING
- a required WTC/Example/YTI Bank ID needed for the Notes map does not exist or its pair relationship is broken.

D. SELECTED IMAGE DEPENDENCY MISSING
- a selected image_id/toolkit_path cannot be verified in the declared current toolkit catalog/course path.

E. OUTPUT/HANDOFF CONTRACT BROKEN
- required JSON cannot parse;
- required filenames/schemas/fingerprints do not match;
- rendered map HTML contains unresolved template/code placeholders.

Everything else is either:
- repair locally during mapping, or
- record as a NON-BLOCKING WARNING for later QA/polish.

DO NOT fail 4A for:
- unrelated Bank audit findings;
- optional stylistic improvements;
- source-library completeness;
- image choices that are merely debatable rather than invalid;
- lack of perfection in wording of planning notes;
- broad architecture checks unrelated to the four-file handoff.
