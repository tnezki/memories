======================================================================
2. CENTRAL NOTES STORY RULE
======================================================================

Build each section as conceptual story beats.

A substantial beat normally contains:
1. physics idea / phenomenon / model
2. planned developed reading
3. zero, one, or several useful images
4. a processing anchor before the story moves on

PROCESSING ANCHOR RULE
- If an existing canonical EX/YTI pair naturally fits, use that pair.
- Otherwise map a content-specific Stop & Discuss.
- Do not invent extra EX/YTI.
- Do not force a Stop & Discuss immediately before or after every EX/YTI.
- Every substantial reading/visual beat must have a meaningful processing destination.

For each reading beat record:
- beat_id
- concept_title
- i_can_ids
- reading_goal
- essential_ideas
- misconceptions/contrasts
- vocabulary
- reading_depth = brief | developed | substantial
- images
- processing_anchor

Physics reading plans should support:
- multiple short developed paragraphs where needed
- concrete before abstract explanation
- phenomenon/model-centered reasoning
- no wall of text
- no one-sentence stacking
- vocabulary developed in context

3. IMAGE-FIRST SEQUENCING
======================================================================

Inspect the toolkit catalog before sequencing the story.

Favor useful images for phenomena, conceptual models, comparisons/rankings, evidence, invisible relationships, misconceptions, historical/contextual understanding, graphs/data/experiments, and bridges to equations/models.

Do not impose a fixed image count.
Use every strong image that materially advances the story.

Omit an image only when it is irrelevant, substantially redundant, unreadable/poor quality, answer-bearing in conflict with the intended task, or better suited elsewhere.

FOR EVERY SELECTED IMAGE RECORD:
- image_id
- toolkit_path
- source/provenance when available
- story_role
- exact concept/I-can connection
- what_students_should_notice
- why_here
- processing destination

Every image_id and toolkit_path must be verified against the toolkit catalog and asset tree in the pinned COURSE snapshot. Store `toolkit_path` relative to the declared toolkit root (normally `images/...`), not as a memories-repo path.

9. CONTENT-STABLE BANK FINGERPRINT — HARD
======================================================================

4A MUST identify the source Bank by curriculum/content identity, NEVER by raw ZIP bytes.

PRIMARY METHOD — stage3e-canonical-v1
1. Read banks/unitN/STAGE_3E_HANDOFF.json from the pinned course commit.
2. Read canonical_authored_content_sha256.
3. Validate exactly 64 hexadecimal characters.
4. Record EXACTLY:

source_bank_fingerprint_method = "stage3e-canonical-v1"
source_bank_fingerprint = "stage3e-canonical:<lowercase-64-hex>"

FALLBACK METHOD — content-manifest-v1
Use only when Stage 3E canonical hash is unavailable and the current authority permits proceeding.

Ignore __MACOSX/, .DS_Store, ._*, __pycache__/, and *.pyc.
Normalize paths to POSIX slashes.
SHA-256 every regular file.
Sort by normalized path.
Feed UTF-8(path) + NUL + lowercase_file_sha256 + LF into SHA-256.

Record:
source_bank_fingerprint_method = "content-manifest-v1"
source_bank_fingerprint = "content-manifest:<lowercase-64-hex>"

FORBIDDEN
- sha256:<raw-zip-hash>
- omitting either fingerprint field
- placing the fingerprint only inside nested authority metadata
- using one fingerprint in the map and another in the handoff
