- exact student-facing I Can statements;
- stable I Can IDs;
- primary Mastery Goal organization;

================================================================
3. ATOMIC I-CAN RULE — HARD
================================================================

Every I Can is one stable, judgeable evidence address.

ATOMICITY TEST:
A valid I Can should normally allow a reviewer to answer one coherent question:
  "What specific understanding/action did the student demonstrate?"

SPLIT an I Can when:
- an "and" joins two independently judgeable skills;
- one half could be convincing while the other half is absent/wrong;
- the statement combines content recognition with a separate representation/modeling job;
- it combines a calculation/result with a separate critique/explanation job;
- Portfolio/Bank routing would need two different evidence families to judge it fairly.

DO NOT split when:
- the parts are inseparable features of one evidence job;
- a term set is naturally classified together;
- a representation requires direction + magnitude as one coherent meaning;
- a short explanation naturally includes the physical consequence of the same idea.

Never bundle independent jobs merely to keep a section at three I Cans.
Never split merely to hit a preferred count.
Section counts may differ.

================================================================
4. IDENTITY / IDS — HARD
================================================================

The Assessment Plan must print stable IDs next to exact I Can text.

Preferred current pattern for courses using primary-Mastery-Goal routing:
  U{unit}-MG{goal two digits}-IC{ican two digits}

Example:
  U1-MG02-IC03

Use this pattern when:
- the course already uses it; OR
- the teacher explicitly migrates the Unit to MG-first identity before downstream rebuilds.

Otherwise preserve an established stable course ID convention.
Do not renumber stable IDs casually after downstream evidence exists.
If a migration is intentional, record it in the machine map and declare which older derivative indexes are superseded.

Every exact I Can has exactly one PRIMARY Mastery Goal for deterministic Portfolio/Bank routing. Supporting cross-goal relationships may be noted, but do not create ambiguous primary ownership.

HUMAN-FACING IDENTITY DISPLAY RULE — HARD
Whenever an Assessment Plan shows an I Can to a human reader, show BOTH:
  <full stable I Can ID> + <exact I Can statement>
Never show a human-facing code-only list or compressed range such as `U1-MG03-IC01 through U1-MG03-IC07`.
If several I Cans belong to one Mastery Goal, list them individually with the exact statement next to each code.
Whenever a Mastery Goal code is shown to a human reader, pair it with its title (and goal statement where the context calls for it).
Machine-readable fields may store IDs as identifiers, but the same record/map must also carry the exact text/title needed to resolve them.

================================================================
5. SECTION CONTRACT — LEAN DEFAULT
================================================================

Each section must contain:
1. Section identity/source alignment
2. one Learning Target
3. exact atomic I Cans with IDs
4. Key Vocabulary / Notation
5. Key Representations
6. Common Misconceptions / Failure Points
7. Evidence Expectations

Optional only when genuinely useful/current-course-required:
- Modeling/Application Opportunities
- Recurring Practice Opportunities

Do NOT auto-create a giant recurring-practice map, Learning Ladder, progress-status table, or daily sequence merely because an older plan had one.

LEARNING TARGET
- coherent section umbrella;
- broader than one I Can;
- narrow enough to distinguish the section.

I CANS
- student-facing;
- assessable;
- atomic per Section 3;
- no filler/duplicate restatements;
- exact enough to become Bank/Portfolio addresses.

REPRESENTATIONS
- include only representations students actually interpret/create/use;
- decorative visuals do not count.

MISCONCEPTIONS
- content-specific, useful for authoring evidence families later.

EVIDENCE EXPECTATIONS
- describe what student work should reveal;
- no finished questions.

================================================================
6. MASTERY GOALS — HARD
================================================================

Mastery Goals organize related I Cans for reporting and body-of-evidence reasoning.

For every MG include:
- stable MG ID;
- concise title;
- goal statement;
- exact primary I Can IDs AND their exact I Can statements, displayed together;
- concise convincing-evidence description.

Do not simply make one MG per section unless that is genuinely the strongest organization.
Do not force a universal MG count.
When revising a current Unit, preserve existing MG IDs when the goal identity remains recognizable.

================================================================
7. EVIDENCE OPPORTUNITY PLAN — LEAN / HARD
================================================================

The plan must state these boundaries:

- each exact I Can is one evidence address;
- one task may support multiple I Can judgments only when the responses are separately judgeable;
- multiple judgments from one source do not become multiple independent opportunities for the same I Can;
- repeated evidence should use meaningfully changed context/representation when independence matters;
- richer artifacts are not automatically stronger evidence; student action determines evidence strength;
- secure Summative evidence must be semantically independent from exposed practice/examples.

Keep this plan concise. Do not author destination inventories here.

================================================================
8. SUMMATIVE PLAN — HARD
================================================================

Define:
- which Mastery Goals require secure evidence;
- the important representations/explanations/justifications;
- what selected-response can efficiently sample;
- what constructed/show-work evidence should reveal;
- calculator/reference/material conditions only when course authority supports them;
- security independence from exposed content.

Do not invent universal item counts, form counts, minutes, or DOK quotas.
Those belong to active course Summative contracts/profiles.

================================================================
9. MACHINE-READABLE UNIT LEARNING MAP
================================================================

When the Course Framework manifest declares a per-Unit learning-map path, the Assessment Plan build/revision must also emit/update that map in the SAME authority change.

Minimum fields:
- schema/status/course/unit/title;
- authority note saying Assessment Plan HTML wins on conflict;
- ID migration note when applicable;
- Mastery Goals with ID/title/goal/sections;
- each exact I Can with ID, section ID, exact text;
- counts.

The machine map is DERIVATIVE. It never outranks the Assessment Plan HTML.

When an intentional revision makes an older global derivative index stale for only one Unit:
- do NOT silently rewrite unrelated Units;
- declare the Unit-specific override in the Course Framework manifest;
- mark the older Unit records superseded;
- leave unrelated Unit records intact.

================================================================
10. REVISE MODE / CHANGE BOUNDARY
================================================================

When revising:
- preserve current Unit/section titles and source alignment unless the teacher changes scope;
- preserve path/filename/shell unless migration is explicitly requested;
- make the smallest coherent upstream correction;
- update the Framework-resident original Assessment Plan copy when that course uses one;
- update the declared Unit learning map;
- update Framework manifest routing only when needed to prevent stale derivative authority.

Do NOT rebuild downstream Bank/Notes/Practice/Portfolio artifacts inside Step 1.
Step 1 may intentionally make them stale. Record that boundary clearly so Step 2 can rebuild from the corrected authority.

================================================================
11. QA — HARD
================================================================

SOURCE / SCOPE
- exact course/unit resolved;
- every section remains inside declared source/course scope;
- no new topic imported merely because a textbook contains it.

ATOMICITY
- no I Can contains two independently judgeable evidence jobs;
- every I Can has stable ID;
- no accidental duplicate I Cans;
- every I Can has one primary MG.

CONSISTENCY
- Learning Target, I Can, MG, evidence wording agree;
- section names and Unit title are consistent;
- machine map exact text matches HTML exact text;
- declared counts match actual records;
- stale derivative Unit records are explicitly superseded when applicable;
- no human-facing I Can or Mastery Goal appears as an unexplained code/range without its exact statement/title.

LEANNESS
- no automatic Learning Ladder;
- no automatic legacy proficiency boxes;
- no WTC/Example/YTI/Practice quota leakage;
- no finished questions.

FINAL BYTES
- valid readable HTML/JSON/TXT;
- no unresolved template tokens;
- valid JSON;
- MathJax delimiters use registered safe delimiters when math appears.
