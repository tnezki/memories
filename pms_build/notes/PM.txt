4B · BUILD PHYSICS NOTES PM v1.4
================================
FAST-PATH REVISION — 2026-08-29

4B NOTES-MAP INPUT — HARD
-------------------------
Read the canonical expanded map at `<course>/notes/unitN_notes_map/unitN_notes_map.json` from the pinned course commit. Do not require a retained Notes Map ZIP.

ROLE
----
Build the complete student + teacher Physics Notes for one Unit by ASSEMBLING the already-approved 4A Notes Map with the current Notes HTML/CSS shell, exact Bank anchors, mapped images, and limited new explanatory/support prose.

4B is an ASSEMBLY/AUTHOR/RENDER stage, not a second mapping stage and not a second Bank audit.

The expected workload is intentionally narrow:
- preserve the established Notes HTML/CSS layout;
- place the exact mapped WTC/EX/YTI content;
- reference the exact mapped images;
- write the mapped reading/explanation, S&D wording, vocabulary definitions, Summary, Common Mistakes, and teacher support;
- create only mapped generated representations;
- run targeted final QA on what was actually built.

The goal is a strong usable first build, not perfection before the first Notes file exists.

======================================================================
CANONICAL STORAGE CONTRACT — HARD
======================================================================

GitHub stores readable authorities and multi-file curriculum artifacts EXPANDED. ZIP is transfer/handoff only.

Build the complete student + teacher Notes for the Unit. Return the installation ZIP described in OUTPUT CONTRACT.

======================================================================
0. FAST-PATH OPERATING RULE — HARD
======================================================================

4B MUST NOT:
- re-plan story order already approved by 4A;
- re-audit the complete Bank for unrelated quality, duplication, difficulty, or solution issues;
- inspect unrelated Bank items;
- re-research textbook/source libraries when 4A already mapped the content story and images;
- re-audit the full image toolkit;
- redesign CSS/layout for ordinary content production;
- fail because of optional polish, broad architecture warnings, or unrelated repository findings.

4B validates only the mapped dependencies it will actually use.

A finding blocks 4B ONLY when it meets one of the DIRECT BLOCKERS below.

======================================================================
4. DIRECT BLOCKERS — THE ONLY REASONS TO FAIL CLOSED
======================================================================

FAIL CLOSED only when one of these prevents a correct build:

1. required current Assessment Plan/Framework/PM/map cannot be retrieved;
2. exact section/LT/I-can mismatch cannot be reconciled to the Assessment Plan;
3. mapped WTC/EX/YTI Bank item is missing or wrong pair identity;
4. mapped image cannot be verified at its canonical course path;
5. required Notes shell/CSS/finalizer dependency is missing or broken such that the artifact cannot render correctly;
6. map/handoff Bank fingerprint is a real content mismatch;
7. final student/teacher HTML cannot be made valid without violating a hard Framework contract.

DO NOT fail 4B for:
- unrelated Bank findings;
- unused image/toolkit issues;
- stylistic preferences that can be improved later;
- broad architecture warnings outside the produced Notes;
- minor prose polish;
- optional QA that is not tied to a mapped dependency or generated output.

Repair local production defects in place and continue.

======================================================================
5. ASSEMBLY ORDER — BUILD FIRST
======================================================================

For each section:

1. Start from the established/current Notes HTML shell/template and required CSS links.
2. Insert exact section title, Learning Target, and I-cans.
3. Add the brief KWL opening.
4. Add Vocabulary Preview + required sort.
5. Insert the exact mapped WTC.
6. Walk the 4A beats in order:
   - write the mapped conceptual reading/explanation;
   - reference mapped image(s) in place;
   - insert the mapped processing anchor;
   - when anchor is EX/YTI, use exact Bank content;
   - when anchor is S&D, write concise final wording from the mapped job.
7. Create only mapped generated representations.
8. Add Vocabulary with Definitions.
9. Add mapped Summary.
10. Add mapped Common Mistakes and required workspace.
11. Finalize STUDENT HTML.
12. Derive TEACHER HTML from the finalized student structure and add only teacher support/solutions.
13. Run targeted section QA, then move to the next section.

Do not stop the whole Unit for a repairable section-level formatting issue.

======================================================================
6. CORE PHYSICS NOTES DESIGN
======================================================================

Physics Notes should read like an illustrated conceptual-physics chapter that periodically stops for students to process and apply ideas.

Execute the map's sequence:
conceptual reading / phenomenon / model
-> selected source image(s) and explanation
-> mapped processing anchor
-> next conceptual beat.

READING
- Write multiple short developed paragraphs when mapped depth is developed/substantial.
- Explain what changes, what stays the same, what causes what, which evidence matters, and how representations relate.
- Use direct, concrete, precise high-school Physics language.
- Avoid one-sentence stacking and walls of text.
- Paraphrase protected source text; do not reproduce long textbook passages/captions verbatim.

IMAGE-DRIVEN STORY
- Use every image selected by the approved map unless the actual selected file is corrupt/unusable.
- Images are instructional, not decoration.
- Direct student attention to the mapped important features without giving away later answers.

======================================================================
7. SECTION OUTER ARCHITECTURE
======================================================================

Unless the current Framework says otherwise:

1. Section title
2. exact Learning Target
3. exact I-cans
4. KWL-style opening: What I already know + What I wonder
5. Vocabulary Preview + three-column prior-knowledge sort
6. canonical What's to Come early
7. mapped story beats/images
8. mapped EX/YTI pairs and S&D anchors
9. Vocabulary with concise definitions before Summary
10. bulleted Summary
11. optional What I figured out near the end when useful
12. Common Mistakes
13. generous Notability/student workspace where required
14. teacher guidance in teacher copy

Do not add a Notes Exit Ticket/Exit Check.

KWL direction:
"Skim the headings and figures. Write one thing you already know about this topic and one question you have."

WTC
- canonical Bank content unchanged;
- generous workspace;
- teacher support facilitates noticing/productive uncertainty and does not solve the preview task.

======================================================================
9. STOP & DISCUSS
======================================================================

Write final S&D wording only where 4A mapped it.

GOOD
- concise and specific to the immediately preceding idea/image/model;
- compare, predict, explain, rank, infer, identify evidence, or resolve a misconception as mapped;
- normally 1-3 focused prompts.

BAD
- generic stock prompts;
- automatic S&D after every pair;
- hidden second question bank.

Teacher copy adds expected reasoning/evidence-to-listen-for.

======================================================================
12. VOCABULARY
======================================================================

Opening Vocabulary Preview contains mapped terms WITHOUT definitions, followed by the established active sort.

Use this student-facing direction exactly unless the user changes it:
"Sort the vocabulary. Write each vocabulary word in the column that best matches what you know right now. You may move a word later."

Headers exactly:
1. Know for sure
2. Recognize
3. Don't know yet

Required structure/classes:
- vocab-preview-section
- h-vocab
- vocab-list
- vocab-sort-task
- vocab-sort-directions
- vocab-sort-table on TABLE
- vocab-sort-space on blank BODY ROW

At first meaningful use in prose, bold a term once. Immediately before Summary, include mapped concise Vocabulary with Definitions.
