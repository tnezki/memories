INDEPENDENT QUESTION AUDIT
--------------------------
Audit every canonical question against the finished prompt, answer/solution, representation, audited map, and resource purpose.

For each item, evaluate the applicable dimensions independently:
1. MAP ALIGNMENT
   Does the finished question actually perform the mapped I-can/evidence job/response demand?

2. STRUCTURE
   Does the finished question actually use the planned question structure? For multi-step, is the dependency real rather than decorative Part A/Part B?

3. WORDING
   Is the prompt short, natural, grammatical, and free from unnecessary setup or template/Mad-Lib scaffolding? Context-rich is not the default.

4. REPRESENTATION
   If a graph, FBD, vector diagram, motion diagram, table, model, or other representation is required or materially carries the mapped evidence, does it actually exist and work correctly?

5. PARALLEL / VARIETY FIDELITY
   When a question is a declared parallel, does it preserve the intended skill/difficulty while visibly realizing the mapped variation? Intentional similarity is GOOD. Literal sameness is only a problem when the map required a meaningful change.

6. PHYSICS / ANSWER
   Is the Physics correct? Is the question solvable as written? Does the answer/solution actually answer the final prompt? Are units, signs, directions, and reasoning coherent?

7. SECURITY
   For Exit and Summative items, is the evidence appropriately fresh from exposed instructional tasks and secure peers while still matching the mapped evidence job?

Applicable dimensions receive PASS or FAIL. Genuinely nonapplicable dimensions receive N/A.
Overall audit_status is derived:
- any applicable FAIL -> FAIL;
- all applicable PASS -> PASS.

Do not use KEEP / CLEAN / REBUILD.

AUDIT PHILOSOPHY
----------------
Audit defects, not resemblance.

Do NOT fail a question merely because:
- Practice forms are intentionally parallel;
- YTI resembles its Example;
- Exit B/C resemble A;
- Summative V2-V4 resemble V1;
- Summative V6 resembles V5;
- the same useful representation style appears more than once;
- a short direct question is not context-rich.

Do flag actual defects such as:
- wrong evidence job;
- broken or missing representation;
- mapped variation not realized;
- wordy or unnatural scaffolding;
- incorrect answer/solution;
- fake multi-step structure;
- secure task copied from exposed instruction or a supposedly distinct secure form;
- selected-response distractors that are not defensible.

TEACHER AUDIT REVIEW PAGE
-------------------------
Create:
  unitN_audit_review.html

This page is FOR INSPECTION ONLY. It has no Fix Now / Later / Accept controls.

Default organization must be:
  Dimension -> Resource -> Severity -> finding cards

Within each dimension:
- group by resource/destination;
- within resource, sort High severity before Medium, then Low;
- stable order after severity should follow section and canonical item order.

At the top show compact counts:

- items with all applicable checks PASS;
- items with one or more findings;
- findings by dimension;
- findings by severity;
- findings by resource.

EVERY ITEM-LEVEL FINDING CARD MUST MAKE THE QUESTION OBVIOUS
------------------------------------------------------------
Use generous whitespace.

Required order:
1. Finding title + severity.
2. Small metadata: item ID, section, resource, I-can.
3. BLANK SPACE.
4. Clearly labeled block: QUESTION BEING REVIEWED.
5. Exact student prompt in larger readable type.
6. Choices, if any.
7. Actual figure/table/diagram, if any, at readable size.
8. Expandable answer + solution/evidence details.
9. BLANK SPACE.
10. Clearly labeled block: AUDIT FINDING.
11. Failed dimension(s), concise why, concrete evidence, and suggested repair direction.

The question block must be visually separated from the finding explanation so the teacher never has to guess which text is the student question.
