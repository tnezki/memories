BUILD PRACTICE - RECURRENCE TARGET PLANS
========================================
STATUS: CURRENT
STEP: 5
JOB: practice
REVISION: 2026-09-26 v4.0

ROLE
Build the selected Algebra section Practice from the approved recurrence map and Bank family architecture.

AUTHORITY
Use pinned Philosophy/Runtime, current Algebra Framework + exact Unit Assessment Plan, curriculum/mastery_recurrence_map.json, current Practice profile, approved Bank families for selected I Cans, Question Structure as needed, and registered rendering tools.

1. TWO TARGET PLANS
Each section has two teacher-editable target plans.
- Target Plan A -> Practice 1 and paired Activity Set 1.
- Target Plan B -> Extra Practice and paired Activity Set 2.
The system supplies a strong recommendation first; the teacher may alter I Cans, counts, family preference, or a fine-tuning note.

2. SET SIZE
Normal = 12 questions. Allowed = 12-16.
Do not restore a universal 24-question requirement.

3. CURRENT INTRO + RECURRENCE MIX
Normally use 4 current Intro questions, with useful coverage/variety across current Intro I Cans/families.
Use the remaining 8-12 slots on a deliberate mixture of Review/Mastery I Cans from MULTIPLE Mastery Goals according to the recurrence map. Current formal Mastery receives meaningful emphasis but does not automatically own the whole recurrence block.
Plan B intentionally overlaps important Plan A targets while rebalancing some counts/targets for additional spacing.

4. BANK / OFFLINE ASSEMBLY
Select approved families that fit each target. Prefer deterministic/seeded family generation when safe; otherwise instantiate a fresh reviewed sibling. Preserve family invariant/evidence job/representation/difficulty and record family + seed/parameters in source lineage when supported.

Every targeted question visibly shows:
  <I CAN CODE> — <FULL EXACT I CAN STATEMENT>

5. OPTIONAL STANDALONE GENERATORS
CYU, Tarsia, Blooket/game exports and similar extras are NOT required initial Practice outputs. They may be generated later from approved Bank families through standalone teacher tools and do not drive initial Bank/Practice inventory size.

6. QA / DELIVERY
Verify exact target-plan counts, recurrence-map alignment, multi-goal mix, family variety, answers, representations, duplicate avoidance within a set, source lineage, layout, and finalization. Return ONE github_transfer / 2 ZIP. No Git operations.

END - ALGEBRA PRACTICE
