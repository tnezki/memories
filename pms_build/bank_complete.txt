============================================================================
3. GOOD-ENOUGH CORE ACCEPTANCE STANDARD
============================================================================

A Bank record is GOOD ENOUGH when it is:

1. CORRECT
   - content/physics/math correct;
   - answer and solution correct;
   - units/signs/relationships correct;
   - representation consistent with the prompt.

2. ALIGNED
   - preserves exact mapped I-can;
   - performs the mapped evidence job;
   - performs the mapped intended reasoning;
   - response mode honestly captures the student action.

3. COMPLETE
   - no placeholders;
   - all required choices/answers/solutions exist;
   - all required metadata exists;
   - all map records are authored exactly once.

4. USABLE
   - student-facing wording is understandable;
   - graph/table/diagram is legible;
   - no broken refs;
   - no answer-leaking student visual;
   - task can actually be assigned.

5. VARIED ENOUGH
   - family seed is a complete distinct classroom task;
   - required family variation axes are genuinely available;
   - no obvious noun-only pseudo-variety;
   - enough meaningful diversity exists for downstream deterministic sets/forms.

6. DOWNSTREAM-READY
   - ITEM_INDEX routes reconcile;
   - BANK_MANIFEST is COMPLETE;
   - Notes/Practice/Exit/Summative PMs can consume it without guessing.

GOOD ENOUGH does NOT require:
- best possible prose;
- perfect aesthetics;
- maximal novelty;
- ideal image size;
- ideal graph styling;
- exhaustive pedagogical refinement.

If a later memoryless audit can improve something WITHOUT fixing correctness/completeness/usability,
that is not a reason to block this core build.

============================================================================
5. QUESTION / RESPONSE QUALITY
============================================================================

QUESTION STRUCTURE
------------------
Execute the mapped question_structure_id.
Do not merely copy its label into metadata.

SELECTED RESPONSE
-----------------
When mapped selected_response:
- use mapped/course-default choice count;
- render every choice visibly in student_html;
- unique choices;
- valid keyed answer;
- distractors tied to plausible task-specific errors/misconceptions;
- no arbitrary filler distractors.

CONSTRUCTED RESPONSE
--------------------
Prompt must actually require the mapped reasoning/construction/explanation.
Provide an appropriate response surface when mapped.

EXAMPLE / YTI
-------------
Preserve mapped pair identity.
Example models the target reasoning.
YTI performs comparable evidence in a meaningfully changed situation.

SECURE FAMILIES
---------------
Security means fresh evidence.

Allowed:
- same I-can;
- same evidence architecture;
- same structure;
- comparable difficulty.

Forbidden:
- exposed finished prompt reuse;
- distinctive exposed data/stimulus reuse;
- noun-only disguise of an exposed item;
- answer-bearing visual.

============================================================================
6. REPRESENTATIONS — GOOD-ENOUGH VISUAL STANDARD
============================================================================

A representation must be ACCURATE, LEGIBLE, RELEVANT, and EXECUTABLE.

It does NOT need to be aesthetically perfect.

GRAPH
-----
Resolve `graph_tool` through Tools/MANIFEST.json when the Map requires/supports it.

Graph PASS requires:
- correct axes;
- useful scale;
- readable labels/units;
- correct plotted relationship/data;
- no clipped essential content;
- answer-neutral student-facing version when required;
- local/reference path works.

Do not burn time tuning a graph merely because a later audit could make it prettier.

SMALL TABLE
-----------
Use semantic HTML.
Use `<table class="values">` where mapped/current Base CSS expects compact data tables.
No pipe-delimited pseudo-tables.

DIAGRAM / VECTOR / FBD / MODEL
-------------------------------
Use the exact mapped route:
- canonical asset;
- registered deterministic tool;
- student-constructed response surface.

PASS requires:
- physically/mathematically correct;
- legible;
- not distorted;
- not answer-leaking;
- required labels present;
- correct reference path.

A merely less-than-beautiful but correct readable diagram is GOOD ENOUGH.
Crude/incorrect/unreadable diagrams are NOT.

DIRECT TEXT / EQUATION
----------------------
Do not add decorative visuals merely to create variety.
