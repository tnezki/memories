===============================================================

STATUS: CURRENT
STEP: 3b
JOB: bank_complete
ROLE: Author the complete canonical Unit Bank from one accepted 3a Bank Map in one run.
REVISION: 2026-09-05 accepted-map fidelity + final QA + unit viewer hardening

AUTHORITY — HARD
1. current explicit teacher instruction
2. current Curriculum Philosophy
3. current universal Question Structure authority
4. current Course Framework + exact Unit Assessment Plan + canonical operational maps
5. current Framework Bank profile
6. accepted 3a Bank Map (MAP_MANIFEST.status = PASS)
7. this PM
8. registered tools/render contracts

Do not use an old/partial Unit Bank, retired bank schema, legacy template library, legacy standards map, or historical artifact as curriculum authority. Build a fresh replacement staging tree from the accepted map/current authorities.

ENTRY GATE — HARD
Require:
- MAP_MANIFEST.status = PASS
- question_design.status = PASS
- qa.status = PASS
- every destination slice declared by MAP_MANIFEST readable and reconciled
- MAP_REPORT semantic Question-Structure audit present and PASS.
If not, FAIL CLOSED as BANK_MAP_NOT_ACCEPTED.

SEMANTIC RECHECK — HARD
Before authoring, spot/reconcile the accepted map against CURRENT Question Structure definitions. If the map contains a structure/action/response/representation mismatch, incomplete mixed-representation route, fake multi-step dependency, invalid Error Diagnose route, or construction task without an answer-neutral construction surface, FAIL CLOSED as BANK_MAP_SEMANTIC_MISMATCH. Do not author around a bad map.

ACCEPTED MAP EXECUTION CONTRACT — HARD
The accepted 3a Map is executable design, not a suggestion. Step 3b may fresh-author values, wording, contexts, and representations only inside the variation contract of each accepted map record. It may NOT substitute a different task family, goal, I Can, evidence job, student action, structure, stage, destination, or representation job merely because a legacy template is available.

Before authoring, build an internal one-to-one expected-record table from every accepted destination slice. After authoring, compare every finished Bank record against that exact source record.

For every finished question/task, the following accepted-map fields are HARD identity/behavior fields and must remain aligned exactly or materially equivalently as specified by the map:
- accepted map record/design slot ID
- destination
- section/unit scope
- stage
- target/Mastery Goal ID and text
- primary and supporting I Can IDs/texts
- evidence_job
- student_action
- selected Question Structure ID
- response_mode
- representation_mode / representation_need
- executable representation route(s) / answer-neutral response surface
- security role
- difficulty intent
- required/forbidden variation axes
- source-map identity
- destination-specific slot/role metadata.

Fresh authoring may instantiate the mapped design. Fresh authoring may NOT replace the mapped design.

ANTI-LEGACY / ANTI-TEMPLATE CONTAMINATION — HARD
- Do not inject historical readiness goals, retired unit goals, generic capability labels, generic card/template types, or standards merely because an old Bank used them.
- Optional metadata may be added only when explicitly supported by a higher current authority and only when it does not alter or drive the mapped task.
- Never let optional metadata override target, I Can, evidence job, structure, stage, representation, or destination from the accepted map.
- If a prior Bank/template conflicts with the accepted map, ignore the prior Bank/template.

PROFILE-DRIVEN INVENTORY — HARD
Author EXACTLY the canonical destinations declared by the accepted Map/current course profile. Do not revive historical inventories merely because old PMs/files exist.
For Algebra 1 v7.2, canonical Bank content is:
- official Exit questions
- secure Summative V1-V6
- Practice 1
- WTC
- canonical Seeds when mapped
NOT Bank content: Extra Practice, CYU, Practice 2/3, fixed Notes Example/YTI pairs, finished Warm-Up questions.

QUESTION STRUCTURE — HARD
For every finished question/task, execute the mapped current universal Question Structure contract. Do not merely store a structure label. The authored prompt, response mode, representation, and evidence job must agree with the selected structure's actual reasoning architecture.
A current course exemption may bypass this rule; Algebra Warm-Ups are the explicit exemption, but Warm-Ups are not authored by this Bank job.
Seeds are not finished questions. When a later builder turns a seed into a question, that later question uses Question Structure.

COMMON AUTHORED RECORD
Preserve accepted map identity and include as applicable:
- record/family/item ID
- destination + section/unit scope
- exact goal/I-Can/stage links
- evidence_job + student_action
- question_structure_id
- response_mode
- representation/tool/response-surface route(s)
- security level
- difficulty intent
- variation axes
- source_map_record_id/source_basis
Finished content includes student prompt/HTML, answer/key, solution, and representation refs as required.
No placeholders or internal authoring labels in student-facing prose.

EXIT — ALGEBRA RULE
Author the exact ticket architecture from the Framework/accepted map.
Normal ticket:
- Q1-Q2 = current new mastery evidence
- Q3-Q4 = fresh parallel reassessment of previous section carryforward pair
U1.1 = four new U1-MG01 opening questions, with Q1-Q2 designated carryforward pair.
Parallel reassessment preserves evidence target + usable difficulty while varying allowed axes. Do not expose future secure parallels in ordinary Practice/Notes.

EXIT MAP-FIDELITY GATE — HARD
For each ticket, compare authored slot-by-slot against exit_map.json before PASS:
- exact Q1/Q2/Q3/Q4 slot identity
- exact NEW vs REASSESS role from map
- exact target/Mastery Goal
- exact source/carryforward relationship
- exact evidence job/student action/structure/representation job.
For U1.1 specifically, if any of Q1-Q4 is authored as readiness/legacy REASSESS when the accepted map says NEW, FAIL CLOSED as EXIT_MAP_DRIFT.
Do not derive Exit classification from an old Bank schema or generic readiness template.

SUMMATIVE — SECURE
For Algebra, accepted map should target approximately TWO secure evidence opportunities per CURRENT Unit Mastery Goal and a complete form designed for about 40 minutes. Exact item count may vary by Unit because Mastery Goal count and task complexity vary; do not hard-code 8.
Author forms in this order:
1. V1 anchor form from current Unit Mastery Goals + accepted Summative blueprint.
2. V2-V4 parallel forms preserving blueprint/evidence/difficulty with fresh secure instances.
3. V5-V6 additional secure forms under the same blueprint/comparable rigor after V1-V4 are complete.
All forms must be independently usable and secure. Do not create pseudo-parallels by noun swaps or trivial number changes when the map requires deeper variation.
Verify each finished form still fits the accepted approximate 40-minute demand.

SUMMATIVE CONTENT — HARD
"Secure" does NOT mean "reference-only" or "placeholder" in the canonical Bank. Every mapped Summative slot must be actually authored in the secure Bank slice with:
- finished prompt/student-facing content
- exact mapped target/I Can/evidence job/student action
- Question Structure ID + executed reasoning architecture
- response mode
- required representation data/routes
- answer/key
- worked solution or scoring criteria sufficient for secure downstream rendering
- form, slot, family identity, and variation provenance.
A URI such as secure_assessment://... may be stored as an additional locator, but it may NOT replace the finished secure content.
If any Summative slot contains only a reference/locator and no authored task/key/solution, FAIL CLOSED as SUMMATIVE_NOT_AUTHORED.

SUMMATIVE MAP-FIDELITY GATE — HARD
Compare every V1-V6 slot against summative_map.json. The authored slot must preserve the mapped Mastery Goal, I Cans, evidence job, student action, structure, response mode, representation job/routes, difficulty intent, timing role, and required variation contract. If V1-S2 is mapped to one evidence job but authored as a different concept/task, FAIL CLOSED as SUMMATIVE_MAP_DRIFT.

PRACTICE 1 — ALGEBRA RULE
Author the accepted Practice 1 map exactly:
- 24 questions per section
- 8 Intro
- 8 Review
- 8 Mastery
- visible stage grouping
Intro practices current learning.
Review practices the exact current Review goal at Review demand.
Mastery practices current Mastery goal independently and is informed by Exit evidence without copying secure Exit prompts/stimuli.
Within each block, purposeful repetition is allowed and preferred over filler. Do not manufacture fake structure variety or mechanical equal-I-Can quotas.
Practice 1 may use canonical Seeds when the map routes them.

PRACTICE MAP-FIDELITY GATE — HARD
For all 120 Algebra Unit 1 Practice rows (and analogous counts in later Units), preserve the exact accepted map row identity and mapped learning job. Do not replace a mapped representation-transfer task with a generic coordinate-reading, motion-story, or other legacy template merely because it seems related.
Before PASS, compare each authored row to practice1_map.json for target, I Can, evidence job, student action, structure, response mode, representation job/routes, stage, and grid sequence.
Any material mismatch = PRACTICE_MAP_DRIFT.

WTC
Author the accepted connected multipart routine. Keep one coherent stimulus/representation and real carry-forward. It is instructional preview/decomposition, not disguised secure assessment. Materialize every required representation/response surface named by the map.

WTC MAP-FIDELITY GATE — HARD
For each WTC routine, preserve the accepted shared-stimulus concept, dependency contract, carried-forward intermediate result, part count, part sequence, target/I Cans, structure, and representation route(s). Do not replace the mapped routine with a generic older "What to Chart" or unrelated multipart routine. Any material mismatch = WTC_MAP_DRIFT.

SEEDS
Store mapped seed records in a reusable non-student-facing slice. Seeds have NO quota. A seed should preserve the useful idea and variation guidance, not force a final prompt/answer unless the map separately defines a finished canonical question. Do not add filler seeds during 3b.

SEED MAP-FIDELITY GATE — HARD
When seed_map.json contains mapped approved candidates, store those exact seed identities and preserve their title, preserve/idea statement, why-useful rationale, and may-vary guidance. Do not replace approved seeds with generic template-library cards, blank-build cards, or different legacy seeds. Any approved mapped seed missing or materially replaced = SEED_MAP_DRIFT.

REPRESENTATIONS
Generate/copy only mapped executable representations. Graphs use registered graph tooling when required; small data tables use semantic HTML; student-constructed representations use answer-neutral response surfaces. If a task requires graph + table, render both. No decorative figures for quota.

- missing accepted records

- Exit role/chain mismatches

- WTC dependency/part mismatches
- Seed identity/content mismatches
