BUILD COMPLETE BANK — STEP 3B / PROFILE-DRIVEN BANK AUTHORING
===============================================================

STATUS: CURRENT
STEP: 3b
JOB: bank_complete
ROLE: Author the complete canonical Unit Bank from one accepted 3a Bank Map in one run.

AUTHORITY — HARD
1. current explicit teacher instruction
2. current Curriculum Philosophy
3. current universal Question Structure authority
4. current Course Framework + exact Unit Assessment Plan + canonical operational maps
5. current Framework Bank profile
6. accepted 3a Bank Map (MAP_MANIFEST.status = PASS)
7. this PM
8. registered tools/render contracts

Do not use an old/partial Unit Bank as curriculum authority. Build a fresh replacement staging tree from the accepted map/current authorities.

ENTRY GATE — HARD
Require:
- MAP_MANIFEST.status = PASS
- question_design.status = PASS
- qa.status = PASS
- every destination slice declared by MAP_MANIFEST readable and reconciled
- MAP_REPORT semantic Question-Structure audit present and PASS.
If not, FAIL CLOSED as BANK_MAP_NOT_ACCEPTED.

SEMANTIC RECHECK — HARD
Before authoring, spot/reconcile the accepted map against CURRENT Question Structure definitions. If the map contains a structure/action/response/representation mismatch, incomplete mixed-representation route, fake multi-step dependency, invalid Error Diagnose route, or construction task without an answer-neutral construction surface, FAIL CLOSED as BANK_MAP_SEMANTIC_MISMATCH. Do not author around a bad map.

PROFILE-DRIVEN INVENTORY — HARD
Author EXACTLY the canonical destinations declared by the accepted Map/current course profile. Do not revive historical inventories merely because old PMs/files exist.
For Algebra 1 v7.2, canonical Bank content is:
- official Exit questions
- secure Summative V1-V6
- Practice 1
- WTC
- canonical Seeds when mapped
NOT Bank content: Extra Practice, CYU, Practice 2/3, fixed Notes Example/YTI pairs, finished Warm-Up questions.

QUESTION STRUCTURE — HARD
For every finished question/task, execute the mapped current universal Question Structure contract. Do not merely store a structure label. The authored prompt, response mode, representation, and evidence job must agree with the selected structure's actual reasoning architecture.
A current course exemption may bypass this rule; Algebra Warm-Ups are the explicit exemption, but Warm-Ups are not authored by this Bank job.
Seeds are not finished questions. When a later builder turns a seed into a question, that later question uses Question Structure.

COMMON AUTHORED RECORD
Preserve accepted map identity and include as applicable:
- record/family/item ID
- destination + section/unit scope
- exact goal/I-Can/stage links
- evidence_job + student_action
- question_structure_id
- response_mode
- representation/tool/response-surface route(s)
- security level
- difficulty intent
- variation axes
- source_map_record_id/source_basis
Finished content includes student prompt/HTML, answer/key, solution, and representation refs as required.
No placeholders or internal authoring labels in student-facing prose.

EXIT — ALGEBRA RULE
Author the exact ticket architecture from the Framework/accepted map.
Normal ticket:
- Q1-Q2 = current new mastery evidence
- Q3-Q4 = fresh parallel reassessment of previous section carryforward pair
U1.1 = four new U1-MG01 opening questions, with Q1-Q2 designated carryforward pair.
Parallel reassessment preserves evidence target + usable difficulty while varying allowed axes. Do not expose future secure parallels in ordinary Practice/Notes.

SUMMATIVE — SECURE
For Algebra, accepted map should target approximately TWO secure evidence opportunities per CURRENT Unit Mastery Goal and a complete form designed for about 40 minutes. Exact item count may vary by Unit because Mastery Goal count and task complexity vary; do not hard-code 8.
Author forms in this order:
1. V1 anchor form from current Unit Mastery Goals + Exit evidence blueprint.
2. V2-V4 parallel forms preserving blueprint/evidence/difficulty with fresh secure instances.
3. V5-V6 additional secure forms under the same blueprint/comparable rigor after V1-V4 are complete.
All forms must be independently usable and secure. Do not create pseudo-parallels by noun swaps or trivial number changes when the map requires deeper variation.
Verify each finished form still fits the accepted approximate 40-minute demand.

PRACTICE 1 — ALGEBRA RULE
Author the accepted Practice 1 map exactly:
- 24 questions per section
- 8 Intro
- 8 Review
- 8 Mastery
- visible stage grouping
Intro practices current learning.
Review practices the exact current Review goal at Review demand.
Mastery practices current Mastery goal independently and is informed by Exit evidence without copying secure Exit prompts/stimuli.
Within each block, purposeful repetition is allowed and preferred over filler. Do not manufacture fake structure variety or mechanical equal-I-Can quotas.
Practice 1 may use canonical Seeds when the map routes them.

WTC
Author the accepted connected multipart routine. Keep one coherent stimulus/representation and real carry-forward. It is instructional preview/decomposition, not disguised secure assessment. Materialize every required representation/response surface named by the map.

SEEDS
Store mapped seed records in a reusable non-student-facing slice. Seeds have NO quota. A seed should preserve the useful idea and variation guidance, not force a final prompt/answer unless the map separately defines a finished canonical question. Do not add filler seeds during 3b.

REPRESENTATIONS
Generate/copy only mapped executable representations. Graphs use registered graph tooling when required; small data tables use semantic HTML; student-constructed representations use answer-neutral response surfaces. If a task requires graph + table, render both. No decorative figures for quota.

BANK OUTPUT / MANIFEST
Build one complete replacement Unit Bank with:
- BANK_MANIFEST.json
- ITEM_INDEX.json
- destination slices exactly as declared by accepted MAP_MANIFEST
- figures/assets actually used
- provenance/build report
- teacher inspection HTML when current profile/renderer requires it

BANK_MANIFEST final state:
  status = COMPLETE
  ready_for_downstream = true
  pending = []
  qa_status = PASS
It must list exact canonical paths for every authored destination and record the accepted Map fingerprint/current profile identity.
Do not require legacy capability tokens that refer to retired Practice 2/3, CYU, Warm-Up, or Notes-pair Bank phases unless a current non-Algebra course profile still uses them.

ITEM_INDEX
Index every canonical Bank record exactly once and no retired/stale record. Provide exact destination/path/key and security/record mode needed by downstream builders.

FINAL CANONICAL QA — HARD
[ ] authored record count equals accepted Map record count
[ ] only current profile canonical destinations authored
[ ] exact goal/I-Can/stage identities preserved
[ ] Question Structure executed semantically for every finished question unless explicit current exemption
[ ] no fake multi-step/error-diagnosis/construction-vs-read-only mismatch survived authoring
[ ] all answers/solutions/math correct
[ ] all required representations accurate, legible, answer-neutral where required, and ALL refs/routes resolve
[ ] Exit chain matches Framework map
[ ] Summative V1-V6 satisfy accepted blueprint, ~2 evidence opportunities/current Mastery Goal target, ~40-minute form demand, and security rules
[ ] Practice 1 = exactly 24 per section = 8 Intro + 8 Review + 8 Mastery and no secure prompt leakage
[ ] WTC coherent and instructional
[ ] Seeds reusable, no quota/filler, and clearly separated from finished questions
[ ] no placeholders/internal labels in student content
[ ] ITEM_INDEX reconciles
[ ] BANK_MANIFEST status COMPLETE / ready_for_downstream true / qa_status PASS

If any HARD check fails, repair or FAIL CLOSED. Do not claim COMPLETE.
