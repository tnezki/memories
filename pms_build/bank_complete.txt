MATH RENDERING — ALGEBRA HARD
Student-facing algebraic notation in HTML must use TeX rendered by MathJax when MathJax improves readability. This includes powers, fractions, radicals, function notation, inequalities, systems, and multi-term algebraic expressions.
- Keep student_text as readable plain text for search/indexing.
- In student_html, wrap inline math in \\( ... \\) and display math in \\[ ... \\].
- Use ONLY \\( ... \\) / \\[ ... \\] delimiters in the viewer. Do NOT register $...$ as an inline MathJax delimiter because ordinary currency such as $5 must remain ordinary text.
- Prefer TeX such as \\(2a-a^2\\), \\(f(x)=3x-2\\), and \\(\\frac{y_2-y_1}{x_2-x_1}\\) rather than raw caret notation or Unicode superscripts when rendered HTML is available.
- Render the algebra where it naturally appears in the sentence. If the complete expression/equation is already present in the prompt, do NOT repeat that same expression in a second standalone math block merely to make MathJax render it.
- A separate display-math/reference block is allowed only when it has a real visual/instructional job: a large system, a formula that must remain visible across parts, a supplied equation separate from prose, or another genuinely useful reference object.
- Do not turn ordinary prose, labels, simple integers, or table headings into unnecessary MathJax.
- unit{unit}.html must load MathJax and re-typeset after dynamically rendering/changing tabs, filters, or search results.
- A math block that visibly exposes unrendered TeX delimiters/caret syntax in the GitHub Pages viewer is a render defect.
- A prompt that repeats the same full algebraic expression immediately below itself with no instructional purpose is a render/content defect.

- A four-family item that lists linear, quadratic, exponential, absolute-value and renders A=linear, B=quadratic, C=exponential, D=absolute-value is invalid because the layout gives away the matching order.

GRAPH MARKUP COMPLETENESS — HARD
The prior QA mistake to avoid: counting only records that already declared graph_tool while ignoring extra improvised graphs embedded in student_html.
- Scan EVERY finished student_html record for coordinate/function/modeling graph markup, regardless of representation metadata.
- Any graph-like inline <svg>, <canvas>, hand-built axis/grid markup, or other improvised plot must be reconciled to the accepted representation route.
- For Algebra coordinate/function/modeling graphs, a graph-like inline SVG such as <svg class="graph"> is NOT an acceptable substitute for the registered graph-tool asset.
- Semantic non-graph SVG is allowed only when the accepted route explicitly calls for it, such as an accessible mapping/diagram representation.
- If representation_mode says table+equation but student_html contains a coordinate graph, that is BOTH a representation-content mismatch and an unauthorized graph substitution.
- Render QA graph_tool_expected_count must be derived from the accepted routes PLUS a full scan of finished graph-bearing content; unexpected graph markup cannot escape the denominator.

Graph routing rules:
- Standard algebra/coordinate graphs: create a square figure (normally 3.5 in × 3.5 in), invoke make_standard_graph, preserve its axes, arrows, tick/grid treatment, and native aspect ratio in HTML. Do not stretch the image with CSS.
- Context/modeling graphs: invoke make_context_graph with natural bounds/labels. Preserve the generated asset's native aspect ratio; do not distort it to fill a card.
- Blank coordinate response surfaces: generate the blank coordinate plane through the registered graph tool (for example make_standard_graph with no answer-bearing function) and keep it answer-neutral.
- Discrete relations/point sets: use the registered graph-tool coordinate-plane styling, then plot the supplied points as POINTS ONLY in the appended generation block. Do not connect discrete points with line segments.
- Continuous relationships: if the mathematical object is a continuous linear/function relationship, render the continuous relationship/curve. Do not make it look like a discrete data set by showing only oversized sample dots connected by segments unless those sampled points are themselves the evidence job.
- A graph of a relation used for function/not-a-function evidence must preserve whether the relation is discrete or continuous; never connect points merely because they share a pattern.

ANSWER-NEUTRAL GRAPH STIMULUS — HARD
A supplied graph may contain the mathematical relationship/data needed to solve the question, but it must not add a visual cue that directly marks the feature the student is being asked to identify.
- Do not add an isolated dot, callout, annotation, special color, label, halo, arrow, or other emphasis to an intercept when the question asks students to identify/interpret that intercept.
- Apply the same rule to vertices, extrema, intersections, zeros, endpoints, specific coordinates, slope triangles, or other answer-bearing features.
- Example: for "Identify the y-intercept and interpret it as a starting amount," draw the relationship normally; do NOT place a special dot on the y-intercept.
- Natural discrete data points are allowed when the point set itself is the required stimulus. The prohibition is against extra answer-revealing emphasis, not legitimate data.
- A marker may be used when the marker itself is a given datum the student must use for a different task and does not reveal the requested answer.
- Student-construction response surfaces must contain no completed mathematical answer.

Graph legibility rules:
- Standard coordinate-plane grid cells must remain visually square; x/y axes must be visible and distinguishable from grid lines according to the registered tool.
- Axis/tick labels must be readable without crowding or duplication.
- Graphs must not be horizontally or vertically stretched by viewer/card layout.
- Every plotted, labeled, or student-required point/value must fit within the generated axis bounds with usable margin. If a WTC asks the student to plot (4,9), a response surface ending at y=6 is invalid.
- Do not clip required intercepts, vertices, endpoints, points, arrows, labels, or student construction space.
- A hand-built graph with visibly rectangular grid cells cannot pass as a registered coordinate graph merely because its surrounding card has the right width.

GRAPH TOOL FAIL-CLOSED CODES
- GRAPH_TOOL_NOT_EXECUTED: record claims graph_tool but no executed generated asset/trace exists.
- GRAPH_TOOL_SUBSTITUTED: graph_tool route was replaced by improvised inline SVG/manual graph rendering.
- UNREGISTERED_GRAPH_MARKUP: finished content contains graph-like markup that is not represented by an accepted executable graph route.
- REPRESENTATION_MARKUP_MISMATCH: representation_mode/route says one representation while finished student_html materially renders another.
- GRAPH_SEMANTIC_MODE_ERROR: discrete points were connected, or a continuous relationship was rendered as a misleading point chain.
- GRAPH_ANSWER_LEAK: a graph adds special emphasis to the feature/value the student is asked to determine.
- GRAPH_RANGE_CLIP: required evidence/construction lies outside the response/stimulus bounds.
- GRAPH_ASPECT_DISTORTION: standard coordinate graph is visibly stretched/non-square after rendering.

TABLE RENDERING — HARD
Small Algebra data/input-output tables use semantic HTML <table class="values"> and must stay compact and readable.
- Natural content width by default; do not stretch a two-column/four-row table across the whole card merely because it appears beside a graph.
- Center mathematical/numeric cell contents; keep headers visually distinct.
- Blank student-entry tables use the same compact geometry and preserve obvious blank cells.
- In graph+table or other split layouts, the graph may use the available visual area while the table keeps natural width and aligns to the top.
- Do not let generic flex rules such as .split>* { flex:1 ... } force tables to become giant panels.

Required Algebra viewer CSS behavior (equivalent implementation allowed):
  .values{border-collapse:collapse;width:auto;max-width:100%;margin:10px 0}
  .values th,.values td{border:1px solid #777;min-width:52px;padding:7px 11px;text-align:center}
  .split>.values{flex:0 0 auto;align-self:flex-start}
  .graph-img{display:block;max-width:420px;width:100%;height:auto;object-fit:contain}

Student-facing tables should not alternate randomly between giant stretched panels and tiny cramped tables when the underlying table job is the same.
