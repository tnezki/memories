WTC — DECOMPOSITION / NAVIGATION HARD CONTRACT
-------------------------------------------------
WTC is FRQ-decomposition/navigation practice, not a content-difficulty contest and not a loose preview list.

Each WTC must:
- use one shared coherent Physics stimulus/representation;
- normally contain 3–5 connected labeled parts;
- require students to actually read/use the shared stimulus/representation;
- contain at least one real dependency/carry-forward between parts;
- execute the mapped `decomposition_move_plan` / mapped WTC moves that are actually assigned to this routine;
- may use prior/current/future Physics;
- keep coverage_role = wtc_frq_practice;
- not satisfy current Unit coverage floors.

The underlying Physics may be straightforward, familiar, or from another Unit. That is often desirable because the primary learning job is entering, annotating, decomposing, and navigating a large multi-part problem. Do not inflate difficulty merely to make the WTC look rigorous. Planning/model-choice/justification is NOT mandatory in every WTC unless it is mapped for that routine.

WTC METADATA TRUTH — HARD:
After the final student-facing parts are authored, derive `wtc_frq_focus`, `variation.realized`, DOK/Bloom, and similar descriptive metadata from what the student actually does.
- If metadata says `select relationship/model/plan`, an actual part must require that action.
- If metadata says `justify`, an actual part must require justification.
- If metadata says `critique/revise`, an actual part must require critique/revision.
- A metadata label is never proof that the move happened.

If content is untaught, keep the navigation/unpacking work structurally accessible. Straightforward content is not itself a defect.
