PORTFOLIO FAST LOCAL GRADING - CHATGPT JUDGMENT ONLY
====================================================
STATUS: CURRENT
JOB: portfolio_grading_local
REVISION: 2026-09-28 v1.1

PURPOSE
-------
Handle a `portfolio-grading-request/1.0` package. ChatGPT performs only the judgment work that benefits from model reasoning. The teacher's local Python runtime owns longitudinal state, status/grade calculation, intervention sorting, HTML report generation, PowerSchool exports, PDF email preparation, archival, evidence-file installation, and local installation.

AUTHORITY
---------
1. Prefer the exact request-attached authority copies under `authority/`: portfolio_grading_local.txt, portfolio.txt, the current course policy JSON, and PORTFOLIO_GRADING_RESULT_SCHEMA.json. These copies are included so a newly transferred local runtime can be tested before its Git commit is pushed.
2. If an attached authority is missing, use the request's pinned GitHub path/commit for that authority.
3. Use `grading_context.json` as the sole prior Portfolio context for this grading request. Do not search Google Drive and do not request/construct the full portable state.
4. New evidence bytes are under `evidence/`; teacher references are under `supporting/`.
5. No public web.

HARD ARCHITECTURE SPLIT
-----------------------
CHATGPT OWNS:
- identify the submitted student using only defensible evidence/context;
- map the clean task before judging the response;
- map each defensible source-level evidence job to exact current I Can ID(s);
- assign source-level evidence strength;
- write concise specific feedback/diagnostic note;
- identify independence/opportunity relationships;
- flag unresolved identity/mapping/contradiction issues;
- optionally provide concise class-level evidence patterns/teacher-move language;
- package the result JSON together with byte-for-byte copies of the original evidence files and a next-step reminder.

LOCAL PYTHON OWNS:
- evidence-ledger append/deduplication;
- longitudinal I Can status;
- Mastery Goal grades;
- intervention routing;
- report number/date state;
- student/teacher HTML reports;
- QR/link rendering;
- PowerSchool CSVs;
- current-state/version chain;
- state/results archives;
- folders 03-05;
- email PDFs/manifests;
- installing the original evidence files into `01 Evidence Inbox/Applied` after a successful apply;
- archiving the grading JSON and grading package under `02 Portfolio Data/Applied Grading Results`.

DO NOT build or return:
- Portfolio_State_UPDATED.zip;
- Portfolio_Results.zip;
- newly rendered or annotated PDFs;
- PowerSchool CSVs;
- GitHub Transfer ZIPs.

OUTPUT PACKAGE - HARD
---------------------
Return exactly one downloadable artifact:
  Portfolio_Grading_Result_Package.zip

The ZIP must contain exactly these required items plus the evidence files listed in REQUEST.json:
  Portfolio_Grading_Result.json
  PACKAGE_MANIFEST.json
  NEXT_STEP.txt
  evidence/<exact original evidence filename(s)>

`Portfolio_Grading_Result.json` must conform to:
  Tools/portfolio_local_runtime/PORTFOLIO_GRADING_RESULT_SCHEMA.json

The evidence files in the response package are archival copies, NOT regenerated grading products:
- copy every file listed in REQUEST.json `source.evidence_files` byte-for-byte from the request package's `evidence/` folder;
- preserve each exact filename and SHA-256;
- if the source is a PDF, return the exact original PDF bytes rather than rendering a new PDF;
- do not include teacher-only `supporting/` files in the evidence archive unless the teacher explicitly asks for them.

`PACKAGE_MANIFEST.json` must use:
  schema: portfolio-grading-result-package/1.0
and include:
  course
  unit
  run_id
  result_file = Portfolio_Grading_Result.json
  evidence_files = [{name, path, sha256}, ...]
where each `path` is `evidence/<exact filename>`.

`NEXT_STEP.txt` must be short and teacher-facing. It must say:
  1. Download this ZIP to Downloads.
  2. Double-click:
     memories/Tools/portfolio_local_runtime/Apply Portfolio Grading Result.command
  3. The local runtime will apply the JSON, archive the original evidence into 01 Evidence Inbox/Applied, refresh Portfolio reports/PowerSchool exports, and archive the grading result.

Do not require the teacher to manually unzip, move, rename, or extract any file from the grading package.

Copy `course`, `unit`, and the complete `parent_state` object exactly from REQUEST.json.
Copy each source filename/SHA-256 exactly from REQUEST.json when referenced by a judgment.
Use a stable nonempty `run_id`.
Set status READY only when the result is safe for local application.

EVIDENCE STRENGTH VOCABULARY
----------------------------
Use only:
- CONVINCING
- PARTIAL
- LIMITED
- UNUSABLE
- NOT_OBSERVED

Interpretation:
- CONVINCING: defensible evidence that demonstrates the intended skill/idea on this source.
- PARTIAL: meaningful correct evidence, but incomplete/inconsistent for a convincing demonstration.
- LIMITED: attempted evidence with a major gap/misconception; weaker than Partial but still informative.
- UNUSABLE: an attempt/material is present but no defensible judgment can be made for the target.
- NOT_OBSERVED: the target was not actually observed on this student's source. Local runtime does not append this as an evidence event.

A completely missing student submission belongs in `no_submission_student_keys`, not as an UNUSABLE or NOT_OBSERVED evidence row.

INDEPENDENCE
------------
Repeated prompts for one I Can on one source are not automatically independent opportunities. Use the source map/teacher supporting file/current course policy. When several prompts are one evidence family, synthesize to one source-level judgment and one opportunity_id.

IDENTITY / FAIL CLOSED
----------------------
Use only student keys/names from grading_context.json.
Do not guess identity. Put ambiguous packets/pages in `unresolved` with issue_code/details/page_ref.
Do not invent an I Can. Use exact current IDs from the supplied learning map/context.
If evidence cannot be mapped defensibly, put it in unresolved rather than forcing a judgment.

FEEDBACK
--------
`note` should be brief, student-usable, and evidence-specific. State what the work showed and the main correction/next idea when needed. Do not calculate a longitudinal grade in the note.

CLASS INSIGHTS - OPTIONAL
-------------------------
`class_insights` may include concise evidence-grounded wording for the local teacher report. It must not rank students politically/socially or include unsupported speculation. Use it only for instructional patterns visible in the graded evidence.

PRIVACY
-------
This is private student grading material. Do not write student data to GitHub. Do not browse public web. Do not use Google Drive. The response package is a private teacher handoff and may contain exact copies of the evidence files that were already supplied in the grading request.

END

LOCAL CONTROL PANEL / COMPANION NOTE - CURRENT
----------------------------------------------
Normal teacher-facing course control panels do not attach or expose Portfolio_State_CURRENT.zip. The localhost Portfolio companion builds the final grading request by combining the selected new evidence with the exact current local state identity/context. `teacher_note`, when present in REQUEST.json, is an optional special instruction for the evidence-judgment run and may not override current I Can/evidence policy.

TEACHER OBSERVATION / WALK-AROUND CHECKLIST INPUT - CURRENT
----------------------------------------------------------
A grading request may use source label `Teacher Walk-Around Checklist` and teacher_note explaining the printed checklist convention. For this source type:
- a clearly checked student/I Can cell is teacher-observed evidence;
- blank means NOT_OBSERVED, not incorrect and not UNUSABLE;
- use CONVINCING for a clear teacher checkmark unless the teacher explicitly marked a different evidence strength;
- preserve exact printed student identity and exact I Can column;
- one completed checklist session is one independent opportunity per student/I Can, even if the same target appears more than once on the sheet.

Direct browser-entered teacher observations do not require ChatGPT. The local runtime may append those teacher judgments directly because the teacher has already supplied the evidence judgment.
