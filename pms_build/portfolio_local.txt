PORTFOLIO / ASSESS NEW EVIDENCE - PORTABLE LOCAL STATE WORKFLOW
===================================================================
STATUS: CURRENT
JOB: portfolio
REVISION: 2026-09-23 v5.1 - PORTABLE LOCAL STATE + RESPONSIVE DIGITAL STUDENT REPORT

PURPOSE
-------
Run the existing Portfolio evidence/grading/report workflow without a normal Google Drive dependency. The teacher keeps private longitudinal Portfolio state under a local `_portfolio_data` folder and transports that folder between computers by USB. Each request carries one authoritative `Portfolio_State_CURRENT.zip` plus only the new evidence/support/roster files needed for the run.

This PM is a STORAGE / DELIVERY / EXECUTION overlay on `pms_build/portfolio.txt`.

HARD PRECEDENCE
---------------
1. Read `pms_build/portfolio.txt` for evidence interpretation, I Can status, Mastery Goal grades, intervention routing, PowerSchool exports, privacy, and teacher-report content.
2. Read `Tools/portfolio_local_state/PORTFOLIO_LOCAL_STATE_CONTRACT.json`.
3. Read `Tools/templates/portfolio/PORTFOLIO_TEMPLATE_CONTRACT.json` and the registered Portfolio templates/CSS.
4. Apply THIS PM last for state authority, storage, migration, execution speed, delivery, and local-mode report QA.
5. Any Google Drive persistence/readback requirement in the base PM is superseded except during an explicit one-time migration request.
6. Any base-PM requirement that the STUDENT report print as exactly two physical pages is superseded in portable-local mode. The canonical student report is responsive digital HTML and has no fixed print-page budget.
7. Do not weaken grading, identity, privacy, teacher-report intervention rules, or template-fidelity requirements.

===========================================================
0. NORMAL AUTHORITY / NO-DRIVE RULE - HARD
===========================================================
Normal portable-state runs use only:
- the current request/current teacher instruction;
- request attachments;
- exact pinned project GitHub authorities;
- the attached `inputs/current_state/Portfolio_State_CURRENT.zip`.

Do NOT search Google Drive, list Drive folders, fetch Drive state, upload to Drive, or verify Drive persistence on a normal portable-state run.

Google Drive is allowed ONLY when the request explicitly sets:
  migrate_from_google_drive = true

That migration is one-time input recovery only. Read the exact canonical private Portfolio state, convert it to the portable-state schema, and thereafter continue entirely from the returned portable state. Do not write the migrated/updated state back to Drive unless the teacher explicitly asks for a separate backup action.

No public web. Student data is never written to GitHub.

===========================================================
1. PORTABLE STATE INPUT - HARD
===========================================================
Normal run input path:
  inputs/current_state/Portfolio_State_CURRENT.zip

The ZIP root must contain:
  STATE_MANIFEST.json
  state/

Before using state:
1. SHA-256 the uploaded state ZIP and require exact match with `REQUEST_MANIFEST.json -> portable_state.input_state_sha256`.
2. Validate manifest schema `portfolio-portable-state/1` and status CURRENT.
3. Validate exact course and unit against the request.
4. Verify each listed internal state file hash.
5. Refuse malformed/cross-course/cross-unit state with `PORTFOLIO_STATE_INVALID`.

The state ZIP is the sole prior-state authority for the run. Do not merge it with stale chat files, Library files, another ZIP, or Drive state.

FIRST RUN / RESET:
- No prior state ZIP is required.
- A current roster/template source is required as in the base PM.
- Output state_version = 1 and parent_state_sha256 = null.

ONE-TIME DRIVE MIGRATION:
- No prior state ZIP is required.
- Read the existing canonical Drive Unit state once.
- Preserve current evidence/history/roster/support state in portable form.
- Output state_version = 1 and source_mode = `drive_migration`.
- Do not require Drive on later runs.

===========================================================
2. STATE CONTENT / DEDUPLICATION
===========================================================
The portable ZIP contains WORKING LONGITUDINAL STATE, not the entire raw evidence archive.

Preserve all legitimate parent-state files, including at minimum:
- student_registry.csv
- evidence_ledger.csv
- i_can_status_current.csv
- mastery_goal_status_current.csv
- unit_status_current.csv
- class_i_can_summary.csv
- intervention_groups.csv
- review_queue.csv
- run_history.csv
- run_manifest.json
- stored PowerSchool schema/template files needed to reproduce exports
- current normalized student-support/contact/email state already present

Historical raw scans/PDFs/images do NOT need to be copied into every state ZIP. Durable source filename/hash/date/label/mapping/judgment remains in the ledger.

For every newly supplied evidence file, hash BEFORE expensive interpretation. If the exact source hash is already represented in the evidence ledger, do not duplicate or re-grade it by default.

===========================================================
3. STATE-CHANGING RUNS
===========================================================
For genuinely new evidence, roster changes, or explicitly supplied student-support updates, follow the base PM and current course policy exactly for:
- identity;
- clean-task mapping;
- evidence strength;
- independence;
- I Can status;
- Mastery Goal grade;
- intervention routing;
- PowerSchool output.

Every successful state-changing run returns:
  Portfolio_State_UPDATED.zip

Its STATE_MANIFEST must:
- keep schema `portfolio-portable-state/1`;
- set status CURRENT;
- match exact course/unit;
- increment parent state_version by exactly 1, or use 1 for first/migration state;
- set parent_state_sha256 to the exact uploaded current-state ZIP hash for normal runs;
- set a new nonempty state_id and run_id;
- record generated_at and source_mode;
- list every internal state file with exact SHA-256.

===========================================================
4. REPORT-REFRESH-ONLY RUNS
===========================================================
A request may set:
  refresh_reports_requested = true
  report_refresh_only = true
  state_change_expected = false

For this mode:
- validate and read the current portable state;
- do not manufacture a new evidence event;
- do not alter grades/status merely because reports were requested;
- do not increment state_version;
- do not create `Portfolio_State_UPDATED.zip`;
- return `Portfolio_Results.zip` only.

===========================================================
5. RESPONSIVE DIGITAL STUDENT REPORT - HARD
===========================================================
Portable-local student reports are DIGITAL HTML first. The teacher no longer requires an exact physical print-page count.

Use the exact canonical current files:
- Tools/templates/portfolio/student_packet_template.html
- Tools/templates/portfolio/portfolio.css
- Tools/templates/portfolio/PORTFOLIO_TEMPLATE_CONTRACT.json

The canonical student report is one continuous responsive `student-report` article containing:
- Current Progress Report;
- Essential Standard;
- Your current picture;
- Mastery Goal snapshot;
- Unit Evidence Picture with every current MG and every current I Can exactly once;
- Recent evidence;
- Your Practice.

HARD DIGITAL FIT RULES:
- required content may grow vertically;
- no hidden/clipped required content;
- no artificial font shrinking merely to hit a page count;
- no requirement for 2 physical pages;
- desktop view uses the canonical balanced two-column Mastery Goal flow;
- narrow screens collapse to one column;
- combined class_student_packet.html contains one complete student-report article per active student in roster order.

Do not re-author a Physics-specific shell. Physics Unit 1 with 19 I Cans uses the same responsive canonical student report as other courses.

===========================================================
6. TEACHER REPORT - STILL LOCKED
===========================================================
The teacher report remains governed by the base PM/course policy/template contract:
1. Class Overview
2. Whole Class only when supported
3. Priority Day Groups - max 2 groups, max 15 students/group
4. Pull In Students - one page

Do not add the normal detailed-evidence appendix or the forbidden `Brief guided practice` lane.

===========================================================
7. FAST LOCKED-TEMPLATE EXECUTION - HARD
===========================================================
A. READ ONCE
- Fetch each exact pinned GitHub authority/template at most once per run unless a read failed.
- Unpack/validate the current state ZIP once.
- Do not repeatedly reconstruct/refetch/re-hash the same canonical files.

B. BATCH DETERMINISTIC WORK
Use one programmatic local pipeline when possible for deterministic work:
- unpack state/request files;
- hash evidence and state files;
- update CSV/JSON longitudinal state when required;
- generate all student HTML from the canonical student template;
- generate the locked teacher HTML;
- generate current Mastery Goal PowerSchool CSVs;
- run identity/count/link/template-provenance checks;
- run `Tools/templates/portfolio/verify_portfolio_output.py` once on the completed results tree;
- build required ZIP artifact(s);
- compute final SHA-256 values.

C. VISUAL QA
Normal output remains HTML; PDFs are not returned.
- For student reports, verify responsive structure/content completeness programmatically and visually inspect only representative browser-rendered outliers when needed.
- Do NOT render student reports to PDF to enforce a page count.
- Teacher report pagination/fit QA remains in force because its intervention pages are intentionally fixed.

===========================================================
8. RESULTS DELIVERY
===========================================================
When refresh_reports_requested=true, return:
  Portfolio_Results.zip

It contains the exact current results structure from the template contract/base PM:
- results_manifest.json
- student_reports/class_student_packet.html
- student_reports/individual/<stable-student-key>.html
- teacher_report/teacher_summary.html
- powerschool/<current MG CSVs>
- QA/provenance files as required

No normal-run PDFs. No overall Unit-grade CSV. Do NOT wrap private Portfolio outputs in a GitHub Transfer ZIP.

Template fidelity remains HARD:
- embed exact canonical CSS bytes in each self-contained report;
- record template/CSS/contract hashes and pinned SYSTEM commit;
- run the current template validator before PASS.

===========================================================
9. LOCAL STORAGE HANDOFF
===========================================================
ChatGPT does not directly write the teacher's local `_portfolio_data` folder.

The local installer owns placement under:
  <GitHub root>/_portfolio_data/<Course>/unit N/

The installer may archive/install:
- Portfolio_State_UPDATED.zip when state changed;
- Portfolio_Results.zip when reports were refreshed;
- results-only refreshes without changing current state.

The entire `_portfolio_data` folder is private and must NEVER be initialized as a Git repository or included in Git commits/transfers. The teacher may manually copy `_portfolio_data` to/from USB between computers.

===========================================================
10. PASS / FAIL
===========================================================
A portable-state Portfolio run may say PASS/Completed only when applicable checks pass:
- input state integrity/course/unit;
- evidence deduplication/mapping/judgment;
- longitudinal state coherence when state changed;
- student report contains all required current MGs/I Cans with no clipping/hidden required content;
- no fixed student print-page count is enforced;
- teacher report intervention structure/fit;
- stable student identity mapping;
- current PowerSchool MG exports;
- canonical template provenance and validator PASS;
- required output ZIP(s) built and hash-verified.

There is NO normal Google Drive persistence/readback requirement in portable-state mode.

Failure codes include:
- PORTFOLIO_STATE_REQUIRED
- PORTFOLIO_STATE_INVALID
- PORTFOLIO_STATE_COURSE_UNIT_MISMATCH
- PORTFOLIO_STATE_CHAIN_ERROR
- PORTFOLIO_TEMPLATE_DRIFT
- PORTFOLIO_RESULTS_BUILD_FAILED

END
