3. QUICK CHECK WORKFLOW - HARD
There is one common four-question Quick Check per section evidence event. Normal owner entry is the LOCAL non-repository tool:
  _algebra_teacher_tools/tools/quick_check/quick_N.html
The shared Algebra Teacher Dashboard links finished Quick Check products through:
  quick_check____htq5855/library.html?unit=N
and must not expose the builder/selector.

The teacher approves four source question architectures/anchors and may add a fine-tuning note. Portfolio need may guide reassessment recommendations; teacher selection is final.

APPROVED QUICK CHECK HISTORY - HARD
Approved Quick Checks are append-only history, not one replaceable file per section.
- Preserve the existing approved files already present in a section root.
- Every new makeup/alternate/corrected/later build receives a unique run folder under:
    quick_check____htq5855/quickN/approved/quick_N_S/runs/<run_id>/
- Each run owns its HTML, 8-page PDF, and JSON lineage/source map.
- Append the run to quick_check____htq5855/library.json.
- Never overwrite or delete an earlier approved run merely to create a new version for the same section.

Four versions A-D inside one run use the same four approved source architectures. Normal version differences are safe family-authorized number/value/data swaps, deterministic question-order scrambling, and answer-choice scrambling when applicable.

Every printed question visibly shows:
  <exact I Can code> — <full exact I Can statement>

4. PERSONALIZED CHECKPOINT WORKFLOW - HARD
Checkpoint is a COURSE-LEVEL OWNER tool at:
  _algebra_teacher_tools/tools/checkpoint/checkpoint_builder.html
It selects one Unit and a student scope. Actual personalized runs resolve current private Portfolio state just in time and remain private.

The shared Teacher Dashboard may show a green Checkpoints product-library button:
  checkpoints___trmn78/library.html?unit=N
but that shared library may contain only intentionally published non-student-specific finished Checkpoint products. Student names, Portfolio status, personalized plans, and private source maps never enter the shared library.

Default personalized Checkpoint length is six questions/student. Portfolio decides what evidence is useful now; the reviewed selected Unit Bank supplies approved question-family architecture. Family letters are stable IDs only and do not encode universal A/B/C roles.

When a family supports safe deterministic/seeded generation, prefer that route and record the seed/parameters. Otherwise author a fresh reviewed instance from the approved family contract. Do not invent a new architecture when a suitable approved family exists.

Every question visibly shows exact I Can code + full exact statement. Every private run saves checkpoint_source_map.json with exact I Can/family/evidence/prompt/parameters/verified answer/opportunity lineage.

5. EVIDENCE-SOURCE MAPPING - HARD
Map the clean task before judging handwriting. Printed question number is not authority when versions shuffle or personalized Checkpoints differ by student. Repeated questions for one I Can on one Quick Check/Checkpoint may strengthen one source judgment but do not automatically become multiple independent opportunities.

6. BANK ROLE
Current Algebra Bank:
  Mastery Goal -> exact I Can -> high-quality approved family pool.
There is no current three-family A/B/C limit. Existing family letters remain stable IDs only. Current family-count/generator rules are owned by Framework v8.1 and profiles/bank_course_profile.json.

7. REPORT FIDELITY / PROGRESS DISPLAY
Use the registered Portfolio template plus the shared Portfolio Progress Model. Recurring headings, report anatomy, progress labels, MG status boxes, and page-2 structure are template/contract owned. Fill declared slots; do not redesign reports per run.

- five-segment progress bar + short status word on each I Can;
- no visible per-I-Can Next line;
- one equal-size MG status/grade box in each MG card;
- the four most recent assessed evidence events on page 2.
