MAP-FIRST AUTHORING / REPETITION DISCIPLINE — COURSE REFLECTION
---------------------------------------------------------------
The current Curriculum Philosophy requires an explicit pre-authoring map for any multi-item / multi-section build that is authoring new learning or evidence content. In Algebra, use that map to see exact I-can coverage, evidence routes, Graph / Equation / Table / Context use, question/task families, and the actual student actions before template momentum drives the build.

Purposeful repetition remains GOOD. Repeated solve/evaluate/simplify/factor/graph/table/translate families may cluster when they serve fluency, retrieval, repeated evidence, or a high-value representation. Do not impose anti-repetition quotas and do not maximize surface variety.

The map should expose ACCIDENTAL repetition caused by template convenience: the same reasoning suffix, question shell, experience sequence, representation choice, or student action repeated across unrelated learning jobs because it was easy to render. Ask what mapped learning/evidence purpose the repetition serves. If the purpose is real, keep it. If it is only a template byproduct, revise the PLAN before authoring final resources.

This map-first review is PRE-AUTHORING quality design, not a late anti-clone/diversification pass. After authoring, repair actual defects; do not cosmetically rewrite good repeated mathematics merely to make counts look more varied. See `contracts/map_first_repetition_contract.json`.

Current Algebra Notes philosophy:
- Exact Assessment Plan Learning Targets and I-can statements are the instructional spine. A section is not a
  generic textbook chapter; its reading, representations, Math Notes, Examples/YTIs, and discussion revolve
  around the exact I-cans.
- The finalized Unit Bank is canonical for WTC + Notes Example/YTI prompts, values, figures, and answers. Notes
  teach around those anchors rather than rewriting them or creating a second Notes question bank.
- Algebra Notes are primarily current-learning instruction. Review/Mastery appears only when it genuinely supports
  the current I-can or a canonical Bank anchor.
- After the WTC and pre-reading setup, organize main content into visible I-can instructional clusters in
  Assessment Plan order. Within a cluster, reading/representation, discussion, Math Notes, and canonical EX/YTI
  interleave naturally rather than following a rigid pair-by-pair template.
- Algebra instructional reading uses a Conceptual-Physics-like voice: mature, concrete, direct, explanatory, and
  relationship-focused. A normal substantial reading is usually 3–4 developed paragraphs; a little more is
  better when it genuinely improves understanding. Do not write thin blurbs merely to get to the problem.
- Bold a target vocabulary/notation term the FIRST time it is meaningfully introduced or defined in the reading.
  Do not bold every recurrence.
- EVERY substantial reading is followed immediately by Stop and Discuss. The main S&D is 2–3 questions: 1–2
  direct/text/vocabulary/representation questions plus the remaining conceptual/inferential question(s). Later
  in the same I-can cluster, a useful S&D checkpoint is normally ONE focused conceptual question. Do not attach
  S&D automatically after every Example/YTI.
- Useful Math Notes abundance is desirable. CPM-style Math Notes are substantive references, not tiny labels:
  show the actual mathematics, explain meaning, and include worked/reference connections when useful. For an
  I-can involving multiple representations, actively look for opportunities to show Graph + Equation + Table +
  Context together around one coherent relationship. The teacher can skip blocks live.
- Show actual Algebra: equations, tables, graphs, number lines, area models, algebra tiles, function comparisons,
  and contexts when they add meaning. Graph / Equation / Table / Context remains the representation system; no
  decorative quota.
- Canonical Bank content keeps its mathematics, but Notes presentation wrappers are mandatory: every graph uses
  `<figure class="notes-graph">` so the 2.52in max-size rule fires; simple two-column task tables use
  `compact-table` with two `half-col` columns so they stay centered, compact, and 50/50. Do not emit bare
  full-width x/y tables when this compact structure fits.
- Do not add visible graph figcaptions or decorative graph titles. Preserve only mathematically necessary axis
  labels, units, ticks, legends, or other labels/data required to interpret the graph. New Notes-specific graph
  calls normally use a blank title.
- Reading Apprenticeship supports sense-making: vocabulary sort, skim/notice-predict-wonder, close-read/annotate,
  discuss meaning/evidence, then apply.
- Current Algebra opening sequence is Learning Target/I-can overview -> Vocabulary / Key Notation Preview + sort ->
  What's to Come -> Let's Get Started Notice/Predict/Wonder skim -> close-reading directions -> I Can 1.
- Notes are Notability-first. Current Algebra visual defaults and wrappers live in
  `contracts/notes_visual_contract.json`; the approved pilot layout is preserved in
  `reference_library/notes_layout/`.
- The approved Unit 1 typography/scale pilot is now the Algebra Notes visual baseline: normal prose/list/table
  text is 9pt, Example/YTI and I-can headings are 13pt, major Learning/Vocabulary/Summary/Mistakes headings
  are 18pt, the title-card scale follows the visual contract, and graphs max at 2.52in x 2.52in. Preserve
  the stronger 20pt What's to Come / Let's Get Started section-heading treatment.
- Student Notes remain clean. Teacher Notes are a copy of the finalized student file with red/bold teacher support
  added only inside existing workspaces. Main S&D teacher support includes direct answers + acceptable inference
  reasoning + evidence to listen for; later one-question checkpoints name the intended insight.
- Notes end with Summary + Common Mistakes, followed by the Framework-defined blank miscellaneous workspace. No
  embedded Exit Ticket / Notes Exit Check and no Summary workspace in the current Algebra layout.
- Production HTML still links exactly base.css then notes.css. The layout reference is NOT a third production
  stylesheet; it records the approved rules to merge/preserve in the course-level notes.css.


ALGEBRA TEACHER-GUIDE DISCOURSE PROFILE — HARD
----------------------------------------------
Meaningful discourse is embedded in instructional TEACHER guides where it helps the teacher
facilitate the exact mathematics being learned. It is not a separate student resource.

Compact teacher-guide format:

  Discourse Moves
  Teacher Moves
  - 2–4 short, content-specific bullets
  Student Moves
  - 2–4 short, content-specific bullets

Teacher move families:
- wait / give think time
- invite more than one strategy, observation, or conjecture
- revoice a student idea without taking ownership of it
- ask another student to restate/rephrase the reasoning
- probe for why / how / evidence / representation
- ask students to compare, agree/disagree, challenge, or build on another idea
- connect student approaches, representations, claims, or observations

Student move families:
- explain
- clarify
- restate / summarize
- compare
- support with evidence
- build on
- question / challenge mathematically

HARD:
- Tailor the bullets to the exact I-can / task phase / representation / likely misconception.
- Do not paste the same generic list repeatedly.
- Keep the block short enough to function as a live-teaching reminder.
- The teacher can skip/adapt moves live; this is support, not a script.
- Student-facing files remain clean.

PLACEMENT:
- Notes teacher copy: ONE compact block for EACH visible I-can instructional cluster. Put it
  after the most useful Math Notes / diagram / representation for that I-can when possible.
  STUDENT Notes retain fixed Notability workspaces. TEACHER Notes release fixed heights and
  expand naturally so answers/discourse push later content downward and never overlap.
- Activity Options hub: do NOT place discourse blocks inside each individual activity.
  Instead, place ONE teacher-facing `Teacher & Student Moves Guide` immediately after the
  activity index. The guide has:
    1. one compact Teacher Moves / Student Moves entry for each section I-can; and
    2. compact participation-structure entries for the activity formats that need distinctive
       facilitation (for example Stations, Find Someone Who, Rally Coach, Showdown, Speed
       Dating, Think-Trade-Agree).
  After that guide, keep the individual activity directions/companions unchanged. Printable
  student companions do not get teacher discourse blocks.
- Demo teacher guide: each substantive discussion-bearing slide/step gets a block in the
  matching teacher-detail notes.
- Investigation teacher guide: each substantive lab/task phase gets a block in the matching
  teacher walkthrough.
- Performance Task teacher guide: each major discussion-worthy phase gets a block. Do not
  force discussion into independent evidence moments.
- Quick Checks, Practice, Warm-Ups, Exit Tickets, Progress Trackers, Reviews, Review Practice,
  and Summatives do not receive discourse coaching by default.

PLANNING:
For discussion-rich instruction, quietly plan with:
anticipate -> monitor -> select -> sequence -> connect.
Those five planning moves do not need to be printed as five headings.

TEACHER-NOTES LAYOUT EXCEPTION — HARD
- Fixed workspace heights are a STUDENT Notability contract, not a teacher-copy contract.
- Teacher Notes may use a teacher-only style override: height:auto; min-height:0; overflow:visible.
- Teacher answers + Discourse Moves must push later content downward; overlap is a hard failure.
- Do not modify deployed student notes.css to solve teacher-only overflow.
- Visible literal escape sequences such as \n, \r, or \t are final-byte defects in BOTH student and teacher HTML.

MATH NOTES / NOTES TONE
-----------------------
reference_library/math_notes/math_note_ideas.json gives section-specific Math Note ideas. They support
downstream Notes and representation planning but never replace canonical Bank Examples/YTIs or override the
Assessment Plan.

Algebra Notes/downstream resources are intentionally compartmentalized around the exact I-can structure.
Readings, explanatory notes, Examples/YTIs, representations, and Practice should make it obvious which I-can
job they serve. Reorder/clean formatting when useful, but do not blur the section into a generic textbook
chapter or preserve stale sequencing after the Framework/I-can architecture changes.

Algebra Notes prose uses the Conceptual Physics benchmark for voice: clear, mature, concrete, direct, and
conceptual, with explanations that develop relationships and why the mathematics works. A normal substantial
I-can reading is usually 3–4 developed paragraphs; a little more is better when it adds real explanatory value.
Avoid thin one- or two-paragraph blurbs and avoid dry procedure lists. Bold each target vocabulary/notation term
at its first meaningful introduction/definition, then return to normal weight on later occurrences.

Every substantial reading is followed immediately by Stop and Discuss: normally 2–3 questions with 1–2
direct/text/vocabulary/representation checks and the remaining conceptual/inferential question(s). Later in the
same I-can cluster, an additional checkpoint is normally one focused question when useful.

Math Notes should be plentiful when useful. Treat them as durable references modeled on the substantive CPM
"Methods and Meanings" role: definitions/meaning, representation connections, worked/reference examples, and
clear structural relationships. For multiple-representation I-cans, look especially for a coherent 2x2
Graph / Equation / Table / Context reference rather than merely naming the four forms.

QUESTION VARIETY / ABUNDANCE
----------------------------
Use real mathematical variety when it helps the I-can: direct skill, reverse reasoning, representation
translation, interpretation, compare/contrast, error analysis, modeling/context, create/complete a
representation, and justification. Do not force all types into every section.

For Algebra, variety is NOT the goal by itself. Within each 24-question Practice form, intentionally giving
3–5 clean versions of a high-value family can be better than inventing five different wrappers. Repeated
numeric/procedural forms are legitimate. Avoid fake variety from noun swaps, generic contexts, or stock
reasoning suffixes.

ASSESSMENT / GRADING PHILOSOPHY
-------------------------------
The original Assessment Plan is authoritative. Evidence accumulates toward Mastery
Goals. Meeting does not require perfection. Progress labels are not difficulty bands.
Exceeding can emerge through transfer/less-familiar representation/extended reasoning
rather than a mandatory trick question. Make reasoning visible when the evidence
standard requires it. DOK is descriptive, not a quota.
