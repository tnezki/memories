CURRICULUM PHILOSOPHY PORTABLE MEMORY v3.16
================================================
STATUS: PROPOSED UNIVERSAL TEACHING / LEARNING PHILOSOPHY
PURPOSE: Preserve the universal educational beliefs and authority boundaries that should shape every course without relying on prior chats, stale copies, or course-specific habits.

================================================================
READ THIS FIRST / CANONICAL AUTHORITY
================================================================

This Philosophy is the BASE layer. It owns universal beliefs about learning, instruction, evidence, teacher choice, useful abundance, representations, resource purpose, quality, authority boundaries, and controlled system improvement.

CANONICAL GITHUB RULE — HARD
The current canonical GitHub repositories are the source of truth. Local folders and generated artifacts are working/test copies until the teacher intentionally syncs approved changes. Whatever is canonical at the pinned job start is authoritative for that job.

BUILD SNAPSHOT RULE — HARD
At job start, resolve the current canonical GitHub state once and pin every required authority/resource to that starting snapshot. Do not mix authorities that changed mid-run.

FAIL-CLOSED RULE — HARD
If a required canonical authority is missing, ambiguous, or cannot be resolved, stop and identify the exact problem. Do not silently substitute an old upload, remembered rule, similarly named file, or stale embedded copy.

AUTHORITY HIERARCHY
  1. Current explicit teacher instruction for the specific job/artifact
  2. This universal Philosophy
  3. Current universal Question Structure authority
  4. Current Course Framework
  5. Current executable PM
  6. Current tool / HTML-CSS shell / renderer

A lower layer may specialize a higher layer only where the higher layer permits specialization. It may not silently contradict it. A direct teacher instruction may create a local exception; that exception stays local unless deliberately promoted upstream.

COURSE AUTHORITY RULE — HARD
The current Course Framework is the canonical course authority. It contains or resolves the approved Unit Assessment Plans exactly, including exact Learning Targets/I-can statements, mastery goals, stage architecture, and evidence architecture. Builds should not hunt for a separate competing assessment-plan authority.

PM OWNERSHIP RULE — HARD
PMs primarily own PROCEDURE: what to resolve, validate, select, assemble, audit, and output. PMs should reference current higher authorities rather than embedding competing copies of Philosophy, Frameworks, Question Structure, Banks, or maps.

CORE SENTENCE
Instruction creates opportunities to learn; assessment collects evidence; the portfolio organizes that evidence over time; and the grade communicates the best current professional judgment of what the student actually understands.

================================================================
1. BUILD FROM LEARNING ARCHITECTURE, NOT RANDOM INVENTORY
================================================================

Do not start by writing questions.

Correct sequence:
  current Course Framework + exact approved Assessment Plan
    -> exact learning targets / I-can map
    -> course-specific learning-stage and fluency architecture
    -> resource-purpose map
    -> learning progression
    -> evidence map
    -> representation plan
    -> item requirements
    -> approved Question Structure
    -> actual authored question
    -> independent verification

For any multi-item, multi-section, or multi-form build, create an explicit PRE-AUTHORING MAP before final student materials. Use it to see coverage, missing opportunities, repeated structures, representation use, evidence routes, and the actual jobs students will do. QA the map before rendering.

Predictable routine is desirable. Formulaic placement and assembly can be good. Formulaic QUESTION THINKING is bad.

Exact Learning Targets and I-can statements are the instructional spine. Readings, explanations, Notes, examples, Practice, activities, evidence, and later resources should revolve around those learning jobs rather than a generic textbook template.

================================================================
1A. COURSE LEARNING / EVIDENCE LANGUAGE AUTHORITY
================================================================

The current Course Framework and its exact Assessment Plans own the course's learning-stage language. Do not invent, normalize, or rename course-specific stage vocabulary into a universal lifecycle.

If a course uses Intro / Review / Mastery, preserve those terms and relationships exactly. If another course uses a different architecture, preserve that instead.

CANONICAL GOAL IDENTITY RULE — HARD
When a course intentionally carries the SAME goal through multiple stages, the goal ID/title/description stays stable. Stage changes the support, independence, representation, context, or complexity of the evidence—not the identity of the goal. Do not hide a spiral by casually rewording the goal at each stage.

Student-facing resource names do not define a learning stage. Resource role and stage routing come from the current Course Framework/Assessment Plan or a lower PM only when the Framework deliberately delegates that implementation detail.

================================================================
2. RICH MENU / USEFUL ABUNDANCE / TEACHER CHOICE
================================================================

The course is a rich menu of high-quality options, not a minimum viable packet or fixed calendar. The teacher may skip, shorten, substitute, combine, reorder, or spend longer on resources.

MORE CAN BE BETTER when additional material is genuinely useful. Unused high-quality material can provide differentiation, reassessment options, alternate representations, repetition, and flexibility. The guardrail is PURPOSE, not minimalism.

Abundance is course-responsive. Procedural courses may need nearby repeated execution. Other courses may gain more from changing representation, phenomenon, model, or reasoning demand.

BANK IS AUTHORITATIVE, NOT EXHAUSTIVE — HARD
A canonical Bank is a reliable reusable content/evidence layer. It does NOT have to pre-store every question that may eventually appear in every classroom artifact. The Framework/Assessment Plan remains the learning authority. Downstream builders may purpose-author or refine new instructional instances when the artifact's job calls for them, provided they do not invent new assessed content or contradict the mapped learning/evidence architecture.

A smaller authoritative Bank can be stronger than a huge repetitive inventory when its contents are well mapped and downstream resources can responsibly generate/refine classroom instances.

================================================================
3. REPETITION IS OFTEN HOW LEARNING DEVELOPS
================================================================

Repetition is not automatically a defect. Repeated execution/retrieval can build fluency, accuracy, notation/control, discrimination, conceptual strength, and confidence.

Several direct solve/evaluate/simplify/graph/classify/calculate/formula questions may be better than forcing every question into a different context or reasoning wrapper.

MAP-FIRST REPETITION DISCIPLINE
A pre-authoring map distinguishes PURPOSEFUL REPETITION from ACCIDENTAL REPETITION. Keep repetition that serves fluency, retrieval, repeated evidence, representation practice, or deliberate return to a high-value structure. Revise repetition caused only by template convenience.

Do not use anti-repetition quotas. The goal is intentionality, not maximum surface variety.

================================================================
4. EVIDENCE FIRST / HIGHEST-STAKES CONTENT
================================================================

The strongest evidence resources deserve the earliest and most careful authoring.

High-priority design areas are:
  1. Exact Learning Target / I-can / Mastery Goal mapping
  2. Explicit evidence architecture
  3. Strong Exit Tickets or equivalent short evidence pulses
  4. Strong secure Summative evidence
  5. Honest distribution of evidence opportunities over time

A course may choose to author its strongest short evidence and Summative families before filling a larger instructional Bank. This is often useful reverse planning: instruction and Practice can then be built to prepare students for already-defined evidence demands.

BANK / BANK-MAP STRUCTURE RULE
The Bank and Bank Map own the machine-readable reusable content structure required by the current course: IDs, mappings, destinations, source/parallel relationships, response modes, evidence roles, and other declared metadata. The current Course Framework decides which destinations are canonical Bank content and which are better generated downstream.

================================================================
5. REPRESENTATIONS ARE INSTRUCTIONAL CONTENT
================================================================

The Course Framework defines the representation system that matters for that discipline and Unit. Possible forms include graphs, equations, tables, contexts, diagrams, phenomena/images, data, formulas, models, number lines, experimental setups, code, or other course-specific representations.

A representation counts only when students actually read, build, use, compare, translate, annotate, or interpret it. Decorative images and metadata labels do not count as representation reasoning.

Use approved tools when they represent the intended content cleanly. Preserve editable source/provenance when useful. Reuse approved canonical representations when appropriate; create a new representation when the artifact's learning job warrants it.

================================================================
6. PRACTICE CREATES LEARNING
================================================================

Practice exists primarily to CREATE LEARNING, not to generate grades.

A good Practice resource gives students substantial productive work for the intended learning job. Useful extra material is allowed because the teacher can skip/select.

Practice may include direct repeated work, representations, conceptual/diagnostic work, partner/social structures, and deeper transfer depending on the course and target.

The canonical Bank does not have to contain every middle-Practice format. A Course Framework may keep a smaller set of canonical Practice anchors while allowing stations, matching, sorting, task cards, partner sets, whiteboards, Find Someone Who, and similar structures to be generated later from the same mapped learning architecture.

================================================================
7. NOTES / EXAMPLES / WTC
================================================================

Notes are a guided instructional pathway, not a script that must be completed top-to-bottom. Exact Learning Targets/I-cans come first; readings, explanations, representations, examples, teacher discussion, and student work revolve around those jobs.

Instructional reading should be substantial enough to teach the idea, not a thin bridge to the next problem. The Course Framework owns reading density, voice, vocabulary-preview behavior, and source style.

Vocabulary should develop in context. When a course uses a vocabulary/notation preview, the first meaningful introduction or definition in instructional prose may be emphasized without turning later recurrences into clutter.

Examples/YTI pairs are instructional anchors, not automatically permanent Bank inventory. A course may keep canonical examples in the Bank, or may generate/refine them when Notes are built, as long as they remain traceable to the mapped target and do not leak secure evidence.

WTC, when used, is a recurring FRQ-decomposition/navigation routine. Its exact content/routing is course-specific and does not automatically satisfy current-section evidence floors.

Notes should not contain a fake closing Exit Check merely for symmetry.

================================================================
7A. ACTIVITIES / INTERACTIVE PRACTICE / CUSTOM INSTRUCTION
================================================================

Activities create learning by changing participation around worthwhile content. Movement, collaboration, stations, projected team work, peer checking, hands-on measurement, modeling, simulations, and structured discussion are means, not ends.

Activities are optional instructional routes unless the Framework explicitly says otherwise. Required core learning/evidence should not accidentally disappear when an optional activity is skipped.

BANK-AS-SOURCE, NOT-PRISON RULE — HARD
When an Activity or downstream artifact uses a finalized Bank, Bank questions are reusable source material. A builder may select, group, order, adapt, rewrite, replace, or purpose-author questions when that produces a better classroom experience and remains aligned to the Framework. A local artifact improvement does not automatically change the Bank.

CUSTOM ARTIFACT RULE — HARD
Labs, investigations, projects, simulations, special activities, and other inherently custom resources may use the structure that best serves the lesson rather than a universal shell. They still must satisfy course authority, accessibility, and declared file/path contracts.

================================================================
7B. RECURRING / ASSESSMENT ARTIFACTS
================================================================

Recurring artifacts should normally use proven canonical shells for speed, consistency, and reliability. The shell owns format; the Framework owns intentional course-specific behavior; the PM owns procedure.

TEMPLATE-DRIVEN DOES NOT MEAN FROZEN
Finished classroom artifacts remain editable. The teacher may replace, rewrite, add, remove, reorder, or purpose-author content when the actual classroom artifact would be better.

USAGE MODE IS PART OF DESIGN
A projector resource should fit a viewport; a handwriting/Notability-first resource should fit writing/import geometry; a print resource should fit physical page flow; a screen study guide should fit navigation/readability.

Preserve useful hidden provenance where available without exposing authoring metadata to students.

================================================================
8. WARM-UPS
================================================================

Warm-Ups create a predictable instructional opening routine. Map their learning/retrieval job before writing them. Controlled repetition is useful.

COURSE-SPECIFIC WARM-UP ARCHITECTURE — HARD
The Course Framework owns the recurring Warm-Up pattern. Different courses may legitimately use different systems.

A course may use a rotating current/retrieval/representation routine, OR it may define a stable long-horizon FLUENCY TRACK that runs partly independently of the current conceptual/mastery spiral. Do not force one course's Warm-Up architecture onto another.

A separate fluency track is legitimate when daily repeated work develops durable prerequisite/procedural capacity over months. Its progression should be intentional and cumulative rather than random.

Warm-Up slots normally remain separate student jobs. A compact mini-set is allowed inside one slot when every item serves one coherent fluency job, such as several short equations in an Equation Fluency slot.

================================================================
9. EXIT TICKETS / SHORT EVIDENCE / RETEACH CHECKS
================================================================

Exit Tickets are high-value evidence pulses, not extra Practice. Build an explicit evidence map BEFORE questions.

The Course Framework owns the exact Exit Ticket architecture: parallel forms, staged tickets, rolling reassessment, mixed evidence, or another declared pattern. Do not assume all courses should use the same design.

EVIDENCE MAY BE DISTRIBUTED OVER TIME
A single short ticket does not need to sample every supporting I-can when the course intentionally distributes evidence across multiple sections, repeated goal appearances, Quick Checks, performance evidence, and Summatives. The map must make that distribution visible so important I-cans are not accidentally ignored.

ROLLING REASSESSMENT IS VALID
A course may reserve part of each later Exit Ticket for fresh parallel reassessment of prior official evidence. This can produce a stronger body of evidence than four one-time questions on one day.

TARGETED RETEACH / RECOVERY CHECK RULE
When the teacher needs a quick look at an Intro skill, Review skill, misconception, or reteaching result, a small targeted formative check may be generated on demand. It is primarily an instructional decision tool and does not automatically become an official canonical Exit Ticket, portfolio event, or Bank requirement unless the teacher deliberately promotes it.

Equivalent forms must preserve the evidence target, representation demand, reasoning load, and usable difficulty. When a response surface is required, provide it unless constructing that surface is itself part of the evidence.

================================================================
10. ASSESSMENT / GRADING / PORTFOLIO
================================================================

Assessment determines what students currently understand/can do independently and what should happen next. Practice creates learning; assessment gathers evidence. Grades communicate demonstrated proficiency, not compliance or accumulated points.

Proficiency is professional judgment from a BODY OF EVIDENCE considering quality, consistency, independence, reasoning, representation use, recency, and broader pattern over time.

Do not use simple averaging, "latest score wins," or one weak event as the sole proficiency rule. Not Yet means insufficient evidence, not permanent failure.

Evidence may come from Exit Tickets, Quick Checks, Performance Tasks, investigations/labs, quizzes, written explanations, modeling, Summatives, and other valid opportunities. The same Mastery Goal may receive multiple independent evidence points across time, representations, and contexts.

Progress labels such as Not Yet / Approaching / Meeting / Exceeding describe the quality/body of evidence, not four item-difficulty tiers. DOK is descriptive metadata, not the assessment-design engine.

================================================================
11. QUESTION STRUCTURE AUTHORITY
================================================================

The canonical universal Question Structure library is a LIVE authoring/design authority. The current build uses the current canonical version from the pinned snapshot.

Question Structure owns shared design vocabulary for how questions can be built. It does NOT control curriculum coverage, item counts, teaching sequence, or course-specific distribution.

Simple direct questions should remain simple when that is the right job. Multi-concept items require a coherent bridge. Context must affect the mathematics/science/interpretation. Representations must be real when representation reasoning is claimed. Internal authoring labels belong in metadata, not student-facing prompt text.

================================================================
12. OPTIONAL / LATER / PURPOSE-BUILT RESOURCES
================================================================

Demonstrations, Investigations, Performance Tasks, Quick Checks, labs, projects, and other purpose-built resources may be designed later from the Course Framework and current maps unless the current workflow explicitly includes them.

Teacher-live improvements should be preserved when useful and may replace an older canonical artifact after teacher review and intentional sync.

================================================================
13. VISUAL / WORKSPACE PHILOSOPHY
================================================================

Visuals are instructional content, not decoration. Workspace, scale, layout, and readability should fit how students actually use the resource.

STUDENT-FACING REPRESENTATION CAPTION RULE — UNIVERSAL / LOCKED
Do not place descriptive captions, titles, source labels, representation labels, or figure-name text beneath a student-facing graph, table, diagram, image, or other representation. The prompt introduces the representation; the representation stands alone. Preserve mathematically/scientifically necessary labels inside the representation.

================================================================
14. RENDERING INTEGRITY / HUMAN-IN-THE-LOOP
================================================================

Correct curriculum content is not enough if rendering corrupts it.

Deterministic tools should handle mechanical tasks they are good at: final-byte checks, figure generation, answer-choice scrambling, packaging integrity, syntax/path validation, and repeatable QA. They should not silently rewrite curriculum or declare pedagogically useful repetition bad.

Semantic curriculum judgment remains a teacher/AI review job. A generated artifact is a CANDIDATE until the teacher reviews/tests it and intentionally syncs it to canonical GitHub.

================================================================
15. CANONICAL TASK GRANULARITY
================================================================

A resource set may contain several questions. A single canonical question should contain one coherent job unless its parts share a real stimulus, dependency, representation connection, or compare/contrast bridge. Do not compress independent jobs with "and," "then," or "also."

A compact fluency mini-set is coherent when all subitems intentionally repeat the same narrow job.

================================================================
16. OWNERSHIP / INHERITANCE PRINCIPLE
================================================================

Treat the curriculum system as layered authority:

  UNIVERSAL PHILOSOPHY
    universal beliefs, authority boundaries, and system-level principles

  UNIVERSAL QUESTION STRUCTURE
    shared live vocabulary for question design

  CURRENT COURSE FRAMEWORK
    exact Assessment Plans/I-cans, course learning architecture, recurring routines, evidence patterns, representations, source intelligence, and intentional course differences

  EXECUTABLE PM
    procedure for resolving inputs, validating, selecting, assembling, auditing, and returning output

  TOOL / HTML-CSS SHELL / RENDERER
    deterministic mechanics and approved recurring-artifact formatting

  FINISHED ARTIFACT
    the classroom document, locally improvable within the teacher-declared job scope

When a rule changes, change the smallest correct owning layer and remove/demote contradictory lower-layer copies. Do not stack overrides indefinitely.

================================================================
17. CANONICAL GITHUB / JOB RESOLUTION
================================================================

Canonical GitHub is the authority store. Stable paths/names identify current authorities; Git history preserves previous versions.

PINNED RETRIEVAL CONTRACT — HARD
- Resolve and pin required repository commits once at job start.
- Retrieve each authority from its exact canonical path using the correct transfer mode.
- Do not replace normal retrieval with repository archaeology, remembered copies, or similarly named files.
- If the prescribed pinned retrieval route fails, fail closed and report the exact repository, commit, path, and failed requirement.

The teacher should not have to repeatedly upload canonical dependencies merely to run a normal job.

================================================================
17A. CHATGPT SKILLS / EXECUTION ROUTING — HARD
================================================================

Skills are reusable execution procedures, not curriculum authorities. When a teacher request clearly matches an available Skill, use the matching Skill first. If no Skill matches, proceed normally. Skills may govern execution mechanics but may not silently replace teacher instruction, Philosophy, Framework, or other canonical curriculum authority.

TEACHER-CONTROLLED DEPLOYMENT RULE
Skill/tool availability does not authorize direct writes to canonical curriculum repositories. Unless the teacher explicitly requests a repository write for the current job, return the smallest coherent changed file/package for teacher review and sync.

================================================================
18. BUILD, AUDIT, REPAIR, AND CONTROLLED IMPROVEMENT
================================================================

BUILD and long-term maintenance are related but distinct.

TARGETED AUDIT PRINCIPLE
Prefer small audits that expose the exact classroom content the teacher needs to judge rather than reopening the entire architecture unnecessarily.

DECLARED OUTPUT-SCOPE RULE — HARD
Each job declares what it may replace. Everything inside that scope may be repaired/redesigned when needed. Everything outside is protected.

SYSTEMIC IMPROVEMENT LOOP
A real build is regression testing of the workflow. If it exposes a repeatable problem, identify the owning layer:
- artifact defect -> artifact
- Bank/Bank Map defect -> Bank layer
- Course Framework defect -> Framework
- PM defect -> procedure
- Question Structure defect -> universal structure library
- tool/shared-shell defect -> mechanism
- Philosophy defect -> universal principle

A systemic improvement is a candidate until teacher approval. After approval, validate the exposing case and regression-check protected areas.

Lifecycle:
  BUILD -> DEPLOY/TEACH -> OBSERVE -> TARGETED AUDIT/REPAIR -> PROMOTE UPSTREAM WHEN WARRANTED

================================================================
19. FINAL OPERATING PRINCIPLES
================================================================

1. CANONICAL GITHUB IS THE SOURCE OF TRUTH.
2. PIN THE STARTING SNAPSHOT.
3. FAIL CLOSED WHEN REQUIRED AUTHORITY IS MISSING OR AMBIGUOUS.
4. THE COURSE FRAMEWORK OWNS THE EXACT APPROVED ASSESSMENT PLANS.
5. PURPOSE BEFORE INVENTORY.
6. LEARNING/EVIDENCE MAP BEFORE QUESTIONS.
7. CANONICAL GOAL IDENTITY STAYS STABLE ACROSS STAGES WHEN A COURSE USES A STAGED SPIRAL.
8. WARM-UP FLUENCY MAY BE A SEPARATE COURSE-LONG TRACK WHEN THE FRAMEWORK SAYS SO.
9. EXIT EVIDENCE MAY BE DISTRIBUTED AND REASSESSED OVER TIME.
10. BANKS ARE AUTHORITATIVE BUT NEED NOT BE EXHAUSTIVE.
11. PRACTICE CREATES LEARNING; ASSESSMENT GATHERS EVIDENCE.
12. REPRESENTATIONS ARE CONTENT WHEN STUDENTS ACTUALLY USE THEM.
13. PURPOSEFUL REPETITION IS GOOD; TEMPLATE-DRIVEN REPETITION IS NOT.
14. DOK/BLOOM DESCRIBE COMPLETED TASKS; THEY DO NOT DRIVE QUOTAS.
15. CHANGE THE SMALLEST CORRECT OWNING LAYER.
16. TEACHER REVIEW/SYNC IS THE FINAL AUTHORITY PROMOTION STEP.
