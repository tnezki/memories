CURRICULUM PHILOSOPHY PORTABLE MEMORY v3.18
================================================
STATUS: CURRENT UNIVERSAL TEACHING / LEARNING PHILOSOPHY
PURPOSE: Preserve the universal educational beliefs and authority boundaries that should shape every course without relying on prior chats, stale copies, or course-specific habits.

================================================================
READ THIS FIRST / CANONICAL AUTHORITY
================================================================

This Philosophy is the BASE layer. It owns universal beliefs about learning, instruction, evidence, teacher choice, useful abundance, representations, resource purpose, quality, authority boundaries, deterministic assembly, and controlled system improvement.

CANONICAL GITHUB RULE - HARD
The current canonical GitHub repositories are the source of truth. Local folders and generated artifacts are working/test copies until the teacher intentionally syncs approved changes. Whatever is canonical at the pinned job start is authoritative for that job.

CURRENT-JOB CONTEXT ISOLATION RULE - HARD
For a Curriculum Control Panel job, prior chats, project conversation history, saved/personal memory, assistant/model memory, prior assistant outputs, and stale uploaded copies are NOT curriculum authority. Use only the CURRENT request/current teacher instruction, request-provided files, and the exact pinned canonical project sources declared by the system.

BUILD SNAPSHOT RULE - HARD
At job start, resolve the current canonical GitHub state once and pin every required authority/resource to that starting snapshot. Do not mix authorities that changed mid-run.

FAIL-CLOSED RULE - HARD
If a required canonical authority is missing, ambiguous, or cannot be resolved, stop and identify the exact problem. Do not silently substitute an old upload, remembered rule, similarly named file, or stale embedded copy.

AUTHORITY HIERARCHY
  1. Current explicit teacher instruction for the specific job/artifact
  2. This universal Philosophy plus declared current philosophy amendments
  3. Current universal Question Structure authority
  4. Current Course Framework and its declared current maps/contracts/profiles
  5. Current executable PM
  6. Current tool / HTML-CSS shell / renderer

A lower layer may specialize a higher layer only where the higher layer permits specialization. It may not silently contradict it. A direct teacher instruction may create a local exception; that exception stays local unless deliberately promoted upstream.

COURSE AUTHORITY RULE - HARD
The current Course Framework is the canonical course authority. It contains or resolves the approved Unit Assessment Plans exactly, including exact Learning Targets/I Can statements, mastery goals, stage architecture, recurrence architecture, and evidence architecture.

PM OWNERSHIP RULE - HARD
PMs primarily own PROCEDURE: what to resolve, validate, select, assemble, audit, and output. PMs should reference current higher authorities rather than embedding competing copies of Philosophy, Frameworks, Question Structure, Banks, or maps.

CORE SENTENCE
Instruction creates opportunities to learn; assessment collects evidence; the portfolio organizes that evidence over time; and the grade communicates the best current professional judgment of what the student actually understands.

================================================================
1. BUILD FROM LEARNING ARCHITECTURE, NOT RANDOM INVENTORY
================================================================

Do not start by writing questions.

Correct sequence:
  current Course Framework + exact approved Assessment Plan
    -> exact Learning Targets / I Can map
    -> course-specific learning-stage architecture
    -> planned recurrence/retrieval architecture
    -> resource-purpose map
    -> evidence map
    -> representation plan
    -> item requirements
    -> approved Question Structure
    -> approved Bank family when applicable
    -> actual instantiated question
    -> independent verification

For any multi-item, multi-section, or multi-form build, create an explicit PRE-AUTHORING MAP before final student materials. Use it to see coverage, missing opportunities, repeated structures, representation use, evidence routes, recurrence, and the actual jobs students will do.

Predictable routine is desirable. Formulaic placement and assembly can be good. Formulaic QUESTION THINKING is bad.

Exact Learning Targets and I Can statements are the instructional spine. Readings, explanations, Notes, examples, Practice, activities, evidence, and later resources should revolve around those learning jobs rather than a generic textbook template.

================================================================
1A. OFFLINE-FIRST / DETERMINISTIC ASSEMBLY - HARD DIRECTION
================================================================

When a curriculum product can be assembled safely from already-approved maps, Bank families, templates, parameters, and deterministic tools, prefer that route over repeatedly asking an AI to reinvent routine content.

OFFLINE-FIRST does NOT mean every current artifact must already be local/offline. It is the system direction for repeatable work.

Use deterministic/local scripts for jobs they can do reliably, including:
- selecting approved records from a declared map;
- seeded number/value swaps;
- table/data generation from known rules;
- graph generation from declared parameters;
- answer/key calculation;
- answer-choice and question-order scrambling;
- reproducible parallel forms;
- path/hash/count/schema checks;
- packaging and transfer.

Use teacher/AI semantic authoring for work that genuinely requires judgment, such as:
- deciding a new evidence architecture;
- creating a new family or misconception route;
- writing rich contexts that cannot be parameterized safely;
- deciding whether a new representation or reasoning job is instructionally worthwhile;
- repairing a pedagogical defect exposed by classroom use.

BANK GENERATOR PRINCIPLE
A strong reusable family should record enough invariant/variation information for deterministic generation when the mathematics allows it. Useful fields may include parameter ranges, constraints, answer-generation rules, graph/table generation rules, misconception/distractor rules, allowed contexts, allowed inversions, forbidden variations, and reproducible test seeds.

A family may remain static or partly parameterized when full deterministic generation would reduce quality. Do not force every family into a generator merely to satisfy an automation goal.

================================================================
1B. COURSE LEARNING / EVIDENCE LANGUAGE AUTHORITY
================================================================

The current Course Framework and its exact Assessment Plans own the course's learning-stage language. Do not invent, normalize, or rename course-specific stage vocabulary into a universal lifecycle.

If a course uses Intro / Review / Mastery, preserve those terms and relationships exactly. If another course uses a different architecture, preserve that instead.

CANONICAL GOAL IDENTITY RULE - HARD
When a course intentionally carries the SAME goal through multiple stages, the goal ID/title/description stays stable. Stage changes the support, independence, representation, context, or complexity of the evidence - not the identity of the goal.

FORMAL STAGE VS RECURRENCE - HARD
A formal Intro/Review/Mastery placement is not the only time students should see a goal. A course may define a separate recurrence map that deliberately brings goals/I Cans back between formal stage appearances. Formal stage identity and recurrence frequency are different concepts.

================================================================
2. RICH MENU / USEFUL ABUNDANCE / TEACHER CHOICE
================================================================

The course is a rich menu of high-quality options, not a minimum viable packet or fixed calendar. The teacher may skip, shorten, substitute, combine, reorder, or spend longer on resources.

MORE CAN BE BETTER when additional material is genuinely useful. Unused high-quality material can provide differentiation, reassessment options, alternate representations, repetition, and flexibility. The guardrail is PURPOSE, not minimalism.

BANK IS AUTHORITATIVE, NOT EXHAUSTIVE - HARD
A canonical Bank is a reliable reusable content/evidence layer. It does not have to pre-store every finished question that may eventually appear in every classroom artifact. The Framework/Assessment Plan remains the learning authority. Downstream builders instantiate or refine fresh questions from approved families when the artifact's job calls for them.

A Bank should grow only when a new family adds a genuinely useful student thinking/evidence job. Do not create filler families to hit a quota.

================================================================
3. REPETITION / SPACING / RETRIEVAL
================================================================

Repetition is not automatically a defect. Repeated execution and retrieval can build fluency, accuracy, notation/control, discrimination, conceptual strength, confidence, and durable memory.

MAP-FIRST REPETITION DISCIPLINE
A pre-authoring map distinguishes PURPOSEFUL REPETITION from ACCIDENTAL REPETITION. Keep repetition that serves fluency, retrieval, repeated evidence, representation practice, or deliberate return to a high-value structure. Revise repetition caused only by template convenience.

SPACING OVER RAW COUNT
For long-term learning, several well-spaced section appearances may be more valuable than many questions concentrated in one section. Courses may therefore track both total questions and distinct section appearances.

Do not use anti-repetition quotas. The goal is intentionality, not maximum surface variety.

================================================================
4. EVIDENCE FIRST / HIGHEST-STAKES CONTENT
================================================================

The strongest evidence resources deserve the earliest and most careful authoring.

High-priority design areas are:
  1. Exact Learning Target / I Can / Mastery Goal mapping
  2. Explicit evidence architecture
  3. Strong short-evidence pulses such as Quick Checks when the course uses them
  4. Strong secure Summative evidence
  5. Honest distribution of evidence opportunities over time

A short assessment does not need to sample every supporting I Can when the course intentionally distributes evidence across repeated goal appearances, Quick Checks, Checkpoints, performance evidence, and Summatives. The map must make that distribution visible.

================================================================
5. REPRESENTATIONS ARE INSTRUCTIONAL CONTENT
================================================================

The Course Framework defines the representation system that matters for that discipline and Unit. Possible forms include graphs, equations, tables, contexts, diagrams, phenomena/images, data, formulas, models, number lines, experimental setups, code, or other course-specific representations.

A representation counts only when students actually read, build, use, compare, translate, annotate, or interpret it. Decorative images and metadata labels do not count as representation reasoning.

DISTINCT REPRESENTATION RULE - HARD
When a course declares a canonical representation family, multiple-representation work must use genuinely distinct mathematical/scientific forms from that family. Rewriting the same information in another notation does not create a new representation.

REQUIRED REPRESENTATION / APPROVED TOOL RULE - HARD
When the Framework requires a representation and the system provides an approved registered tool for that representation, use the registered tool directly. Do not silently omit the required representation or replace it with an easier redundant form.

================================================================
6. PRACTICE CREATES LEARNING
================================================================

Practice exists primarily to CREATE LEARNING, not to generate grades.

A good Practice resource gives students substantial productive work for the intended learning job. Useful extra material is allowed because the teacher can skip/select.

Practice may include direct repeated work, representations, conceptual/diagnostic work, partner/social structures, and deeper transfer depending on the course and target.

Practice should not be forced into one current goal when the course recurrence map intentionally mixes several high-value prior goals/I Cans.

================================================================
7. NOTES / EXAMPLES
================================================================

Notes are a guided instructional pathway, not a script that must be completed top-to-bottom. Exact Learning Targets/I Cans come first; readings, explanations, representations, examples, teacher discussion, and student work revolve around those jobs.

Instructional reading should be substantial enough to teach the idea, not a thin bridge to the next problem.

Examples/You Try It pairs are instructional anchors. When the current course uses an approved family Bank for those I Cans, Examples/YTIs should normally instantiate that family architecture rather than inventing an unrelated local question structure.

A course may still declare another multipart routine, but no WTC/FRQ-style routine is universal or implied by this Philosophy.

Notes should not contain a fake closing evidence check merely for symmetry.

================================================================
7A. ACTIVITIES / INTERACTIVE PRACTICE / CUSTOM INSTRUCTION
================================================================

Activities create learning by changing participation around worthwhile content. Movement, collaboration, stations, projected team work, peer checking, hands-on measurement, modeling, simulations, and structured discussion are means, not ends.

Activities are optional instructional routes unless the Framework explicitly says otherwise. Required core learning/evidence should not accidentally disappear when an optional activity is skipped.

When an Activity uses a finalized Bank, it should normally instantiate approved families and the course recurrence/target plan. Activities may change participation and surface, but should not casually change the evidence job.

Labs, investigations, projects, simulations, special activities, and other inherently custom resources may use the structure that best serves the lesson rather than a universal shell.

================================================================
7B. RECURRING / ASSESSMENT ARTIFACTS
================================================================

Recurring artifacts should normally use proven canonical shells for speed, consistency, and reliability. The shell owns format; the Framework owns intentional course-specific behavior; the PM owns procedure.

TEMPLATE-DRIVEN DOES NOT MEAN FROZEN
Finished classroom artifacts remain editable. The teacher may replace, rewrite, add, remove, reorder, or purpose-author content when the actual classroom artifact would be better.

USAGE MODE IS PART OF DESIGN
A projector resource should fit a viewport; a handwriting/Notability-first resource should fit writing/import geometry; a print resource should fit physical page flow; a screen study guide should fit navigation/readability.

================================================================
8. WARM-UPS
================================================================

Warm-Ups create a predictable instructional opening routine. Map their learning/retrieval job before writing them. Controlled repetition is useful.

COURSE-SPECIFIC WARM-UP ARCHITECTURE - HARD
The Course Framework owns the recurring Warm-Up pattern. Different courses may legitimately use different systems.

A Warm-Up may combine a stable long-horizon fluency track with planned cumulative I Can retrieval. Retrieval should be planned before students use the resource rather than changed opportunistically after one class has already seen a different version.

Warm-Up slots normally remain separate student jobs. A compact mini-set is allowed inside one slot when every item serves one coherent fluency job.

================================================================
9. SHORT EVIDENCE / REASSESSMENT / RETEACH CHECKS
================================================================

A course-specific Quick Check, Exit Ticket, quiz, or other short evidence pulse is evidence, not extra Practice. The current Course Framework owns the active name and mechanics.

Equivalent forms must preserve the evidence target, representation demand, reasoning load, and usable difficulty. Number/value swaps, deterministic question-order changes, and choice scrambling are appropriate when the family contract permits them.

TARGETED RETEACH / RECOVERY CHECK RULE
A small targeted formative check may be generated on demand after reteaching. It is primarily an instructional decision tool and does not automatically become a canonical Portfolio event unless the course deliberately promotes it.

================================================================
10. ASSESSMENT / GRADING / PORTFOLIO
================================================================

Assessment determines what students currently understand/can do independently and what should happen next. Practice creates learning; assessment gathers evidence. Grades communicate demonstrated proficiency, not compliance or accumulated points.

Proficiency is professional judgment from a BODY OF EVIDENCE considering quality, consistency, independence, reasoning, representation use, recency, and broader pattern over time.

Do not use simple averaging, "latest score wins," or one weak event as the sole proficiency rule.

Exact status/grade vocabulary is course-specific. Portfolio-specific status/action/report rules may live in current Philosophy amendments and current course policies; legacy examples never override them.

================================================================
11. QUESTION STRUCTURE AUTHORITY
================================================================

The canonical universal Question Structure library is a LIVE authoring/design authority. The current build uses the current canonical version from the pinned snapshot.

Question Structure owns shared design vocabulary for how questions can be built. It does NOT control curriculum coverage, item counts, teaching sequence, recurrence, or course-specific distribution.

Simple direct questions should remain simple when that is the right job. Multi-concept items require a coherent bridge. Context must affect the mathematics/science/interpretation. Representations must be real when representation reasoning is claimed. Internal authoring labels belong in metadata, not student-facing prompt text.

================================================================
12. OPTIONAL / LATER / PURPOSE-BUILT RESOURCES
================================================================

Demonstrations, Investigations, Performance Tasks, games, Tarsia/matching exports, Blooket/game exports, targeted review generators, and other purpose-built resources may be designed or generated later from the Course Framework, Bank, and current maps unless the current workflow explicitly includes them.

These optional tools do not need to inflate the initial Unit build or drive the permanent Bank family count.

================================================================
13. VISUAL / WORKSPACE PHILOSOPHY
================================================================

Visuals are instructional content, not decoration. Workspace, scale, layout, and readability should fit how students actually use the resource.

STUDENT-FACING REPRESENTATION CAPTION RULE - UNIVERSAL / LOCKED
Do not place descriptive captions, source labels, or figure-name text beneath a student-facing graph, table, diagram, image, or other representation unless that text is mathematically/scientifically necessary. The prompt introduces the representation; the representation stands alone.

================================================================
14. RENDERING INTEGRITY / HUMAN-IN-THE-LOOP
================================================================

Correct curriculum content is not enough if rendering corrupts it.

Deterministic tools should handle mechanical tasks they are good at: final-byte checks, figure generation, answer-choice scrambling, seeded variant generation, packaging integrity, syntax/path validation, and repeatable QA. They should not silently rewrite curriculum or declare pedagogically useful repetition bad.

Semantic curriculum judgment remains a teacher/AI review job. A generated artifact is a CANDIDATE until the teacher reviews/tests it and intentionally syncs it to canonical GitHub.

================================================================
15. CANONICAL TASK GRANULARITY
================================================================

A resource set may contain several questions. A single canonical question should contain one coherent job unless its parts share a real stimulus, dependency, representation connection, or compare/contrast bridge. Do not compress independent jobs with "and," "then," or "also."

A compact fluency mini-set is coherent when all subitems intentionally repeat the same narrow job.

================================================================
16. OWNERSHIP / INHERITANCE PRINCIPLE
================================================================

Treat the curriculum system as layered authority:

  UNIVERSAL PHILOSOPHY
    universal beliefs, authority boundaries, and system-level principles

  UNIVERSAL QUESTION STRUCTURE
    shared live vocabulary for question design

  CURRENT COURSE FRAMEWORK
    exact Assessment Plans/I Cans, course learning architecture, recurrence maps, recurring routines, evidence patterns, representations, and intentional course differences

  EXECUTABLE PM
    procedure for resolving inputs, validating, selecting, assembling, auditing, and returning output

  TOOL / HTML-CSS SHELL / RENDERER
    deterministic mechanics and approved recurring-artifact formatting

  FINISHED ARTIFACT
    the classroom document, locally improvable within the teacher-declared job scope

When a rule changes, change the smallest correct owning layer and remove/demote contradictory lower-layer copies. Do not stack overrides indefinitely.

================================================================
17. CANONICAL GITHUB / JOB RESOLUTION / TRANSFER
================================================================

Canonical GitHub is the authority store. Stable paths/names identify current authorities; Git history preserves previous versions.

PINNED RETRIEVAL CONTRACT - HARD
- Resolve and pin required repository commits once at job start.
- Retrieve each authority from its exact canonical path.
- Do not replace normal retrieval with repository archaeology, remembered copies, or similarly named files.
- If the prescribed pinned retrieval route fails, fail closed and report the exact repository, commit, path, and failed requirement.

GITHUB TRANSFER DELIVERY RULE - HARD
For BUILD or MAINTENANCE work that changes files in a known canonical repository destination, return ONE `github_transfer / 2` package following `Tools/LOCAL_REPO_TRANSFER_CONTRACT.txt` unless the governing PM explicitly declares a private/non-repository exception.

Do not directly commit, push, merge, or otherwise mutate canonical GitHub as part of a normal curriculum build. The transfer helper installs changes locally and leaves them uncommitted for teacher review.

The teacher should not have to manually unzip/copy ordinary repository changes into place.

================================================================
17A. CHATGPT SKILLS / EXECUTION ROUTING - HARD
================================================================

Skills are reusable execution procedures, not curriculum authorities. When a teacher request clearly matches an available Skill, use the matching Skill first. Skills may govern execution mechanics but may not silently replace teacher instruction, Philosophy, Framework, or other canonical curriculum authority.

================================================================
18. BUILD, AUDIT, REPAIR, AND CONTROLLED IMPROVEMENT
================================================================

BUILD and long-term maintenance are related but distinct.

TARGETED AUDIT PRINCIPLE
Prefer small audits that expose the exact classroom content the teacher needs to judge rather than reopening the entire architecture unnecessarily.

DECLARED OUTPUT-SCOPE RULE - HARD
Each job declares what it may replace. Everything inside that scope may be repaired/redesigned when needed. Everything outside is protected.

GOOD-ENOUGH / STOP RULE - HARD
Good enough does not mean careless or minimum effort. It means the artifact is correct, aligned, complete for its declared job, usable, traceable, and ready for the intended next step.

Once the current job's HARD contract and required QA pass and no BLOCKER/REPAIR defect remains, STOP. Improvements above the good-enough floor belong in a later targeted Improve Artifact job unless the teacher explicitly asks for them now.

SYSTEMIC IMPROVEMENT LOOP
A real build is regression testing of the workflow. If it exposes a repeatable problem, identify the owning layer:
- artifact defect -> artifact
- Bank/Bank Map defect -> Bank layer
- Course Framework/map defect -> Framework
- PM defect -> procedure
- Question Structure defect -> universal structure library
- tool/shared-shell defect -> mechanism
- Philosophy defect -> universal principle

Lifecycle:
  BUILD -> DEPLOY/TEACH -> OBSERVE -> TARGETED AUDIT/REPAIR -> PROMOTE UPSTREAM WHEN WARRANTED

================================================================
19. FINAL OPERATING PRINCIPLES
================================================================

1. CANONICAL GITHUB IS THE SOURCE OF TRUTH.
2. PIN THE STARTING SNAPSHOT.
3. FAIL CLOSED WHEN REQUIRED AUTHORITY IS MISSING OR AMBIGUOUS.
4. THE COURSE FRAMEWORK OWNS EXACT LEARNING AND COURSE-SPECIFIC STAGE/RECURRENCE ARCHITECTURE.
5. PURPOSE BEFORE INVENTORY.
6. LEARNING/EVIDENCE/RECURRENCE MAP BEFORE MASS QUESTION AUTHORING.
7. CANONICAL GOAL IDENTITY STAYS STABLE ACROSS STAGES.
8. PURPOSEFUL SPACED RETRIEVAL IS GOOD; CONCENTRATED TEMPLATE REPETITION IS NOT.
9. BANKS ARE AUTHORITATIVE FAMILY/GENERATOR SOURCES, NOT FINISHED-QUESTION WAREHOUSES.
10. PREFER DETERMINISTIC/OFFLINE ASSEMBLY WHEN APPROVED CONTRACTS MAKE IT SAFE.
11. PRACTICE CREATES LEARNING; ASSESSMENT GATHERS EVIDENCE.
12. REPRESENTATIONS ARE CONTENT WHEN STUDENTS ACTUALLY USE THEM.
13. DOK/BLOOM DESCRIBE COMPLETED TASKS; THEY DO NOT DRIVE QUOTAS.
14. CHANGE THE SMALLEST CORRECT OWNING LAYER.
15. NORMAL REPOSITORY CHANGES RETURN THROUGH THE CURRENT GITHUB TRANSFER CONTRACT.
16. TEACHER REVIEW/SYNC IS THE FINAL AUTHORITY PROMOTION STEP.
17. WHEN THE HARD CONTRACT PASSES AND NO REAL DEFECT REMAINS, GOOD ENOUGH MEANS STOP AND DELIVER.
