CURRICULUM PHILOSOPHY - SHARED CURRICULUM AND TEACHER WORKSPACES
====================================================================
STATUS: AGREED DIRECTION / AUTHORITATIVE AMENDMENT
REVISION: 2026-10-16
SCOPE: Unified CPM Tools (CC1, CC2, CC3, Algebra 1, Geometry, Algebra 2, Precalculus)

INTENT
------
One district-maintained curriculum foundation supports many independent teachers.
CC3 was a pilot, not a mandate to develop seven separate apps. Physics,
AP Calculus, STEM, and other existing course tools remain operational until
separately revisited. Reuse accepted builder patterns without replacing them.

SHARED CURRICULUM OWNERSHIP
---------------------------
- The maintainer (currently the teacher/developer; eventually district controlled)
  curates common question banks, assessment plans, unit plans, course frameworks,
  approved instructional assets, interactive reference pages, activity strategies,
  generic discourse moves, and reusable printable formats.
- Assessment Plans remain the approved assessment progression and I Can/Mastery
  Goal authority. Unit Plans are a related but distinct instructional-planning
  layer; their detailed model is still to be discussed.
- Shared materials may be HTML/CSS/JS and data, not only PDFs; keep their
  interactive features and all required companion assets.
- A resource has one declared authoritative home and a declared revision.
  The initial proposed restricted/shared Google Drive folder is a pilot;
  future district ownership/location must be replaceable without rebuilding
  lesson builders. The intended teacher setup is direct authenticated downloading
  by CPM Tools (one-time teacher authorization unless district-managed), not
  a requirement to install Drive for desktop. No existing repository or local
  workflow is migrated by this document alone.
- Public GitHub may still own specifically approved, publishable assets and
  application code. Controlled CPM textbook extractions, restricted bank content,
  and other material without publication rights must not be exposed through a
  public repository simply for developer or teacher access.
- Public instructional questions, legitimately shareable answer keys, and
  assessment explanations are not categorically prohibited. Publication must
  be intentional, rights-respecting, and compatible with assessment use.

INDIVIDUAL TEACHER WORKSPACE
----------------------------
- Teachers create and customize lessons, sets, activities, assessments, practice,
  printables, and drafts locally. Their personal Google Drive may sync and back
  up these working files, including safe troubleshooting mirrors.
- Teacher A/B folders in public GitHub and a custom multi-teacher publishing
  system are NOT required. Teachers may exchange files by email, shared Drive,
  or existing school methods.
- Normal teacher use must not require GitHub Desktop, a GitHub account, or
  direct browsing of the district/shared curriculum storage location.
- Printable individualized practice is the default. Optional online practice
  may use teacher-configured GitHub hosting and the established student-privacy
  approach. This option is not a prerequisite for CPM Tools.
- Canvas course pages/templates may be prepared later; individual teachers
  manually populate and customize their Canvas courses. Automatic Canvas
  publishing is not part of the present requirement.

PORTFOLIO AND REPORTING
-----------------------
- CPM Tools includes the classroom workflow for Portfolio, evidence, progress,
  reports, and individualized printed outputs.
- The current local Portfolio runtime retains authority over private student
  state. Restricted Google Drive may hold authorized synced/mirrored copies;
  it does not silently become a competing source of grading truth.
- Portfolio reports may be printed. Optional teacher-reviewed email delivery
  uses the established dedicated sender service and its safety checks.
- Real student records, names/grades/evidence/reports/addresses and private
  sender packages never enter a public repository or public diagnostic mirror.

MAINTENANCE AND DEVELOPMENT
---------------------------
- The memories repository retains core development contracts, versioned source
  history, and Philosophy. Its contents will be audited before consolidation.
- Safe local application mirrors may be shared via private Google Drive for
  debugging. A redundant public GitHub diagnostic mirror is not mandatory
  when an up-to-date, accessible, verified private mirror is available.
- Local runtime files, not diagnostic mirrors, remain the executable owner.
- The earlier GitHub-only mirror requirement is superseded for unified CPM
  Tools; existing mirror scripts remain in place until individually migrated.

PRECEDENCE
----------
This amendment supersedes older GitHub-only authority and mandatory-GitHub-
mirror language ONLY for the shared-curriculum and diagnostic-mirror scopes
above. Existing course/site GitHub publication contracts and current Portfolio
privacy, evidence, and grading contracts remain in force until explicitly
replaced and tested.

END
