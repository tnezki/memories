BASE COURSE BANK SYNC - PORTABLE MEMORY v1.1
================================================

PURPOSE
-------
Surgically place one finalized/upgraded Unit Bank into an existing course-site ZIP
and refresh ONLY the course artifacts that depend on that Bank.

This is NOT a general course rebuild.
This is NOT a cleanup pass.
This is NOT permission to improve unrelated files.

GENERIC RUN COMMAND
-------------------
The teacher may use exactly:

  Carefully read PM and Run.

Infer the operation from this PM and the uploaded authority set.

EXPECTED INPUT SET
------------------
1. One existing course-site ZIP, such as algebra.zip.
2. The CURRENT course Framework ZIP.
3. One finalized/upgraded Bank ZIP for exactly one unit.
4. This PM ZIP.

Do not require the teacher to name the unit if it can be resolved from the Bank
and Framework.

EMBEDDED AUTHORITIES
--------------------
This PM package contains:
- the current Base Notes PM
- the current Base Downstream Bundle PM
- ~surgical_course_sync.py

Read and obey the embedded family PMs when regenerating their artifact families.
Do not reconstruct their shells from memory.

CORE IDEA
---------
The existing course ZIP is the destination baseline.
The new Unit Bank is canonical for Bank content.
The current Framework is canonical for course/unit routing and structure.

Refresh the Bank-driven artifacts for THAT UNIT only, then use the surgical sync
tool to prove that every unrelated file remains byte-identical.

THE NON-NEGOTIABLE TOUCH CONTRACT
---------------------------------
For detected Unit N, ONLY these course-root locations may be added/replaced:

  banks/unitN/**
  notes/uN_*_notes/**
  practice_sets/practice_sets_N_*/**
  activities/uN_*_act1/**
  warmups/unit_N_warmups/**
  exit/exitN/**
  reviews/reviewN/**
  assessments_zxrtjp/unitN_summative/**

Everything else is protected.

In particular, DO NOT touch:
- any other Unit Bank
- css/**
- demo/**
- investigations/**
- performance-task folders
- quick-check folders
- progress/**
- assessment-plan folders
- misc/**
- index.html
- teacher dashboard
- root navigation files
- any artifact belonging to another unit
- Git metadata or other existing unrelated files

Do not perform opportunistic cleanup, even for .DS_Store, __MACOSX, old files,
or formatting. "Touch nothing else" is literal.

WHY WHOLE CHILD FOLDERS ARE REPLACED
------------------------------------
Do not attempt fragile search/replace inside old HTML.

For a Bank-driven child resource, regenerate the canonical current child folder
from the current Framework + new Bank + embedded family PM, verify it, then
replace that exact unit child folder atomically.

This removes stale figures and stale question instances while avoiding edits to
unrelated course files.

BANK STRUCTURE SAFETY GATE
--------------------------
If an old Bank for Unit N already exists in the course ZIP:

1. Compare old vs new unit_bank_data.json.
2. The Bank ID set must remain the same for an Upgrade-style sync.
3. For each preserved Bank ID, section and destination must remain the same.
4. Unit identity must remain the same.
5. Framework-required section architecture and route counts must still resolve.

If Bank IDs, destinations, section architecture, or route counts have changed
structurally, STOP. Do not force a surgical sync. Report that the change requires
a broader deliberate rebuild.

Content, values, answers, representations, figures, metadata, and question
quality MAY change while the identity/routing structure remains stable.

If the course does not yet contain Unit N Bank/artifacts, creation is allowed
only when the new Bank and current Framework agree exactly on unit structure.

WHAT TO REGENERATE
------------------
For the detected Unit N, regenerate the complete current Bank-driven resource
families so no dependency is missed:

NOTES
- all section student Notes
- all section teacher Notes
Use the embedded Base Notes PM.

DOWNSTREAM BANK-DRIVEN RESOURCES
Use the embedded Base Downstream Bundle PM to build canonical current outputs,
but stage only the allowed Bank-driven families:
- Practice Sets 1-3
- Extra Practice
- CYU
- Tarsia
- Blooket
- Activities and their required companions
- Warm-Ups
- Exit Tickets
- Unit Review and Review Practice
- Summative Assessment

Do NOT stage the Progress Tracker during Course Bank Sync.
It is Framework/mastery architecture rather than question-Bank content and is
therefore protected by this surgical workflow.

Do NOT build or stage:
- Demos
- Investigations
- Performance Tasks
- Quick Checks

They are outside this Bank-sync dependency path and must remain untouched.

FIGURES
-------
Use the finalized new Bank figures for regenerated Bank-driven artifacts.
Copy only figures required by the regenerated child resource.

Never reuse an old course figure merely because the filename exists.
Never modify shared CSS to solve a figure/layout issue.

CSS / SHELL PARITY GATE
-----------------------
Before staging regenerated HTML:
- verify the current Framework's required shared CSS contract is compatible
  with the course ZIP's existing shared css/ files used by the regenerated shells.
- do NOT update css/ in this workflow.

If a required stylesheet is missing or materially incompatible, STOP and report
the CSS conflict instead of modifying css/.

RENDERING RULE
--------------
Rendering is a deterministic downstream pass:
Framework routing + Bank canonical content + embedded approved HTML shells.

Do not rewrite questions.
Do not substitute "similar" questions.
Do not redesign HTML.
Do not improvise class names.
Do not change approved CSS.

SURGICAL SYNC WORKFLOW
----------------------
1. Inspect the existing course ZIP without modifying it.
2. Detect the course root.
3. Detect Unit N from the new Bank.
4. Validate the new Bank against the current Framework.
5. Compare old and new Bank structure using the Bank Structure Safety Gate.
6. Determine whether actual Bank content changed.
7. Regenerate all Bank-driven Unit N artifacts listed above.
8. Run each embedded family PM's semantic, shell, figure, MathJax, and packaging
   checks on the regenerated staging outputs.
9. Compare every regenerated allowed child folder against the existing course ZIP.
   Build an overlay tree containing ONLY the allowed Unit N child folders whose file
   sets or file bytes actually differ.
10. Determine whether banks/unitN/** itself differs. If it is byte-identical, mark
   the Bank folder as protected for this run rather than rewriting it.
11. Run ~surgical_course_sync.py with:
      --course <existing course zip>
      --bank <new unit bank zip>
      --overlay <validated overlay directory>
      --out <new course zip>
      --report <temporary report path>
12. Require the tool to PASS its untouched-file byte-hash audit.
13. Open/check representative regenerated HTML from every touched family.
14. Deliver ONE updated course ZIP using the SAME filename as the teacher's
    input course ZIP.
15. Also deliver a changes-only ZIP containing only the Unit N folders actually
    replaced, plus SYNC_REPORT.txt.
16. Summarize what unit/families were replaced and confirm protected files were
    byte-identical. Do not surface internal support files separately.

CANONICAL REFRESH BEHAVIOR
--------------------------
DO NOT use Bank equality as a reason to skip downstream regeneration.

The uploaded Unit Bank + current Framework + embedded family PMs are the current
canonical authorities for Bank-driven descendants.

For the detected Unit N:

1. Always regenerate ALL allowed Bank-driven descendants into a temporary staging
   area:
   - Notes
   - Practice Sets 1-3
   - Extra Practice
   - CYU
   - Tarsia
   - Blooket
   - Activities and required companions
   - Warm-Ups
   - Exit Tickets
   - Unit Review
   - Review Practice
   - Summative Assessment

2. Compare each regenerated child folder against the corresponding folder already
   inside the course ZIP.

3. Stage for replacement ONLY child folders whose file set or file bytes differ.

4. If the uploaded Bank is byte-identical to banks/unitN/** already in the course,
   leave the existing Bank folder byte-identical and do not rewrite it merely to
   create new archive bytes.

5. If a regenerated child folder is already byte-identical to the course version,
   leave that folder untouched.

6. If every regenerated child folder and the Bank are already identical, then and
   only then return NO CHANGE.

This rule exists because the current Bank may match the Bank stored in the course
while older downstream artifacts were originally rendered from an earlier Bank,
older PM, older Framework, or older HTML shell.

FINAL ACCEPTANCE GATES
----------------------
PASS only if all are true:

[ ] correct Unit N resolved
[ ] Framework and Bank unit architecture agree
[ ] structural Bank identity/routing gate passes
[ ] new Bank replaces only banks/unitN/**
[ ] Notes for Unit N are current with new Bank
[ ] Practice/CYU/Tarsia/Blooket for Unit N are current
[ ] Activities for Unit N are current
[ ] Warm-Ups for Unit N are current
[ ] Exit Tickets for Unit N are current
[ ] Review/Review Practice for Unit N are current
[ ] Summative for Unit N is current
[ ] generated figures resolve
[ ] MathJax/final-byte checks pass
[ ] CSS was not changed
[ ] Progress Tracker was not changed
[ ] Demos/Investigations were not changed
[ ] Performance Tasks/Quick Checks were not changed
[ ] other units were not changed
[ ] index/dashboard/navigation were not changed
[ ] every protected original file is byte-identical in output
[ ] output ZIP integrity passes

FAIL CLOSED
-----------
If the sync cannot prove that unrelated files are untouched, do not deliver the
modified course ZIP as successful.

Do not guess.
Do not silently broaden scope.
Do not "fix while here."
